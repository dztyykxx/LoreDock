## Why

T1～T6A 已经具备认证、项目/分支范围、正式知识与活动代码快照检索，以及可追溯的 `project_qa` 单 Agent 运行时，但这些能力尚未通过 Web 问答入口形成用户可用闭环。依据 `docs/product/项目业务上下文知识库_MVP需求文档_v1.0.md` 的 FR-QA-01～08、事实优先级与可信回答要求，以及开发计划 T7，现在需要交付带引用、可拒答、可重连并能沉淀知识缺口的项目问答体验。

## What Changes

- 新增已认证的 Web 项目问答 HTTP 契约：用户在已启用项目和确定分支内创建问答，服务端持久化用户可见的会话消息并启动既有 `project_qa` 运行。
- 新增运行快照与 SSE 事件入口：页面先读取持久化快照，再按事件序号增量展示阶段、可信答案、拒答、冲突、错误和来源；刷新或断线后从服务端状态恢复，不重新执行模型。
- 新增安全引用展示：知识来源展示文档标题、适用范围、公开来源和更新时间；代码来源展示仓库相对路径、分支、活动 commit 和索引时间，并区分“业务设计原因”与“当前实现事实”。
- 新增问答页并遵循 `docs/UI/README.md` 与 Pencil `04 · 项目问答 / 引用展开` 的结构和可信状态；项目与分支范围在一次问答运行中固定，模型不可用时仅影响当前问答，文档浏览和普通检索继续可用。
- 新增知识缺口反馈：`ADMIN` 与 `MEMBER` 可针对当前范围和可选问答运行提交“没有回答”“回答错误”“知识已过期”之一；管理员可按项目、分支、类型和处理状态查询，并以最小状态流转完成确认或关闭，不建设完整工单系统。
- 调整 Agent 运行敏感数据边界：运行追踪表和公开事件仍不保存完整问题，但 Web 会话消息可在独立持久化边界中保存用户主动提交的问题与最终公开回答，用于刷新恢复和反馈追溯；日志、运行摘要与 SSE 不额外复制正文。
- 明确不包含 T6B 的多 Agent、检查点恢复、项目记忆与 Skill 管理，不包含 T10 的自动知识体检，也不包含 T12 的完整管理前端扩展。

## Capabilities

### New Capabilities

- `web-project-qa`: 定义项目问答会话、消息、启动运行、快照/SSE 重连、可信状态与引用展示，以及问答页面行为。
- `knowledge-gap-feedback`: 定义成员反馈的创建、幂等防重、范围绑定、管理员查询与最小处理状态。

### Modified Capabilities

- `agent-runtime`: 明确 Web 会话可以在独立、受授权的消息存储中保存用户可见问题和最终产物，同时运行追踪、工具摘要、公开事件与日志继续遵守最小化和脱敏边界。

## Impact

- 后端新增问答与反馈能力的 application/domain/infrastructure 分层、Flyway 迁移、MyBatis-Plus 显式映射、REST/SSE Controller、鉴权和结构化日志；复用 `StartProjectQaRunUseCase`、`AgentRunQueryUseCase` 与 `AgentEventQueryUseCase`，不复制 Agent 范围和引用校验规则。
- 前端新增项目问答路由、API/SSE 客户端、会话与消息状态、可信回答/拒答/冲突展示、引用侧栏和反馈交互，并复用现有项目详情、会话与设计组件。
- 不新增模型、搜索或前端框架依赖；数据库新增独立问答会话、消息和知识缺口反馈表，既有 Agent 运行表保持兼容。
- 测试新增后端契约/领域/真实 PostgreSQL 集成测试和前端组件/重连测试，并回归认证、项目/分支隔离、普通检索和 Agent 运行契约。
