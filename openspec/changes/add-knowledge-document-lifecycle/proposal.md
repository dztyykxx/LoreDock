## Why

T1、T2 已提供持久化、后台任务、身份、项目与分支基础，但 LoreDock 还不能承载正式知识，后续 T5 检索、Web 问答、Agent 草稿审核和 MCP 都缺少统一的文档事实来源。依据 `docs/product/LoreDock_MVP功能开发计划.md` 的 T3 与需求基线 FR-DOC-01～11，现在需要先建立可审计、范围隔离且由管理员控制发布的知识文档完整生命周期。

## What Changes

- 提供 Markdown 与纯文本知识的新建、查看和编辑能力，维护标题、正文、目录、标签、来源类型、原 Wiki URL、原文件名和人工整理说明。
- 建立通用、项目、分支三级知识范围；项目级必须关联项目，分支级必须关联同一项目下的分支，通用知识不得残留项目或分支关联。
- 建立草稿、已发布、已归档状态和受控状态转换；只有管理员显式发布的当前文档版本才进入正式检索数据集，归档后退出默认检索。
- 支持新文档声明替代旧文档；发布替代文档时在同一业务操作中归档被替代文档，并保留可追溯关系，失败时不得出现新旧文档同时被部分更新的状态。
- 支持上传单个 Markdown、纯文本文件以及包含 Markdown 的 ZIP；对 ZIP 内每个条目分别报告成功、失败或忽略，单个条目失败不得掩盖其他结果。
- 对上传内容实施文件类型、大小、条目数量、路径穿越、符号链接和压缩膨胀限制；不解析网页、Word、PDF、附件或 ZIP 内非 Markdown 文件。
- 提供普通成员按通用入口或指定项目、目录浏览可见文档的只读接口；草稿和已归档文档只在管理员管理视图中可见，停用项目不通过普通入口暴露项目知识。
- 提供管理员手动请求重新索引的后台任务入口与可观察状态；本变更建立文档到正式检索数据集的同步边界，不实现 T5 的关键词、向量、混合排序或检索 API。
- 参考 Pencil `03 · 项目详情 / 知识管理` 与 `05 · 新建 / 编辑知识` 交付桌面端知识目录、文档详情/编辑、导入结果、发布/归档/替代和重新索引交互，并覆盖加载、空、失败、权限与确认状态。
- 非目标：网页抓取、Word/PDF/附件解析、文档协同编辑与版本历史、自动发布、自动归档、Agent 生成、定期整理、代码快照、知识检索排序、MCP 工具、移动端或窄屏专项适配。

## Capabilities

### New Capabilities

- `knowledge-document-lifecycle`: 知识文档内容与元数据、三级范围、目录浏览、草稿/发布/归档、替代关系、正式检索数据集同步和对应 Web 管理体验。
- `knowledge-document-import`: Markdown、纯文本和 Markdown ZIP 的安全导入、逐文件处理语义以及成功/失败/忽略结果报告。

### Modified Capabilities

无。仓库尚无已归档的知识文档主规格；本变更复用既有身份、项目、分支、对象存储和后台任务能力，但不改变它们的需求语义。

## Impact

- 后端新增按 `knowledge` 业务能力分包的领域、应用和基础设施代码，复用 T2 管理员授权、项目/分支查询端口以及 T1 对象存储、后台任务、审计和时间能力。
- HTTP API 新增普通只读 `/api/knowledge-documents/**` 与管理员 `/api/admin/knowledge-documents/**` 契约，以及导入和重新索引任务入口；新增稳定的 400、404、409、413、422 业务错误语义。
- PostgreSQL 通过追加 Flyway 迁移新增文档、标签、替代关系、导入批次/条目和文档索引投影或同步状态所需结构；持久化继续使用 MyBatis-Plus 显式映射。
- 原始上传文件保存到既有受控对象存储；Markdown/纯文本透传不引入渲染器或文档转换框架，ZIP 为可靠识别符号链接和中央目录元数据引入经版本、许可证与安全核验的最小 Apache Commons Compress 依赖。
- 前端在现有认证、项目路由、设计令牌与组件基础上增加知识目录、编辑器、导入结果和生命周期操作；已实现的项目/分支数据必须来自真实 API。
