## Purpose

为已登录用户提供严格绑定项目与分支、可在刷新或断线后恢复、明确区分可信回答与拒答并展示可核验来源的 Web 项目问答入口，形成 LoreDock 首个可内部试用闭环。

## ADDED Requirements

### Requirement: Web 问答必须在确定项目和分支内创建独立运行
系统 SHALL 允许已认证的 `ADMIN` 或 `MEMBER` 通过 `POST /api/projects/{identifier}/qa/questions` 提交 `idempotencyKey`、1～2000 个 Unicode 字符的问题和可选分支。系统 MUST 在接受前确认项目已启用、分支存在；省略分支时 MUST 解析为项目 `main`。成功时 SHALL 返回 HTTP 202，以及稳定的问答记录 ID、既有 `project_qa` 运行 ID、解析后的项目/分支、创建时间和当前运行状态。

每次提交 SHALL 创建一个独立 `project_qa` 运行并复用现有运行时的 Skill、范围、工具、资源限制、引用校验和拒答规则。T7 问答历史 MUST NOT 被自动加入后续运行的模型输入，页面也 MUST NOT 暗示模型记住了以前的对话；用户的新问题只能以本次提交正文和该运行受控检索到的证据回答。

#### Scenario: 在明确分支提问
- **WHEN** 已登录用户向已启用项目提交合法问题、存在分支和新幂等键
- **THEN** 系统返回 HTTP 202，问答记录与运行固定到该项目和分支，且模型与工具不能切换到其他范围

#### Scenario: 省略分支时使用 main
- **WHEN** 用户提交问题但未指定分支
- **THEN** 系统把该项目 `main` 固定为实际分支，并在创建响应、问答详情和来源区域持续显示 `main`

#### Scenario: 项目或分支无效
- **WHEN** 项目不存在或已停用，或指定分支不存在
- **THEN** 系统分别返回 HTTP 404 与 `PROJECT_NOT_FOUND` 或 `BRANCH_NOT_FOUND`，不创建问答记录、不启动模型且不回退到其他项目或分支

#### Scenario: 问题输入无效
- **WHEN** 问题去除首尾空白后为空、超过 2000 个 Unicode 字符或幂等键缺失/超限
- **THEN** 系统返回 HTTP 400 参数校验错误，不创建问答记录或 Agent 运行

#### Scenario: 后续提问不继承历史内容
- **WHEN** 用户在页面中已完成一个问题后继续提交包含指代但本身证据不足的新问题
- **THEN** 系统只以新问题启动独立运行，不把旧问答正文作为隐藏上下文补足事实，并按当前运行证据正常回答或拒答

### Requirement: 问答创建和可见历史必须幂等且受授权
系统 SHALL 以当前操作者与 `idempotencyKey` 唯一标识一次 Web 问答创建。相同操作者以相同键重试相同项目、分支和规范化问题时 MUST 返回原问答记录与原运行，不重复保存消息或调用模型；同键提交不同输入时 MUST 返回 HTTP 409 和 `AGENT_RUN_IDEMPOTENCY_CONFLICT`。

系统 SHALL 持久化用户主动提交的问题和经运行时校验后的最终公开回答或拒答，以支持 `GET /api/projects/{identifier}/qa/questions` 的有界游标分页及 `GET /api/projects/{identifier}/qa/questions/{questionId}` 的详情恢复。历史和详情 MUST 只允许创建该记录的当前操作者在仍有项目访问权时读取；不存在、越权、项目不匹配或项目已停用均 MUST 返回 HTTP 404 `QA_QUESTION_NOT_FOUND`，不得暴露记录是否存在。历史默认按创建时间和稳定 ID 倒序返回，且不得包含隐藏提示、完整证据正文或模型思维链。

#### Scenario: 创建响应丢失后安全重试
- **WHEN** 客户端未收到首次 HTTP 202 响应并以相同幂等键重试完全相同的请求
- **THEN** 系统返回相同问答记录 ID 和运行 ID，数据库只有一条用户问题消息且模型最多启动一次

#### Scenario: 同键输入冲突
- **WHEN** 同一操作者复用已有幂等键提交不同项目、分支或问题
- **THEN** 系统返回 HTTP 409 `AGENT_RUN_IDEMPOTENCY_CONFLICT`，原问答记录与运行保持不变

#### Scenario: 查看最近问题
- **WHEN** 用户查询自己在一个可访问项目中的问答历史
- **THEN** 系统按稳定倒序返回有界摘要、实际分支、可信状态和时间，并提供下一页游标且不混入其他操作者或其他项目记录

#### Scenario: 猜测其他问答记录标识
- **WHEN** 用户请求不属于当前操作者或 URL 项目的问答记录 ID
- **THEN** 系统返回 HTTP 404 `QA_QUESTION_NOT_FOUND`，响应不泄露真实项目、分支、运行、来源或操作者

### Requirement: 运行快照和 SSE 必须支持可靠续读
问答详情 SHALL 以持久化运行快照为事实来源，至少返回问答记录 ID、运行 ID、固定项目/分支/活动快照摘要、状态、结果类型、可信状态、拒答或错误码、最终公开正文、引用和最后事件序号。系统 SHALL 通过 `GET /api/projects/{identifier}/qa/questions/{questionId}/events` 提供 `text/event-stream`；每个业务事件 MUST 使用对应持久化 Agent 事件序号作为 SSE `id`，并提供稳定事件名、服务端时间和有限 JSON 数据。

客户端 SHALL 能以标准 `Last-Event-ID` 或等价的非负 `afterSequence` 从已消费序号之后续读。服务端 MUST 先授权并验证项目与问答记录关联，再按严格递增顺序发送已提交事件；心跳不得占用业务序号。连接中断、页面刷新或同一序号重连 MUST NOT 重新执行模型、工具或创建新运行。运行进入终态后，SSE SHALL 发送终态事件并结束连接；客户端 MUST 再读取详情，以快照校正本地拼接状态。

#### Scenario: 从创建响应开始观察运行
- **WHEN** 客户端取得 HTTP 202 后先读取详情并从其已消费序号订阅 SSE
- **THEN** 页面按序看到运行阶段、有限工具/来源摘要、经校验文本增量和终态，且最终正文与详情快照一致

#### Scenario: SSE 中断后续读
- **WHEN** 浏览器已消费到序号 8 后连接中断并携带 `Last-Event-ID: 8` 重连
- **THEN** 服务端只发送序号大于 8 的已持久化事件，不重发更早业务事件、不重新调用模型，并最终与当前快照收敛

#### Scenario: 页面刷新时运行已结束
- **WHEN** 用户刷新页面且关联运行已完成、失败或终止
- **THEN** 页面从详情恢复最终可信状态、正文或安全错误和引用，不创建新运行也不依赖刷新前内存

#### Scenario: SSE 建连后会话失效
- **WHEN** Web 会话在活动流期间失效或当前操作者不再有项目读取权
- **THEN** 服务端停止继续公开业务事件；客户端显示需要重新登录或无法访问，且不把连接失败伪装成回答完成

### Requirement: Web 必须按事实类型和可信状态展示答案与引用
系统 SHALL 把运行结果映射为三个稳定的 Web 可信状态：有效 `ANSWER` 为“有可靠依据”，`REFUSAL/SOURCE_CONFLICT` 为“来源存在冲突”，其他拒答为“当前知识库没有足够依据”。有效回答 MUST 至少展示一个本运行经服务端校验的来源；冲突状态 MUST 同时展示知识与代码来源；任何失败、终止或未完成运行 MUST NOT 被标记为可信回答。

当回答依据为业务规则或设计原因时，页面 SHALL 标注“业务设计原因”并展示知识文档标题、通用/项目/分支适用范围、公开来源和更新时间。当回答依据为当前实现时，页面 SHALL 标注“当前快照实现”并展示仓库相对路径、实际分支、活动 commit 和索引时间。混合回答 SHALL 分区展示两类事实；服务器绝对路径、对象键、内部 generation 和完整证据正文 MUST NOT 出现在 API、SSE 或页面中。

#### Scenario: 基于知识回答设计原因
- **WHEN** 运行以有效知识引用完成业务规则回答
- **THEN** 页面显示“有可靠依据”和“业务设计原因”，并可展开对应文档标题、适用范围、公开来源和更新时间

#### Scenario: 基于代码回答当前实现
- **WHEN** 运行以当前活动快照的有效代码引用完成实现回答
- **THEN** 页面显示“当前快照实现”，并展示仓库相对路径、固定分支、commit 与索引时间，不显示服务器索引路径

#### Scenario: 知识与代码冲突
- **WHEN** 运行以 `SOURCE_CONFLICT` 拒答结束
- **THEN** 页面显示“来源存在冲突”，并列出相互冲突的知识与代码来源及各自版本时间，不静默选择其中一方

#### Scenario: 运行输出部分事件后失败
- **WHEN** 运行在阶段或来源事件之后因超时、越权、引用无效或模型故障进入失败/终止
- **THEN** 页面显示安全终态与错误码，不把未完成文本或来源摘要呈现为最终可信回答

### Requirement: 证据不足和模型故障必须提供清晰且隔离的降级
拒答页面 SHALL 明确显示“当前知识库没有足够依据”、稳定拒答原因、实际项目与分支、当前快照状态及运行返回的少量当前范围候选来源，并提供记录知识缺口入口。分支没有活动快照且问题要求确认实现时 MUST 显示“当前分支代码尚未索引”，不得展示其他分支代码。

模型连接失败、限流、鉴权失败、运行队列繁忙或响应无效时，当前问答 SHALL 显示脱敏错误和重试入口；重试 MUST 使用新的幂等键创建新运行。该故障 MUST NOT 改变应用 readiness，也不得阻止用户继续访问已发布文档、知识搜索和代码搜索。

#### Scenario: 当前分支未索引实现代码
- **WHEN** 用户询问具体实现而实际分支没有活动代码快照
- **THEN** 页面显示“当前分支代码尚未索引”和“当前知识库没有足够依据”，可显示当前范围人工知识但不冒充代码事实

#### Scenario: 没有足够证据
- **WHEN** 运行以 `INSUFFICIENT_EVIDENCE` 或 `OUT_OF_SCOPE` 拒答结束
- **THEN** 页面显示稳定原因、有限相关来源和知识缺口入口，不使用模型常识补造项目事实

#### Scenario: 模型暂时不可用
- **WHEN** 当前问答以 `AGENT_MODEL_UNAVAILABLE` 失败
- **THEN** 页面显示模型暂时不可用及重新提问入口，同时文档浏览、知识搜索和代码搜索仍可正常调用

### Requirement: 项目问答页面必须遵循可信问答设计基线
前端 SHALL 参考 Pencil `04 · 项目问答 / 引用展开` 和 UI Kit 实现桌面问答页，保持最近问题侧栏、项目/分支选择与“范围已锁定”提示、对话主区、三种可信状态、提问输入区、来源数量入口、引用侧栏和知识缺口反馈入口。一次运行接受后，当前消息展示的项目与分支 MUST 锁定为服务端响应值；用户切换选择只影响下一次新问题，不得改写已存在记录的范围或来源。

页面 SHALL 使用真实 API、快照与 SSE 状态，并提供加载、空历史、输入校验、流式运行、拒答、冲突、失败、重连和无权限状态。来源详情采用渐进展开；键盘用户 MUST 能提交问题、访问可信状态、打开/关闭来源面板并发起反馈。移动端和窄屏专项布局不属于 T7 验收范围。

#### Scenario: 打开没有历史的问答页
- **WHEN** 已登录用户进入一个已启用项目的问答页且没有历史记录
- **THEN** 页面显示项目与默认分支、空历史说明和可用提问输入，不显示静态样例为真实回答

#### Scenario: 提问后切换分支选择
- **WHEN** 一个运行已固定到 `feature/import-export` 后用户把下一题选择改为 `main`
- **THEN** 当前消息及引用仍显示 `feature/import-export`，只有随后新建的问题绑定 `main`

#### Scenario: 展开来源面板
- **WHEN** 用户打开一个已完成回答或冲突拒答的来源面板
- **THEN** 页面显示本次运行的查询范围和按引用顺序排列的安全来源元数据，并可关闭后回到原焦点
