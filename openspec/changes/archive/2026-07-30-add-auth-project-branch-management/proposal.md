## Why

T1 已提供可运行工程和持久化基础，但 LoreDock 尚无身份边界，也没有承载后续知识、快照与检索范围的项目/分支主数据。依据 `docs/product/LoreDock_MVP功能开发计划.md` 的 T2、需求基线 FR-AUTH-01～03 与 FR-PROJ-01～04，现在需要先建立 Web、管理接口和后续 MCP 服务共用的认证、授权与范围基础，并交付设计稿对应的最小前端入口。

## What Changes

- 提供一个管理员账号和一个组内共享只读账号的登录、当前会话查询与退出能力；密码仅以带盐 BCrypt 哈希配置，Web 登录状态统一由 Sa-Token 管理。
- 在服务端强制区分管理员写权限与已登录用户只读权限；未登录请求、只读用户写请求均返回稳定且不泄露内部信息的错误语义。
- 建立独立于 Web 会话的共享 MCP Token 校验边界；后续 `/mcp/**` 请求在进入工具处理前必须通过 Token 校验，本变更不提前实现 MCP 工具。
- 提供项目创建、管理视图、普通用户已启用项目列表、项目启用/停用、分支添加与查询能力；项目创建时在同一事务中建立默认 `main` 分支。
- 使用 Flyway 新增项目与分支表，并通过领域约束保证项目标识全局唯一、分支名在项目内唯一、默认分支始终可解析；持久化继续使用 MyBatis-Plus 显式映射。
- 参考 Pencil 设计稿 `01 · 登录`、`02 · 项目列表`、`10 · 项目设置 / 分支管理` 实现面向电脑浏览器的 Vue 3 页面、路由保护和管理员操作状态；复用设计令牌与页面骨架，当前后端接口已提供的数据必须真实加载，尚无后端接口的后续能力信息允许按设计稿样例静态占位并在接口具备后替换。
- 为演示数据准备提供可重复执行、无敏感内容的初始化方式，使验收环境可创建网络设计工具、对照项目及两个演示分支，但不把演示数据硬编码进正式查询逻辑。
- 非目标：注册、个人资料、组织/用户管理、细粒度权限、密码找回、第三方登录、项目删除、分支删除/重命名、MCP 工具、知识数量与代码快照的后端接口、完整 T12 Web 页面，以及移动端或窄屏专项适配。

## Capabilities

### New Capabilities

- `identity-access`: 固定 Web 账号认证、管理员/只读角色授权、会话生命周期和独立 MCP Token 认证边界。
- `project-branch-management`: 项目与分支主数据、启停规则、默认 `main` 分支、管理/只读接口以及对应的登录、项目列表和项目设置前端体验。

### Modified Capabilities

无。仓库尚无已归档的身份或项目管理主规格，本变更只新增能力。

## Impact

- 后端新增按 `identity`、`project` 业务能力分包的领域、应用和基础设施代码，并让平台审计操作者从已认证 Web 身份获取；系统后台任务仍使用 `SYSTEM`。
- HTTP API 新增 `/api/auth/**`、普通只读 `/api/projects/**` 和管理员 `/api/admin/projects/**` 契约；后续 `/mcp/**` 进入独立 Token 校验链。
- 数据库新增项目、分支及必要唯一约束/索引；不修改已执行的 T1 Flyway 迁移。
- 后端新增与 Spring Boot 4 对应的 Sa-Token starter 和 BCrypt 支持，版本在实现前按官方发布信息锁定；前端新增与现有 Vue 3/Vite 兼容的官方 Vue Router 并锁定精确版本。
- 前端状态页替换为受路由管理的登录、项目列表和项目设置流程；样式以 `docs/UI/LoreDock-MVP-UI.pen` 的 Geist 字体、颜色、间距、导航和交互状态为基线。
