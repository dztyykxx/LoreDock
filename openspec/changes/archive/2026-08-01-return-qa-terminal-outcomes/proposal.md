## Why

当前 Web 问答在检索不到证据时，模型可能继续重复调用工具并最终以 `AGENT_STEP_LIMIT_EXCEEDED` 终止；页面只显示“本次问答未完成”和内部错误码，用户无法判断是当前范围确实没有资料，还是系统发生了故障。这与需求基线 FR-QA-06、第 8 节以及现行 `project-qa-agent` 规格要求的“无依据明确拒答”不一致，也没有兑现 Pencil 问答页定义的“当前知识库没有足够依据”状态。

## What Changes

- 将“已完成必要检索但没有达到阈值的证据”确定性收敛为 `COMPLETED/REFUSAL`，返回“当前知识库没有足够依据”、稳定拒答原因、固定项目/分支和快照状态，而不是继续重复检索直到资源上限终止。
- 保持步骤上限、模型调用上限、超时、模型不可用等运行保护为失败或终止事实，不把运行故障伪装成可信拒答或回答。
- 为 Web 问答失败/终止状态返回并展示稳定、脱敏、可操作的用户说明；内部错误码作为诊断信息保留，但不再作为主要回答文案。
- 失败或终止运行仍不得投影为可信 `ASSISTANT` 消息，也不得公开未经校验的部分模型文本；页面在回答区域展示终态说明和重试/浏览知识入口。
- 补充运行时、HTTP/SSE 快照和前端组件测试，覆盖无证据拒答、无快照拒答、步骤上限终止与终态刷新恢复。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-qa-agent`: 明确无命中、低相关和无活动快照场景必须在耗尽运行预算前确定性形成公开拒答，并禁止用扩大或重复检索代替拒答。
- `web-project-qa`: 为拒答、失败和终止提供可区分的人类可读终态说明，在回答主区域展示安全结果，同时保持可信状态、错误事实和未校验文本隔离。

## Impact

- 后端 Agent 编排、`project_qa` Skill/工具结果处理、运行结果校验和事件发布。
- Web 问答详情/SSE 的公开终态 DTO 与错误文案映射；保持现有路由和创建接口兼容，不新增第三方依赖。
- Vue 问答回答面板、API 类型和终态恢复逻辑。
- 相关单元测试、真实 PostgreSQL 集成测试、前端组件测试以及 OpenSpec 主规格同步。
- 不改变每次提交独立运行、项目/分支隔离、引用校验、资源硬上限或知识发布边界；不在本 change 中处理多轮会话、主键生成策略或 SSE 的 Sa-Token 异步上下文问题。
