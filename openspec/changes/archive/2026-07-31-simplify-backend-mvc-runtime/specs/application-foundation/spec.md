## ADDED Requirements

### Requirement: 数据库主外键必须使用自增 Long 标识
LoreDock 通过 Flyway 管理的关系表 SHALL 使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY` 作为主键，Java 持久化实体的对应主键和外键 MUST 使用 `Long`，MyBatis-Plus 主键策略 MUST 使用数据库自增。业务标识、Commit、索引 generation 标识或外部框架要求的 UUID MAY 作为普通唯一字段存在，但 MUST NOT 替代自增主键。所有外键、唯一约束和索引 MUST 明确指向重构后的列类型。

#### Scenario: 向空库写入业务记录
- **WHEN** 应用在全新迁移完成的 PostgreSQL 中创建项目、文档、快照、Agent 运行或其他业务记录
- **THEN** 数据库生成正数 `BIGINT` 主键，应用以 `Long` 返回和关联该记录，调用方不需要提供主键

#### Scenario: 创建带外键的关联记录
- **WHEN** 应用创建分支、索引分块、运行事件或证据等从属记录
- **THEN** 从属记录使用 `BIGINT` 外键引用存在的父记录，数据库拒绝不存在或类型不匹配的父标识

#### Scenario: 框架要求独立 UUID 标识
- **WHEN** Agent Checkpoint 等外部框架协议要求使用 thread UUID 或 checkpoint UUID
- **THEN** 表仍以自增 `BIGINT` 作为主键，并以受唯一约束的普通 UUID 字段满足框架查询和关联需要

### Requirement: 快速迭代数据库必须从单一新基线重建
在没有生产数据迁移要求的当前快速迭代阶段，系统 SHALL 以新的 Flyway 基线一次性创建精简后的表、约束和索引，MUST NOT 为保留本地 UUID 测试数据增加双写、兼容视图或逐表转换流程。迁移后的应用 MUST 能在空 PostgreSQL 数据库完成启动；旧开发数据库必须通过明确的重建说明处理，不能静默混用新旧结构。

#### Scenario: 使用新基线初始化开发环境
- **WHEN** 开发者删除旧的可丢弃开发数据库并按文档重新启动
- **THEN** Flyway 一次建立新结构，应用进入就绪状态，核心初始化和示例数据流程可以运行

#### Scenario: 旧数据库直接运行新代码
- **WHEN** 新代码连接仍包含旧 UUID 基线且未按说明重建的数据库
- **THEN** Flyway 或启动校验明确失败，不通过隐式转换或运行时建表掩盖结构不兼容

#### Scenario: 运行时组件尝试自动建表
- **WHEN** MyBatis-Plus、Agent 框架或其他依赖尝试绕过 Flyway 创建或修改表
- **THEN** 应用配置或结构测试阻止该行为，数据库结构仍以 Flyway 迁移为唯一事实来源
