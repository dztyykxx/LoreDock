## ADDED Requirements

### Requirement: 运行必须固定 Agent 定义、模型和业务范围事实
系统 SHALL 通过统一 Agent Runtime 启动任务。启动输入 MUST 包含服务端生成或校验的幂等键、已认证操作者、任务类型和该任务要求的业务范围；系统 MUST 在首次接受请求时生成稳定运行 ID，并固定本次运行使用的 Agent 定义名称、模型名称、运行限制和解析后的项目、分支、代码快照及知识索引范围。内置 Agent/Skill SHALL 从应用 classpath 和受控配置加载，系统 MUST NOT 要求数据库 Skill 版本、对象存储版本包、发布目录或独立策略版本记录才能启动运行。

#### Scenario: 启动内置项目问答运行
- **WHEN** 已认证调用方以新幂等键提交合法的 `project_qa` 任务
- **THEN** 系统使用当前 classpath Agent 定义创建运行，固定模型、限制和业务范围事实，并返回稳定运行 ID 与初始状态

#### Scenario: 相同幂等键重复提交相同请求
- **WHEN** 同一操作者使用相同幂等键重复提交完全相同的任务输入
- **THEN** 系统返回原运行及其当前状态，不重复调用模型、不重复执行工具也不创建第二份运行记录

#### Scenario: 相同幂等键提交不同请求
- **WHEN** 同一操作者使用已存在的幂等键提交不同任务、问题或业务范围
- **THEN** 系统拒绝请求并返回 `AGENT_RUN_IDEMPOTENCY_CONFLICT`，原运行保持不变

#### Scenario: 内置 Agent 定义不可用
- **WHEN** 请求的任务类型没有可加载且校验通过的 classpath Agent 定义
- **THEN** 系统不调用模型并以 `AGENT_SKILL_UNAVAILABLE` 或等价稳定错误拒绝启动

#### Scenario: 应用配置在运行期间改变
- **WHEN** 一个运行已经开始后部署配置或 classpath Agent 定义发生变化
- **THEN** 当前运行继续使用已固定的运行事实，新配置只影响后续新运行，且系统不为此创建通用版本管理记录

## MODIFIED Requirements

### Requirement: 运行记录和公开事件必须可追溯且不暴露隐藏推理
系统 SHALL 持久化运行状态、任务类型、解析范围、模型名称或配置摘要、阶段、可引用证据、实际可得的模型用量、耗时、结果类型和脱敏错误。状态 MUST 只按 `ACCEPTED → RUNNING → COMPLETED|FAILED|TERMINATED` 前进，`COMPLETED` 的结果类型 MUST 明确区分 `ANSWER` 与 `REFUSAL`，终态不得回退。公开事件 SHALL 带运行 ID、单调递增序号、事件类型和服务端时间，支持调用方从已知序号读取后续事件；持久化事件只表达接受、开始、必要进度、发现来源、完成、失败和终止等对外有意义的阶段，不要求复制每个模型分片、工具内部步骤、Hook 或 Graph 节点。

Agent 运行记录、公开事件与结构化日志 MUST NOT 保存或公开模型原始思维链、完整系统提示、完整知识/代码正文、模型密钥、内部端点、对象键、服务器绝对路径或连接信息。工具参数和错误只保存稳定标识、长度、数量、范围及脱敏摘要；模型没有返回 Token 用量时 MUST 记录为未知，不得伪造为零。被标记为可恢复的长运行 MUST 从最后已提交的框架 Checkpoint 继续，并不得重复已经提交的业务写入；未标记为可恢复的短运行在重启后 MUST 以稳定错误单调终结。

面向已认证用户的 Web 问答能力 MAY 在独立于 Agent 运行追踪的受授权消息存储中保存用户主动提交的完整问题，以及通过引用校验后允许公开的最终回答或拒答，以支持问答历史、刷新恢复和知识缺口追溯。该存储 MUST 执行项目与操作者访问控制、正文长度限制和审计约束，不得保存隐藏提示、模型思维链或完整证据正文。

#### Scenario: 完成带证据检索的运行
- **WHEN** Agent 调用允许的只读工具并形成回答或拒答
- **THEN** 运行快照、粗粒度事件和证据能够证明固定范围、实际阶段、来源标识、引用、Token 可用性、耗时和最终结果，且不包含隐藏推理、完整证据正文或逐分片事件副本

#### Scenario: 从已知序号继续读取事件
- **WHEN** 下游调用方携带某运行已消费的最后事件序号重新读取
- **THEN** 系统按序返回更大的持久化公开事件，不重复更早事件，并以当前运行快照作为终态事实来源

#### Scenario: 运行失败后收到迟到结果
- **WHEN** 运行已经进入失败或终止状态后模型或工具仍返回迟到内容
- **THEN** 系统不得改变终态或把迟到内容作为回答发布，只记录脱敏的忽略结果摘要

#### Scenario: 可恢复长运行期间后端重启
- **WHEN** 后端重启时发现一个声明为可恢复且已经写入有效 Checkpoint 的 Agent 运行
- **THEN** 系统从最后已提交 Checkpoint 继续运行，不重复已经提交的工具副作用或业务记录

#### Scenario: 不可恢复短运行期间后端重启
- **WHEN** 后端重启时发现一个未声明为可恢复的 `ACCEPTED` 或 `RUNNING` 运行
- **THEN** 系统以 `AGENT_RUN_INTERRUPTED` 或等价稳定错误将其单调终结并保留既有运行事实

#### Scenario: 敏感内容进入运行输入或错误
- **WHEN** 输入、证据、模型响应或异常包含密钥样式、内部地址、完整正文或服务器路径
- **THEN** Agent 运行记录、结构化日志和公开事件只保留允许字段或脱敏摘要，敏感原文不被写入这些追踪边界

#### Scenario: Web 问答保存用户可见消息
- **WHEN** 已认证用户通过 Web 问答提交问题并得到经引用校验的回答或拒答
- **THEN** 独立消息存储可以保存该用户可见问题与最终产物供授权恢复，但运行记录和日志仍只保存必要摘要，且任何边界都不保存隐藏提示、思维链或完整证据正文

## REMOVED Requirements

### Requirement: 运行必须固定启用的 Skill、模型和安全配置版本
**Reason**: 当前只有内置 classpath Agent/Skill，没有在线编辑、发布、启停或历史版本切换需求；数据库版本目录、对象存储内容包和多组策略版本号增加了启动依赖、表和适配层，却不提供当前可用能力。

**Migration**: 由新增的“运行必须固定 Agent 定义、模型和业务范围事实”要求替代。运行继续固定模型、限制和范围等必要事实，内置 Agent/Skill 改为从 classpath 与应用配置加载；删除数据库 Skill 版本、内容包发布和独立策略版本管理。
