## Why

当前后端已经具备知识导入与检索、代码快照、项目问答和证据引用等 MVP 能力，但代码被大量 `application/domain/infrastructure`、单实现接口、Repository Adapter 和细粒度数据表拆散，导致新增核心功能需要跨越过多层次。依据当前需求基线 `docs/product/项目业务上下文知识库_MVP需求文档_v1.0.md` 和快速迭代阶段目标，需要在不破坏已成型核心链路的前提下，将后端收敛为按功能模块组织、模块内严格 MVC 的简单结构，并让模型与 Agent 能力优先复用 Spring AI/Spring AI Alibaba。

## What Changes

- **BREAKING**：后端生产代码改为按 `auth`、`project`、`knowledge`、`code`、`agent`、`qa`、`feedback` 等功能模块组织，固定主链路为 `Controller → Service → Mapper → PostgreSQL`。`service` 只放业务服务，`mapper` 只放 MyBatis-Plus Mapper；Entity、Request、Response、Command、Result、Tool、Snapshot 和枚举必须进入对应 `model` 子包。配置、异常、调度、转换器和 Skill 可使用职责明确的并列包；移除 `application`、`domain`、`infrastructure`、`port`、`gateway`、`repository`、`adapter`、`usecase` 等结构性层次。
- 保留真实可替换边界：Agent Runtime、Agent/Skill 定义加载、聊天模型、Embedding 模型和外部存储；删除仅用于单实现转发或复制 Mapper 能力的接口。
- 聊天模型与 Embedding 推理优先使用 Spring AI 的 `ChatModel`、`EmbeddingModel` 标准接口；LoreDock 只保留模型选择、知识文本组合、索引版本契约等业务相关逻辑。
- 保留 `agent` 一级模块和 Agent Runtime，使用 Spring AI Alibaba 的 ReactAgent、Flow Agent、Hook、Interceptor、流式执行与 Checkpoint 能力，支撑现有项目问答以及后续多 Agent 知识挖掘；不再自行实现框架已经提供的 ReAct 循环、编排、调用限制、重试和检查点机制。
- 精简 Agent 业务持久化，只保存运行摘要、粗粒度公开事件和可引用证据；不把框架内部节点、思维过程或每个流式分片重复持久化。
- 删除当前没有真实切换入口和管理需求的版本管理能力，包括 Agent Skill 数据库版本、对象存储版本包、发布/启用目录以及独立的策略版本号；内置 Agent/Skill 直接从 classpath 和应用配置加载。
- 只保留保证业务正确性的版本事实：代码 Commit/活动快照、知识活动索引 generation、Flyway 迁移版本，以及运行记录中用于排障的模型名称或配置摘要；这些字段不得扩展成独立版本管理子系统。
- **BREAKING**：LoreDock 管理的数据库表统一使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY` 主键，Java/MyBatis-Plus 主外键统一使用 `Long` 和 `IdType.AUTO`；业务标识和框架 UUID 仅作为唯一字段，不再作为表主键。
- Flyway 继续作为唯一建表入口；需要使用 Spring AI Alibaba PostgreSQL Checkpoint 时，由 Flyway 建立兼容表并以 `CREATE_NONE` 接入，禁止框架自动修改数据库结构。
- 删除半成品、没有真实入口或明显阻碍开发的流程；对已成型且不妨碍后续开发的核心能力保持 HTTP 行为、范围隔离、引用和拒答语义。
- 用最小代表性测试和真实核心链路冒烟验证重构，不为旧分层结构保留无业务价值的测试。

### 非目标

- 本次不实现多 Agent 知识挖掘业务，只为其保留可演进的 Agent Runtime 和持久化边界。
- 本次不新增模型供应商，不建设模型管理后台、动态 Agent Marketplace、Skill 发布平台或通用版本管理平台。
- 本次不改变知识发布边界、项目/分支隔离、代码快照范围、引用校验和证据不足拒答规则。
- 本次不要求保留现有开发数据库中的 UUID 测试数据；数据库迁移以可重建的快速迭代环境为前提。

## Capabilities

### New Capabilities

- `backend-module-architecture`: 约束后端按功能模块组织、模块内部严格 MVC、接口只用于真实替换边界，并通过自动化结构检查防止旧分层回流。

### Modified Capabilities

- `application-foundation`: 将数据库主外键统一为自增 `Long`，保持 Flyway 唯一建表入口，并确保重构后的空库启动和持久化映射可验证。
- `agent-runtime`: 保留 Agent Runtime 和可替换接口，改为优先委托 Spring AI/Spring AI Alibaba 的标准模型、编排、流式与 Checkpoint 能力，同时精简运行、事件和证据持久化，并取消当前无用的 Agent Skill 与策略版本管理。

## Impact

- 后端全部功能模块的包路径、依赖关系、Spring Bean 装配和测试引用会发生大范围调整。
- PostgreSQL/Flyway 迁移、MyBatis-Plus Entity/Mapper、Java 主外键类型和前端 ID 类型需要同步修改。
- `agent`、`qa`、`knowledge` 模块受影响最大；项目问答外部 API 和可信回答语义保持兼容，但内部运行、事件和流式实现会替换。
- `spring-ai-alibaba-agent-framework` 和 Spring AI 模型 API 成为 Agent 与模型实现的主要依赖边界；现有 ONNX Embedding 适配器需要接入标准 `EmbeddingModel`。
- 当前进行中的 `return-qa-terminal-outcomes` 与本 change 存在 Agent/QA 实现重叠，实施前必须确认其已完成行为基线并避免继续固化待移除结构。
