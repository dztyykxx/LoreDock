## Why

LoreDock 已具备项目、分支和知识文档基础，但还不能安全导入指定 commit 的代码，也不能在严格的项目/分支范围内检索实现事实，首个可用问答闭环因此缺少代码证据。根据 MVP 需求基线 FR-CODE-01～07 和开发计划 T4，现在需要建立可恢复、可隔离且失败不影响旧查询入口的代码快照能力。

## What Changes

- 管理员可为已启用项目的指定分支上传 ZIP 代码快照并记录 commit，导入和索引作为可查询状态的后台任务执行。
- 对 ZIP 路径、条目类型、文件数量、展开大小、压缩比和单文件大小实施硬限制，排除依赖、构建产物、二进制、`.git`、`.env`、证书、私钥及明显密钥类文件。
- 为每个候选快照建立独立的 Lucene 索引 generation；只有在完整构建和验证成功后才原子切换为该分支的活动快照，新任务失败时保留旧活动快照与旧索引。
- 提供活动快照元数据与索引任务状态查询，明确展示项目、分支、commit、索引时间和相对前一活动快照的变化提示。
- 提供受项目和分支强约束的代码路径/内容搜索，以及按活动快照文件路径读取有长度上限的代码片段；无活动快照、路径不存在或上下文不匹配时返回明确且不泄漏其他范围信息的失败语义。
- 使用脱敏或模拟的 20 万行级代码夹具验证索引与查询，并覆盖分支隔离、敏感文件排除、恶意压缩包和索引切换失败等高风险场景。
- 本变更只提供后端契约和可供界面消费的状态数据；完整代码快照管理页面仍由开发计划 T12 实现。

## Capabilities

### New Capabilities

- `code-snapshot-management`: 定义代码 ZIP 的安全导入、项目/分支/commit 元数据、后台索引状态、独立 generation 验证与活动快照原子替换行为。
- `code-snapshot-search`: 定义活动快照内按路径和内容搜索、受限代码片段读取、项目/分支隔离、结果元数据和无快照失败行为。

### Modified Capabilities

无。

## Impact

- 后端新增 `code` 业务能力及管理、只读 HTTP 契约，并复用现有身份权限、项目/分支查询、对象存储和后台任务能力。
- PostgreSQL 通过新的 Flyway 迁移保存快照、索引 generation、活动指针与任务关联；原始 ZIP 保存在现有对象存储中，Lucene 索引保存在独立持久化目录。
- Maven 启用 T1 已冻结的 Apache Lucene 10.5.0 模块；ZIP 结构检查复用现有 Commons Compress，不引入 Elasticsearch、OpenSearch、代码向量化或 AST 分析依赖。
- 后续 T5、T6A、T7 和 T11 将复用本变更的活动快照查询与代码检索应用端口，不各自复制范围规则。
