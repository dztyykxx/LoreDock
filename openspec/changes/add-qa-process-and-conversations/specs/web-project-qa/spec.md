## MODIFIED Requirements

### Requirement: Web 问答必须在确定项目和分支内创建独立运行
系统 SHALL 允许已认证的 `ADMIN` 或 `MEMBER` 通过 `POST /api/projects/{identifier}/qa/questions` 提交 `idempotencyKey`、1～2000 个 Unicode 字符的问题、可选分支和可选 `conversationId`。系统 MUST 在接受前确认项目已启用、分支存在；省略分支时 MUST 解析为项目 `main`。省略 `conversationId` 时系统 SHALL 创建属于当前操作者和项目的新会话；提供时系统 MUST 验证该会话属于当前操作者和 URL 项目且当前没有活动轮次。成功时 SHALL 返回 HTTP 202，以及稳定的会话 ID、问答记录 ID、既有 `project_qa` 运行 ID、解析后的项目/分支、创建时间和当前运行状态。

每次提交 SHALL 创建一个独立 `project_qa` 运行并复用现有运行时的 Skill、范围、工具、资源限制、引用校验和拒答规则。后续轮次 MAY 携带同一操作者、同一项目和同一会话内按稳定顺序选择的已完成用户问题及经校验最终回答/拒答；服务端 MUST 同时限制轮数和 Unicode 字符总量，并从最早消息开始稳定裁剪。失败、终止、运行中轮次的模型文本、Tool 返回正文、其他会话和其他项目内容 MUST NOT 进入模型输入。历史消息只用于理解当前对话，不得作为项目事实 evidence；本轮项目事实回答仍 MUST 使用本运行 Tool 返回并经引用校验的证据。

#### Scenario: 创建首轮会话
- **WHEN** 已登录用户向已启用项目提交合法问题、新幂等键且省略 `conversationId`
- **THEN** 系统返回 HTTP 202，在一个新会话中创建独立问题和运行，并把模型与 Tool 固定到该项目和实际分支

#### Scenario: 在既有会话连续追问
- **WHEN** 当前用户为同一项目已完成会话提交包含指代的合法新问题
- **THEN** 系统创建新的问题和运行，只加入该会话内受限的已完成公开消息，并要求所有项目事实重新由本轮受控 Tool 证据支持

#### Scenario: 省略分支时使用 main
- **WHEN** 用户提交问题但未指定分支
- **THEN** 系统把该项目 `main` 固定为实际分支，并在创建响应、问答详情和来源区域持续显示 `main`

#### Scenario: 会话不属于当前范围
- **WHEN** 用户提交属于其他操作者、其他项目或不存在的 `conversationId`
- **THEN** 系统返回 HTTP 404 `QA_CONVERSATION_NOT_FOUND`，不泄露会话是否存在、不创建问题且不启动模型

#### Scenario: 同一会话已有活动轮次
- **WHEN** 用户在一个已有 `ACCEPTED` 或 `RUNNING` 轮次的会话中再次提交问题
- **THEN** 系统返回 HTTP 409 `QA_CONVERSATION_BUSY`，不创建分叉轮次或重复启动模型

#### Scenario: 项目或分支无效
- **WHEN** 项目不存在或已停用，或指定分支不存在
- **THEN** 系统分别返回 HTTP 404 与 `PROJECT_NOT_FOUND` 或 `BRANCH_NOT_FOUND`，不创建会话、问答记录或运行且不回退到其他范围

#### Scenario: 问题输入无效
- **WHEN** 问题去除首尾空白后为空、超过 2000 个 Unicode 字符或幂等键缺失/超限
- **THEN** 系统返回 HTTP 400 参数校验错误，不创建会话、问答记录或 Agent 运行

#### Scenario: 失败轮次不进入后续上下文
- **WHEN** 同一会话的上一轮产生过模型增量或 Tool 结果但最终失败
- **THEN** 后续新运行不携带该轮任何中间文本或 Tool 正文，只使用更早已完成轮次并正常检索或拒答

### Requirement: 问答创建和可见历史必须幂等且受授权
系统 SHALL 以当前操作者与 `idempotencyKey` 唯一标识一次 Web 问答创建。相同操作者以相同键重试相同项目、分支、会话和规范化问题时 MUST 返回原会话、原问答记录与原运行，不重复保存消息或调用模型；同键提交不同输入时 MUST 返回 HTTP 409 和 `AGENT_RUN_IDEMPOTENCY_CONFLICT`。

系统 SHALL 持久化会话、用户主动提交的问题和经运行时校验后的最终公开回答或拒答。`GET /api/projects/{identifier}/qa/conversations` SHALL 提供当前操作者的有界游标分页；`GET /api/projects/{identifier}/qa/conversations/{conversationId}` SHALL 返回有界轮次详情；既有 `GET /api/projects/{identifier}/qa/questions` 与 `GET /api/projects/{identifier}/qa/questions/{questionId}` SHALL 保持兼容。会话、历史和详情 MUST 只允许创建记录的当前操作者在仍有项目访问权时读取；不存在、越权、项目不匹配或项目已停用均 MUST 返回对应资源的 404，不得暴露记录是否存在。任何历史接口不得包含隐藏提示、完整证据正文或模型思维链。

#### Scenario: 创建响应丢失后安全重试
- **WHEN** 客户端未收到首次 HTTP 202 响应并以相同幂等键重试完全相同的会话、项目、分支和问题
- **THEN** 系统返回相同会话 ID、问答记录 ID 和运行 ID，数据库只有一条用户问题消息且模型最多启动一次

#### Scenario: 同键输入冲突
- **WHEN** 同一操作者复用已有幂等键提交不同会话、项目、分支或问题
- **THEN** 系统返回 HTTP 409 `AGENT_RUN_IDEMPOTENCY_CONFLICT`，原会话、问答记录与运行保持不变

#### Scenario: 查看最近会话
- **WHEN** 用户查询自己在一个可访问项目中的问答会话
- **THEN** 系统按最后问题时间和稳定 ID 倒序返回有界会话摘要、最后问题、状态和时间，并提供下一页游标且不混入其他操作者或项目

#### Scenario: 查看会话轮次
- **WHEN** 用户打开属于自己的项目会话
- **THEN** 系统按稳定正序返回有界的问题、最终回答/拒答、引用、状态和时间，不返回失败中间文本或 Tool 正文

#### Scenario: 猜测其他会话或问答记录标识
- **WHEN** 用户请求不属于当前操作者或 URL 项目的会话 ID 或问答记录 ID
- **THEN** 系统返回 HTTP 404，响应不泄露真实项目、分支、运行、来源或操作者

### Requirement: Web 必须按事实类型和可信状态展示答案与引用
系统 SHALL 把运行结果映射为三个稳定的 Web 可信状态：有效 `ANSWER` 为“有可靠依据”，`REFUSAL/SOURCE_CONFLICT` 为“来源存在冲突”，其他拒答为“当前知识库没有足够依据”。有效回答 MUST 至少展示一个本运行经服务端校验的已发布知识文档来源；冲突状态 MUST 展示彼此冲突的已发布知识来源；任何失败、终止或未完成运行 MUST NOT 被标记为可信回答。

页面 SHALL 明确回答基于已发布文档，并展示文档标题、通用/项目适用范围、公开来源和更新时间。Web 问答当前 MUST NOT 使用或展示代码快照、PR/diff、其他分支或模型常识作为项目事实来源。服务器绝对路径、对象键、内部 generation 和完整证据正文 MUST NOT 出现在 API、SSE 或页面中。

#### Scenario: 基于知识回答业务问题
- **WHEN** 运行以有效知识引用完成业务规则回答
- **THEN** 页面显示“有可靠依据”和“基于已发布文档”，并可展开对应文档标题、适用范围、公开来源和更新时间

#### Scenario: 已发布文档互相冲突
- **WHEN** 两篇当前允许范围的已发布文档对同一规则给出无法同时成立的结论
- **THEN** 页面显示“来源存在冲突”，并列出双方文档与更新时间，不静默选择其中一方

#### Scenario: 问题要求确认当前代码实现
- **WHEN** 用户要求确认当前本地或仓库代码实现
- **THEN** Agent 只依据已发布业务知识回答其明确记载的内容，无法确认实现时拒答并提示用户以本地最新代码核验，不访问代码快照或 PR 材料

#### Scenario: 运行输出部分事件后失败
- **WHEN** 运行在阶段或来源事件之后因超时、越权、引用无效或模型故障进入失败/终止
- **THEN** 页面显示安全终态与错误码，不把未完成文本或来源摘要呈现为最终可信回答

### Requirement: 拒答和运行故障必须在回答区域提供可理解终态
拒答页面 SHALL 明确显示“当前知识库没有足够依据”、稳定拒答原因、实际项目及运行返回的少量当前范围候选文档，并提供记录知识缺口入口。拒答 SHALL 是 `COMPLETED/REFUSAL` 的正常公开结果，不得以通用“本次问答未完成”替代。

模型连接失败、限流、鉴权失败、运行队列繁忙、响应无效、步骤或模型调用达到上限、运行超时或中断时，当前轮次 SHALL 在同一回答主区域显示与错误码稳定对应的脱敏 `failureMessage`、结果未被视为可信回答的说明以及可执行的下一步。重试 MUST 使用新的幂等键创建新运行。该故障 MUST NOT 改变应用 readiness，也不得阻止用户继续访问已发布文档和知识搜索。

失败或终止运行 MUST NOT 投影为可信 `ASSISTANT` 消息，MUST NOT 把 Tool 摘要、模型中间文本或未通过引用校验的部分输出显示为最终回答，也 MUST NOT 把该轮加入后续会话上下文。回答区域展示终态说明不改变运行的 `FAILED/TERMINATED` 事实，不得将故障误标为 `INSUFFICIENT_EVIDENCE`。

#### Scenario: 当前范围没有合格证据
- **WHEN** 运行以 `INSUFFICIENT_EVIDENCE` 或 `OUT_OF_SCOPE` 拒答结束
- **THEN** 页面把拒答正文作为本轮正常结果显示，并提供稳定原因、有限相关文档和知识缺口入口，不使用模型常识补造项目事实

#### Scenario: 步骤上限终止
- **WHEN** 当前轮次以 `AGENT_STEP_LIMIT_EXCEEDED` 终止
- **THEN** 页面显示尚未形成可信回答的稳定脱敏说明，提示缩小问题范围或创建新运行，并把错误码降为次要诊断信息

#### Scenario: 模型暂时不可用
- **WHEN** 当前轮次以 `AGENT_MODEL_UNAVAILABLE` 失败
- **THEN** 页面显示模型暂时不可用及重新提问入口，同时已发布文档浏览和知识搜索仍可正常调用

#### Scenario: 失败前存在中间模型文本
- **WHEN** 运行产生过中间文本或 Tool 结果但随后失败或终止
- **THEN** 页面只把已提交安全过程事件用于诊断展示，不把中间文本保存为可信最终回答或加入下一轮上下文

### Requirement: 项目问答页面必须遵循可信问答设计基线
前端 SHALL 参考 Pencil `04 · 项目问答 / 引用展开` 和 UI Kit 实现桌面问答页，保持最近会话侧栏、当前项目与“范围已锁定”提示、多轮对话主区、三种可信状态、可折叠处理过程、提问输入区、来源入口、引用侧栏和知识缺口反馈入口。所有 Web 请求 SHALL 省略分支选择并由服务端解析为默认 `main`；当前消息的项目范围 MUST 锁定为服务端响应值，不得因切换会话改写既有记录的范围或来源。

页面 SHALL 使用真实 API、快照与 SSE 状态，并提供加载、空会话、输入校验、流式运行、拒答、冲突、失败、重连和无权限状态。来源与处理过程采用渐进展开；键盘用户 MUST 能提交问题、切换会话、展开/折叠过程、访问可信状态、打开/关闭来源面板并发起反馈。移动端和窄屏专项布局不属于本次验收范围。

#### Scenario: 打开没有历史的问答页
- **WHEN** 已登录用户进入一个已启用项目的问答页且没有历史会话
- **THEN** 页面显示当前项目、范围锁定说明、空历史和可用提问输入，不显示静态样例为真实回答

#### Scenario: 在历史会话和新会话之间切换
- **WHEN** 用户打开一个历史会话后点击“新建问答”
- **THEN** 主区显示新的空会话输入，历史会话中的消息、来源和处理过程保持原范围且可再次打开

#### Scenario: 展开处理过程和来源
- **WHEN** 用户打开一个已完成轮次的处理过程和来源面板
- **THEN** 页面显示本次运行的真实安全事件和按引用顺序排列的文档来源，可关闭后回到原焦点

## ADDED Requirements

### Requirement: 问答处理过程必须以安全真实事件流式展示
系统 SHALL 为每个问题提供可折叠的公开处理过程，并 SHALL 只根据持久化 Agent 事实事件展示 Agent/模型阶段、Tool 开始与结束、查询摘要、RAG 命中文档安全元数据、引用校验、可选公开决策摘要、文本增量和终态。每个事件 MUST 复用该运行的单调序号并通过既有问题 SSE 增量发送；问题详情 MUST 返回足以在刷新后恢复的有界安全事件投影和最后序号，终态仍以详情快照为事实来源。

Tool 事件 MUST 只包含注册名称、用户可理解用途、脱敏参数摘要、数量、耗时、状态和结果摘要；RAG 来源 MAY 包含文档 ID、标题、通用/项目范围、更新时间、相关性摘要与截断状态。API、SSE 和页面 MUST NOT 保存或展示完整系统提示、隐藏消息、原始 Tool JSON、完整证据正文、模型原始思维链、内部端点、对象键或服务器路径。模型生成的计划或理由只能作为明确标记的 `PUBLIC_DECISION_SUMMARY`，MUST NOT 被页面当作 Tool 已执行或校验已通过的事实。

#### Scenario: 流式展示一次知识检索
- **WHEN** 当前运行调用知识搜索并返回三篇允许范围内的文档后形成回答
- **THEN** 处理过程按序展示 Tool 开始、脱敏查询摘要、三篇文档标题/范围/更新时间、引用校验和最终回答，且详情快照与 SSE 收敛

#### Scenario: 文档标题过长
- **WHEN** RAG 命中文档标题超过页面可用宽度
- **THEN** 页面单行截断显示并提供键盘或悬停可访问的完整标题，不修改服务端真实标题

#### Scenario: 模型描述未执行计划
- **WHEN** 模型公开摘要声称准备再次检索，但随后没有产生对应 Tool 事实事件
- **THEN** 页面只把它标记为模型生成的决策摘要，不创建已完成 Tool 卡片或声称检索发生

#### Scenario: Tool 返回包含敏感正文
- **WHEN** Tool 参数、结果或异常包含完整文档、隐藏提示、内部地址或服务器路径
- **THEN** 持久化事件、SSE、详情和页面只保留允许的脱敏摘要，敏感原文不进入公开处理过程

#### Scenario: 运行中断后重新提问
- **WHEN** 后端重启使活动轮次以 `AGENT_RUN_INTERRUPTED` 失败
- **THEN** 页面展示已提交安全事件和明确失败终态，不恢复原模型/Tool 过程；用户可在同一会话创建新轮次
