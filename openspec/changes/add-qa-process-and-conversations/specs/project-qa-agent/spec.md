## MODIFIED Requirements

### Requirement: project_qa 必须只使用受控证据工具回答项目事实
`project_qa` SHALL 只能通过当前 Skill 授权的知识混合搜索和文档读取工具获取项目事实，并 SHALL 复用这些能力既有的发布状态、通用/项目知识范围、有限返回和错误契约。系统 SHALL 为每条本轮 Tool 结果分配仅在当前运行有效的稳定证据 ID，并保留知识文档 ID、标题、范围、来源和更新时间等元数据；Tool 正文 MUST 在进入模型上下文前受长度和总量限制。

当 Web 会话提供历史时，模型请求 MAY 同时包含同一操作者、同一项目、同一会话中受服务端裁剪的已完成用户问题及经校验最终回答/拒答，以理解省略和指代。历史消息 MUST 标记为非证据上下文，不得生成本轮 evidenceId，不得替代当前 Tool 检索，也不得支持新的项目事实结论。模型常识、其他会话、其他运行、失败轮次、未通过 Tool 取得的内容和历史回答本身 MUST NOT 作为 LoreDock 项目事实证据。

#### Scenario: 基于人工知识回答业务问题
- **WHEN** 当前问题询问业务规则，且允许范围内的已发布知识达到证据阈值
- **THEN** Agent 使用本轮 Tool 取得的知识证据形成结果，并保留文档 ID、范围、标题、公开来源和更新时间

#### Scenario: 使用历史理解指代后重新取证
- **WHEN** 用户在同一会话追问“它还有哪些限制”，受限历史能够确定“它”指上一轮讨论的模块
- **THEN** Agent 使用历史理解查询对象，再调用本轮知识 Tool 取得限制证据；最终回答只引用本轮 evidenceId

#### Scenario: 历史回答存在但当前检索无证据
- **WHEN** 上一轮最终回答提到某项目事实，但本轮允许范围内的 Tool 没有返回达到阈值的证据
- **THEN** Agent 不把历史回答当作证据复制该事实，并以当前证据规则拒答或明确无法核实

#### Scenario: 其他会话存在更相关内容
- **WHEN** 当前操作者的其他会话或其他项目包含能解释当前问题的消息
- **THEN** 模型输入、候选生成、证据台账和最终结果均不包含这些越界消息

#### Scenario: Tool 没有命中
- **WHEN** 当前允许范围内的知识 Tool 没有返回达到阈值的证据
- **THEN** Agent 不扩大到其他范围、不使用模型常识或会话历史补写项目事实，并进入拒答结果

### Requirement: 回答必须携带可由服务端校验的引用
`project_qa` 的结构化结果 SHALL 包含结果类型、回答正文或拒答说明、引用的当前运行证据 ID 和使用的来源摘要。`ANSWER` MUST 至少引用一个由本次运行知识 Tool 实际返回且仍属于固定项目范围的已发布文档证据；每个引用 MUST 能解析为知识文档来源。服务端 MUST 在完成运行前验证引用存在、文档仍可见、来源元数据完整、未被模型篡改且未跨范围；验证失败时不得发布回答文本。会话历史消息和以前运行的 evidenceId MUST NOT 通过该校验。

#### Scenario: 生成知识引用回答
- **WHEN** 模型输出引用本次运行返回的有效知识证据 ID
- **THEN** 系统完成 `ANSWER`，引用可解析到文档 ID、范围、标题、公开来源和更新时间

#### Scenario: 模型引用历史回答
- **WHEN** 模型试图把上一轮回答正文或上一运行 evidenceId 作为本轮项目事实引用
- **THEN** 服务端拒绝该引用，要求使用本轮 Tool 证据；无法形成有效引用时转换为 `REFUSAL`

#### Scenario: 模型伪造或遗漏引用
- **WHEN** 模型给出项目事实回答但没有引用，或引用了 Tool 未返回、已裁剪移除、另一运行或另一范围的证据 ID
- **THEN** 服务端拒绝该回答并转换为 `REFUSAL`，记录 `AGENT_CITATION_INVALID` 摘要而不暴露越权来源

### Requirement: 证据不足、超出范围和无法解释的文档冲突必须拒答
系统 SHALL 使用服务端固定的最低证据阈值和可信回答规则验证 `project_qa` 结果。没有相关证据、只有低相关证据、问题超出当前项目与通用知识范围、问题要求确认当前代码实现但已发布文档无法证明、或已发布文档之间存在无法解释的冲突时，结果 MUST 为 `REFUSAL`。拒答 SHALL 明确说明“当前知识库没有足够依据”，包含稳定原因码和少量仍在当前范围内的候选文档；不得使用模型常识、会话历史、代码快照或 PR/diff 补齐结论。

当当前问题已经完成必要知识检索且没有达到阈值的证据时，系统 MUST 在运行资源上限内确定性完成 `REFUSAL`，不得继续执行等价检索并最终以步骤上限、模型调用上限或超时替代拒答。模型连接失败、Tool 故障、权限变化、文档版本变化或真实资源耗尽仍 SHALL 保留对应失败或终止事实。

#### Scenario: 要求确认当前实现但文档无法证明
- **WHEN** 用户询问当前本地代码的具体实现，而已发布文档只描述业务设计或没有相关内容
- **THEN** Agent 完成 `REFUSAL`，提示以本地最新代码核验，可附带相关文档但不得把它冒充当前实现事实

#### Scenario: 只有低相关来源
- **WHEN** 知识 Tool 只返回低于固定证据阈值的候选且必要检索已经完成
- **THEN** Agent 返回 `REFUSAL` 与 `INSUFFICIENT_EVIDENCE`，最多展示配置上限内的当前范围候选，不生成项目事实结论

#### Scenario: 问题超出项目范围
- **WHEN** 用户询问当前项目和通用业务知识以外的事实
- **THEN** Agent 返回 `REFUSAL` 与 `OUT_OF_SCOPE`，不访问其他项目、其他会话或外部网络

#### Scenario: 已发布文档相互冲突
- **WHEN** 当前允许范围的两篇已发布文档对同一事实给出无法同时成立的结论
- **THEN** Agent 返回带 `SOURCE_CONFLICT` 原因的 `REFUSAL`，引用双方文档、范围与更新时间，不静默选择其中一方

#### Scenario: 检索基础设施发生故障
- **WHEN** 必要 Tool 因权限变化、证据版本变化或检索基础设施异常而未能完成
- **THEN** 系统保留对应失败或终止错误，不把“检索失败”错误宣称为“当前范围没有证据”
