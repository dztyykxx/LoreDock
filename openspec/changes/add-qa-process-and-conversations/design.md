## Context

现有 QA 以问题记录绑定单个 Agent run，问题历史按孤立条目分页，SSE 复用持久化 Agent 事件序号。运行时已经保存粗粒度阶段、来源和终态，但缺少足以支撑 Tool/RAG 折叠面板的稳定公开事件模型。当前规格还明确禁止把任何历史加入后续模型输入。

## Goals / Non-Goals

**Goals:**

- 在不破坏既有问题接口和独立运行语义的前提下增加项目内多轮会话。
- 只使用同会话已完成的公开消息构造有界上下文，并继续以本轮 Tool 证据校验项目事实。
- 用服务端真实事件支撑可折叠、可恢复、可脱敏的处理过程。
- 为后续多 Agent 复用事件信封和前端时间线模型，但本次只实现 `project_qa` 单 Agent。

**Non-Goals:**

- 不恢复运行中的模型、Tool 或流式文本检查点。
- 不保存、推导或展示模型原始思维链、隐藏消息和完整证据正文。
- 不做自动摘要、长期记忆、会话分享、跨项目上下文或多 Agent 调度。

## Decisions

### 1. 保留“一轮一运行”，在问题之上增加会话聚合

既有 `POST /api/projects/{identifier}/qa/questions` 增加可选 `conversationId`。省略时服务端在同一事务中创建会话和首个问题；提供时先验证会话属于当前操作者和 URL 项目，再追加问题。响应增加稳定 `conversationId`，但继续返回问题 ID 和 run ID。既有客户端省略字段即可保持行为兼容。

增加 `GET /api/projects/{identifier}/qa/conversations` 游标分页和 `GET /api/projects/{identifier}/qa/conversations/{conversationId}` 详情。会话详情返回有界轮次摘要；单题详情和 SSE 仍使用 questionId，避免把多个并发运行混在同一事件流。

### 2. 多轮上下文只选已完成公开消息，事实引用仍来自本轮

创建新轮次时，服务端在同一操作者、项目、会话范围内，按稳定顺序读取最近已完成轮次的用户问题与最终 `ANSWER/REFUSAL` 正文。失败、终止、运行中轮次的模型文本和 Tool 返回正文均不进入上下文。服务端同时限制轮数和 Unicode 字符总量，超限时从最早轮次开始裁剪并记录裁剪摘要。

历史回答只作为对话语义，不能生成本轮可引用 evidenceId。任何项目事实 `ANSWER` 仍必须引用本轮 Tool 返回且通过服务端校验的证据；如果指代无法在受限历史中解析，Agent 正常补充检索或拒答。

Agent 先判断本轮是否需要项目知识。闲聊、能力说明和对当前会话历史的提问可不调用 RAG，并以 `answerBasis=null`、零引用回答；涉及项目业务事实、规则或文档内容时由 Agent 自主调用 `knowledge_search`，服务端继续要求本轮知识证据。若本轮已经产生检索证据，模型不得再以普通对话回答绕过引用门禁。

### 3. 公开事件使用类型化信封和安全载荷

沿用运行级单调序号，增加稳定事件类别：`AGENT_STAGE`、`MODEL_STAGE`、`TOOL_STARTED`、`TOOL_COMPLETED`、`SOURCE_DISCOVERED`、`CITATION_VALIDATION`、`PUBLIC_DECISION_SUMMARY`、`ANSWER_DELTA` 和终态事件。每个事件只允许预定义字段，Tool 参数由服务端投影为查询摘要、范围、数量和长度；检索结果只含文档标识、标题、范围、更新时间、相关性摘要和截断状态。

`PUBLIC_DECISION_SUMMARY` 是可选的用户可见解释，必须明确标记为模型生成摘要；它不能证明 Tool 已执行，也不能改变运行状态。前端阶段、Tool 状态和来源只能由对应服务端事实事件驱动。

### 4. REST 快照是事实，SSE 只负责增量体验

问题详情返回最后事件序号和已持久化安全过程事件的有界投影，前端加载详情后从最后已消费序号订阅 SSE。断线、刷新或终态时重新读取详情进行校正。页面按事件类型渲染折叠卡片，不根据模型文本猜测阶段。

运行时从模型结构化 JSON 的首字段 `text` 提取已完整生成的正文片段，并以 `ANSWER_DELTA/UNVERIFIED` 有界持久化和推送；页面在正文下提示仍待最终校验。模型完成后服务端再执行引用与输出策略校验，终态详情可以保留回答，也可以用拒答覆盖先前的未校验文本。这样校验仍是发布门禁，但不再阻塞正文的流式展示。

### 5. 中断采用失败后新运行，不引入 checkpoint

后端启动时将遗留 `ACCEPTED/RUNNING` 短运行单调终结为 `AGENT_RUN_INTERRUPTED`。对应轮次保留问题和失败状态，但不作为后续上下文；用户可以在同一会话重新提问并获得新 run。已完成轮次和会话元数据保持可读。

## Data and Transaction Boundaries

- 会话至少保存 ID、项目、操作者、标题摘要、创建/更新时间和最后问题时间。
- 问题增加非空会话外键；新会话与首题在一个事务内提交，Agent 启动继续使用既有可靠启动/幂等边界。
- 既有问题迁移为一题一会话，或通过兼容读取层惰性映射；实现前需在迁移设计中选择一种并验证回滚路径。
- 相同操作者和幂等键的重试必须返回原 conversation/question/run；同键改变 conversationId 或问题仍返回冲突。

## Risks / Trade-offs

- [历史回答包含旧事实] → 历史只用于理解对话，本轮事实必须重新检索并引用；上下文中明确标记消息时间和非证据属性。
- [会话过长导致上下文膨胀] → 同时限制轮数与字符数，稳定裁剪并在运行摘要中记录。
- [事件过细泄露输入或扩大存储] → 使用白名单字段和长度限制，不保存原始 Tool JSON、完整证据、提示词或隐藏消息。
- [旧问题没有会话] → 数据迁移或兼容映射保证旧记录仍可从原 URL 读取，不改变其授权语义。
- [同一会话并发提交造成顺序不确定] → MVP 对同一会话已有活动轮次时返回 HTTP 409 `QA_CONVERSATION_BUSY`，避免上下文分叉。

## Test Strategy

- 后端契约与 PostgreSQL 集成测试：新/既有会话创建、幂等冲突、活动轮次互斥、授权隔离、历史裁剪和旧数据兼容。
- Agent 用确定性 Fake Model 验证：历史能解析指代，但无本轮 evidenceId 时仍拒答；失败轮次和其他会话不进入输入。
- 事件测试：Tool/RAG/引用事件的顺序、脱敏、长度、重连和终态快照一致。
- 前端测试：会话切换、连续追问、折叠过程、长标题、SSE 增量、刷新校正、失败重试和键盘可访问性。

关键范围校验、历史非证据规则、事件脱敏和活动会话互斥需要中文 Javadoc/业务注释说明其安全原因与回归风险。
