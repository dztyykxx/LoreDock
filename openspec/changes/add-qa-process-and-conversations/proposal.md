## Why

当前 Web 项目问答已经能够创建独立运行、流式返回最终正文并保存孤立问题历史，但用户看不到 Agent 实际调用了哪些 Tool、RAG 命中了哪些文档以及引用是否通过校验，也无法在同一语境中连续追问。后续知识挖掘与冲突整理将复用同一运行事件能力，因此需要先把单 Agent 的公开执行轨迹和最小多轮会话做成稳定的平台契约。

本变更依据产品需求 v1.3 的 `FR-QA-09～12`、`FR-AGENT-12`、`FR-AGENT-16` 以及开发计划 T7A。它延续“公开执行事实而非原始思维链”的安全边界。

## What Changes

- 在既有问题创建契约中增加可选会话标识；未提供时创建新会话，提供时向当前操作者、当前项目的既有会话追加独立运行。
- 后续轮次只注入同一会话中数量和字符数受限的已完成用户问题及经校验最终回答/拒答；历史文本只帮助理解指代，项目事实仍必须来自本轮授权 Tool 证据。
- 增加会话列表和会话详情读取契约，保留既有问题历史与问题详情接口兼容。
- 扩展持久化公开事件，区分 Agent/模型阶段、Tool 开始与结束、检索命中文档摘要、引用校验、公开决策摘要、文本增量和终态。
- 问答页按会话展示多轮消息，并用可折叠区域流式展示安全过程；最终状态始终由服务端详情快照校正。
- 活动轮次在后端重启后明确失败，不恢复模型或 Tool 检查点；已完成轮次可继续用于同会话的新问题。
- 非目标：不展示原始思维链、完整提示词或完整证据正文；不做自动会话摘要、长期记忆、跨用户/项目会话、生成中断续跑或多 Agent 编排。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `web-project-qa`：增加会话化创建/历史、受限多轮上下文和可折叠流式处理过程。
- `project-qa-agent`：允许使用同一会话已完成公开消息理解当前问题，但不把历史回答当作项目事实证据。
- `agent-runtime`：把真实 Agent/模型/Tool/校验事件标准化为安全公开执行轨迹。

## Impact

- 后端：QA 会话数据模型与接口、上下文构造、Agent 事件类型与脱敏投影、SSE/详情映射。
- 前端：最近会话、连续消息、可折叠处理过程、Tool/RAG/校验卡片和流式状态收敛。
- 数据：新增会话实体或等价关联字段；既有孤立问题需要兼容映射为单轮会话。
- 安全：不扩大项目、知识或 Tool 权限；历史正文进入模型前必须重新执行操作者、项目、会话和长度边界校验。
