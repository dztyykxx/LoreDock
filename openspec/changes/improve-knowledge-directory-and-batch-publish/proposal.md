## Why

知识管理页目前把目录当作精确路径查询，父目录下只有子目录文档时会错误显示为空，并由空结果重建目录树，造成计数、列表和详情相互矛盾。批量导入又会产生大量草稿，逐篇发布阻塞“导入—审核—发布—索引—问答”主流程；同时项目页顶部工作空间面包屑和侧栏问答入口仍是不可用的静态展示。

本变更依据 `FR-DOC-06`、`FR-DOC-10`、`knowledge-document-lifecycle` 与 `web-project-qa` 现有规格，收口知识维护和页面导航的可用性，不引入自动发布或新的全局问答后端范围。

## What Changes

- 将知识目录浏览调整为父目录包含自身及全部后代目录文档，目录树和递归计数独立于当前分页结果。
- 为管理员提供服务端分页的当前上下文浏览响应，删除前端每个范围最多读取 100 篇再合并的限制。
- 在知识列表中支持勾选本页草稿、二次确认并原子批量发布；已发布文档保持幂等，归档或不存在文档使整批失败。
- 批量发布不建立替代关系、不自动发起重新索引；成功后刷新真实目录、列表和详情状态。
- 将项目顶部“工作空间”改为返回项目列表的真实链接；侧栏“新建问答”和“问答”在项目上下文中进入该项目问答，并继续使用服务端已经允许的通用与项目已发布知识范围。
- 非目标：不增加跨分页全选、自动发布、自动重建索引、批量替代关系或独立的 `GLOBAL` 问答后端与数据模型。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `knowledge-document-lifecycle`: 明确目录子树浏览、稳定目录计数、管理员本页选择与原子批量发布行为。
- `web-project-qa`: 增加项目页面侧栏真实问答入口和工作空间返回导航，不改变问答后端项目范围契约。

## Impact

- 后端：知识模块管理浏览和批量发布 HTTP 契约、查询与生命周期事务；不新增表和跨模块依赖。
- 前端：知识工作区、目录树、文档列表、顶部导航、公共侧栏、路由测试和状态刷新。
- 规格与需求：补充 `FR-DOC` 批量发布验收以及现有 Web 项目问答导航行为。
- 依赖：不新增第三方依赖或基础设施。
