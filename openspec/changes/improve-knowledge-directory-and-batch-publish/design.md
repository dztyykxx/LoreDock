## Context

参见 `proposal.md`。现有普通浏览接口返回目录和分页摘要，但目录筛选为精确匹配；管理员页面则分别查询全局、项目和默认分支各最多 100 篇摘要，在浏览器合并、分页和构造目录树。单篇发布已具备行锁、状态机、乐观条件更新和幂等语义，公共侧栏已经拿到可选的当前项目标识。

## Goals / Non-Goals

**Goals:**

- 用服务端范围过滤、递归目录统计和分页形成唯一浏览事实。
- 在知识模块内复用现有生命周期规则完成原子批量发布。
- 让现有项目问答和项目列表路由成为真实、可访问的导航目标。

**Non-Goals:**

- 不新增目录表、缓存、跨分页选中状态、批量替代关系或自动索引任务。
- 不把项目问答改造成无项目的全局问答，也不修改 Agent、QA 或数据库范围模型。

## Decisions

### 1. 新增管理员上下文浏览端点，不重解释旧管理筛选字段

新增 `GET /api/admin/knowledge-documents/browse`，接受与普通浏览一致的 `context`、`project`、可选 `directory`、`page` 和 `size`，返回完整目录节点及当前目录子树分页。旧 `GET /api/admin/knowledge-documents` 的精确范围筛选继续保留，避免改变编辑页替代候选等调用方。

普通浏览增加显式 `includeDescendants=true` 参数，前端知识工作区使用该模式；缺省调用保留既有精确目录兼容语义。递归条件同时匹配目录本身和 `directory + '/'` 后代，目录节点计数始终使用完整当前范围路径集合生成。

替代方案是前端拉取全部摘要后递归过滤；该方案会延续 100 篇上限、重复范围规则和错误分页，因此不采用。

### 2. 批量发布以文档 ID 列表作为最小契约并整批事务

新增 `POST /api/admin/knowledge-documents/batch-publish`，请求只包含 1 至 100 个唯一文档 ID，响应包含请求数、新发布数和已发布数。生命周期服务一次稳定锁定全部 ID，先验证数量与状态，再使用同一个可信审计元数据转换并条件更新全部文档。

不存在文档映射 404，归档状态映射 409；异常触发事务整体回滚。已经发布的文档不再写入，保证网络不确定后的安全重试。替代发布继续走单篇端点，因为每个候选需要独立旧文档和冲突检查。

### 3. 列表选择限定当前页并与浏览上下文绑定

文档列表把整行按钮拆为列表项、草稿复选框和独立详情按钮，避免交互控件嵌套。选择目录、翻页或批量发布完成均清空选择；仅管理员和 `DRAFT` 行展示可用复选框。确认对话框明确发布数量和重新索引后果。

### 4. 公共侧栏只复用已存在的项目问答

`AppSidebar` 根据 `currentProject` 生成 `/projects/{identifier}/qa`；“新建问答”附带 `new=1` 查询参数，由项目问答页忽略历史自动选中并聚焦输入。没有当前项目时两个入口导航至 `/projects`，由用户显式选择范围。顶部 `AppTopBar` 使用 `/projects` 的 `RouterLink` 表达“工作空间”。

## Risks / Trade-offs

- [目录路径包含 SQL 通配符时前缀条件可能误匹配] → 使用转义后的 `LIKE ... ESCAPE` 或等价安全条件，并增加包含 `%`、`_` 的测试。
- [批量请求在确认后发生并发归档] → 行锁后统一验证，任一状态冲突使事务整体回滚。
- [项目页刷新仍带旧文档 ID] → 切换目录时导航到不含详情 ID 的知识页，再加载目录子树。
- [非项目侧栏问答不能直接回答] → 明确引导到项目列表，不伪造全局后端；独立全局问答留待后续产品决策。

## Migration Plan

无数据库迁移。前后端同版本部署；旧管理列表和缺省普通浏览调用保持兼容。若回滚，移除新端点和前端调用即可，已发布文档仍是合法生命周期状态。
