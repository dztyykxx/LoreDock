## Purpose

知识整理多轮会话的模型输入必须由上下文管理能力按节点最小组装与预算控制：子 Agent 不继承历史消息，模型输入超预算时先确定性裁剪、再受限压缩兜底，压缩后仍超限的 run 进入可恢复等待而非失败终态。

## ADDED Requirements

### Requirement: 知识整理模型输入必须在节点入口按最小语义上下文组装

每个知识整理 Agent 节点入口 SHALL 按“当前 Agent × 当前任务意图”组装最小语义消息（系统规则、当前任务、已确认人工决定、必要事实与稳定引用、当前工作窗口），MUST NOT 把父图历史消息、旧 Agent 原始结构化输出或旧 Tool 链原样传给模型。

#### Scenario: 各节点只接收自身任务所需的最小字段

- **WHEN** 完整整理子图依次进入 Retriever、Coordinator、Drafter、Reviewer 节点
- **THEN** 每个节点只接收其允许读取的字段（如 Drafter 只接收支持事实及引用、写入指令、草稿基线 revision，不接收 Retriever Tool 原文或旧审查结论），并且这些字段均可从状态化、可验证的业务事实中重组

#### Scenario: 主 Agent 的元对话只接收会话摘要与角色化历史

- **WHEN** 连续完整整理后用户发送闲聊或追问
- **THEN** 主 Agent 只接收会话摘要、最近角色化轮次、当前用户消息、已确认决定与任务状态摘要，不携带旧检索/草稿/审查结果原文或完整 Tool 链

#### Scenario: 本轮用户指令不再从消息流追溯

- **WHEN** 本轮用户指令写入独立会话状态键且随后多次 ReAct 模型调用产生工具回执
- **THEN** 轮次历史重建以该指令键为权威来源，不依赖对消息条目的扫描或从消息流反推

### Requirement: 子 Agent 不继承历史消息

专家直调路径与子图节点路径的子 Agent MUST NOT 继承父会话历史消息；跨节点、跨轮历史 SHALL 由父图结构化状态与会话摘要承担，子 Agent 只见当前准备节点生成的最小初始消息视图。

#### Scenario: 直调路径子 Agent 在全新状态下执行

- **WHEN** 主 Agent 直调某专家
- **THEN** 该专家的初始消息只包含其固定职责指令与父侧组装的任务文本，不包含父图会话历史、旧对话或本任务之外的专家历史

#### Scenario: 子图节点路径专家只见准备后的初始消息

- **WHEN** 完整整理子图的某专家节点执行
- **THEN** 其模型调用所见消息等于该节点入口准备的最小视图，同一节点的调用间可连续累积工具结果，但不得恢复旧轮或跨节点历史

### Requirement: 准备节点重建的消息视图必须保留显式阶段标记语义

阶段推进信息 MUST 由下一准备节点按任务意图显式生成，并 SHALL 保持与既有 Agent 指导一致的“以输入中最后出现的阶段标记为准、无标记则视为初始阶段”语义。

#### Scenario: 阶段标记缺失时不得重复开场白

- **WHEN** 子图进入 DECIDE 或 FINISH 阶段而准备节点生成的消息视图不含显式阶段标记
- **THEN** 该情况不得产出，准备节点必须生成与指导约定一致的标记文本，防止协调 Agent 重复初始开场白或丢失上下文

### Requirement: 上下文预算必须由统一配置约束并在启动时校验

上下文预算 SHALL 由统一部署配置提供（单次调用窗口、输入硬上限、输出预留、安全余量、压缩触发阈值、压缩目标、run 累计输入上限、LLM 压缩调用上限、滚动摘要代数上限），不绑定模型名称；启动时 SHALL 校验阈值间约束关系。

#### Scenario: 预算配置约束生效

- **WHEN** 存在一组预算配置且压缩目标不小于压缩触发阈值，或输入上限与输出预留、安全余量之和大于窗口
- **THEN** 系统在启动时拒绝该配置并给出明确原因

#### Scenario: 单次窗口与 run 累计分别受控

- **WHEN** 一个 run 内 ReAct 循环产生多次模型调用
- **THEN** 单次调用输入不超过输入硬上限，全部调用累计输入不超过 run 累计上限且受既有最大模型调用数共同限制

### Requirement: 确定性压缩必须先于任何有损压缩执行

节点入口估算超过压缩阈值时，MUST 按可复现顺序执行确定性压缩：移除旧 Tool 参数与原文、移除已完成节点原始结构化 JSON、以稳定引用替换正文、按完整轮次从旧到新裁剪会话历史；压缩结果 MUST 可复现，测试可断言。

#### Scenario: 确定性压缩执行且结果可复现

- **WHEN** 同一状态与阈值下节点入口估算超过压缩阈值
- **THEN** 确定性压缩生成压缩前/后 Token、裁剪轮数与引用替换数量，且同一输入两次压缩结果一致

#### Scenario: 确定性压缩保留关键事实

- **WHEN** 确定性压缩移除旧历史与 Tool 原文
- **THEN** 原始目标、人工已确认决定、未解决问题、当前写入/审查引用与仅供恢复目标节点使用的待用管理者指导均保留

### Requirement: 每次模型调用前必须执行预算守卫并记录证据

每次模型调用发送前，当前完整消息链 MUST 接受预算守卫：未超输入上限且 run 累计预算未耗尽时允许调用；超限时只清理最旧且已经闭合的工具调用组，并保护最新未闭合工具调用、匹配的工具结果与当前任务消息；清理后仍超限或 run 累计耗尽时 MUST NOT 发送模型请求。每次调用前与完成后 MUST 记录估算与实际用量日志，实际用量缺失时 MUST NOT 伪报为 0。

#### Scenario: 超限时只清理最旧闭合工具组

- **WHEN** 节点内部某次模型调用前消息链估算超过输入硬上限
- **THEN** 守卫只移除最旧且已闭合的工具调用/结果组且最新未闭合配对保持完整；清理后仍超限时该调用不被发出，run 转为可恢复等待，且不写入实际用量的伪 0 值

### Requirement: LLM 压缩兜底必须在确定性压缩后仍超限时受限执行

只有节点入口确定性压缩后仍超输入上限时，才能由上下文管理组件内部发起受限压缩模型调用；该调用 SHALL 只处理已完成轮次的对话解释与过程说明，MUST NOT 处理来源事实、人工决定、草稿修订版本或当前节点输入；压缩产出 MUST BE 输入中已有引用 ID 的子集，校验失败 SHALL 拒绝结果。

#### Scenario: 压缩输出非法引用时结果被拒绝

- **WHEN** 压缩调用返回的保留引用、决定或问题标识包含输入中不存在的 ID
- **THEN** 该压缩结果被拒绝，不进入任何业务 Agent，run 转为可恢复等待且业务模型调用数不增加

### Requirement: 摘要缓存必须可重建且不新增持久化表

摘要及覆盖进度 SHALL 随父图 Checkpoint 在会话状态中持久化（同一会话可在进程重启、暂停恢复与下一轮中复用），相同摘要来源与目标预算 SHALL 最多压缩一次；摘要失效（来源消息异常修改、压缩规则或摘要 Schema 或 Agent 定义版本变化、会话级 Checkpoint 不存在或已废弃）时 SHALL 从业务权威消息重建。SHALL NOT 为摘要新增数据库表。

#### Scenario: 摘要随会话状态复用且可重建

- **WHEN** 同一会话后续轮次发生压缩需求
- **THEN** 已提交摘要与其后的增量轮次被用于滚动生成，不重复压缩完整历史；覆盖进度与版本不一致时从权威消息源重建并把历史代数重置

### Requirement: 压缩后仍超限的 run 必须进入可恢复等待而非失败

超过一切压缩手段后的节点输入仍大于输入硬上限时，run MUST 进入 `WAITING_FOR_USER`（原因标识为上下文超限），保留当前语义稳定 Checkpoint 与可见说明，MUST NOT 进入失败终态、MUST NOT 进入同输入重试回路。

#### Scenario: 上下文超限转可恢复等待

- **WHEN** 节点入口确定性压缩与受限压缩后仍超输入硬上限
- **THEN** run 进入 `WAITING_FOR_USER`，Checkpoint 保持可恢复，管理员可通过缩小范围或拆分任务后继续

### Requirement: 跨轮对话的权威来源固定在业务消息表

压缩与历史重建所需的跨轮真实对话 SHALL 从业务消息表读取（用户消息与最终回复，最终回复按会话目标过滤排除执行摘要），事件与工具调用记录 SHALL NOT 当作对话喂入压缩模型。

#### Scenario: 压缩输入只含真实用户消息与最终回复

- **WHEN** 需要压缩旧轮对话时按业务消息表读取最近窗口之前的轮次
- **THEN** 输入只包含真实用户指令与其对应的最终回复，不含子 Agent 消息、工具调用、阶段事件、原始候选或公开执行摘要
