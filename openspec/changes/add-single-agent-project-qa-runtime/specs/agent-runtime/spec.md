## Purpose

为 Web 问答及后续文档工作流提供统一、受控且可追溯的服务端 Agent 执行契约，使模型与 Skill 可以替换或版本化，同时不能绕过项目范围、工具权限、运行上限和人工发布边界。

## ADDED Requirements

### Requirement: 运行必须固定启用的 Skill、模型和安全配置版本
系统 SHALL 通过统一 Agent 运行能力启动任务。启动输入 MUST 包含服务端生成或校验的幂等键、已认证操作者、任务类型和该任务类型要求的业务范围；系统 MUST 在首次接受请求时生成稳定运行 ID，并固定启用的 Skill 名称、Skill 版本与内容哈希、模型提供方与模型名、输出结构版本、工具白名单版本、运行限制版本及解析后的业务范围。运行期间配置或 Skill 发生更新 MUST 只影响后续新运行。

内置 `project_qa` Skill MUST 以版本化 Markdown 任务说明加载，并包含名称、版本、适用场景、必要输入、推荐步骤、输出结构、引用要求、拒答条件和验收示例。T6A SHALL 只提供内置版本的加载与查询，不提供管理员在线编辑、启停或发布 Skill 的能力。

#### Scenario: 启动启用 Skill 的新运行
- **WHEN** 已认证调用方以新幂等键提交合法的 `project_qa` 任务
- **THEN** 系统创建一个运行，固定当时启用的 Skill、模型、安全配置和业务范围版本，并返回稳定运行 ID 与初始状态

#### Scenario: 相同幂等键重复提交相同请求
- **WHEN** 同一操作者使用相同幂等键重复提交业务输入完全相同的启动请求
- **THEN** 系统返回原运行及其当前状态，不重复调用模型、不重复执行工具也不创建第二份运行记录

#### Scenario: 相同幂等键提交不同请求
- **WHEN** 同一操作者使用已存在的幂等键提交不同任务、问题或业务范围
- **THEN** 系统拒绝请求并返回 `AGENT_RUN_IDEMPOTENCY_CONFLICT`，原运行保持不变

#### Scenario: Skill 在运行期间更新
- **WHEN** 一个运行已开始后内置 Skill 或安全配置发布了新版本
- **THEN** 当前运行继续使用启动时固定的版本，新版本只被后续新运行采用

#### Scenario: 没有可用 Skill
- **WHEN** 请求的任务类型没有可加载且校验通过的启用 Skill
- **THEN** 系统不调用模型并以 `AGENT_SKILL_UNAVAILABLE` 拒绝启动

### Requirement: 模型调用必须通过可替换且受控的运行边界
系统 SHALL 通过不向业务用例泄漏具体模型 SDK 类型的模型端口执行同步或流式模型调用，并 SHALL 支持生产 MiniMax 2.7 兼容模型和能够脚本化模型回复、工具请求、Token 用量、延迟与失败的测试替身。模型请求 MUST 仅包含本次运行固定的系统规则、Skill、用户输入和经服务端裁剪的证据；模型密钥、内部端点和其他运行数据不得进入提示内容或公开事件。

#### Scenario: 生产模型流式返回
- **WHEN** MiniMax 兼容模型按配置正常返回文本增量、工具请求和用量信息
- **THEN** 运行边界把它们转换为项目自有事件与结果类型，并保留模型描述和实际可得的 Token 用量

#### Scenario: 测试模型驱动确定性工具循环
- **WHEN** 测试替身按脚本依次请求允许工具并返回最终结果
- **THEN** 运行执行可重复的相同步骤、工具摘要、引用和终态，不需要真实模型凭据或外部网络

#### Scenario: 模型暂时不可用
- **WHEN** 模型连接失败、限流、鉴权失败或返回不可解析响应
- **THEN** 系统以脱敏的 `AGENT_MODEL_UNAVAILABLE` 或 `AGENT_MODEL_RESPONSE_INVALID` 结束运行并保留失败记录，既有文档浏览、知识搜索和代码搜索能力继续可用

### Requirement: 工具执行必须由服务端白名单和固定范围授权
每个 Skill SHALL 只能看到并调用其服务端结构化配置允许的内部工具。工具执行器 MUST 在每次调用前校验工具名、操作者权限、运行固定的项目与分支、活动代码快照、允许的知识范围、参数类型和服务端上限；模型、Skill、用户问题或检索材料 MUST NOT 指定其他项目/分支、历史 generation、服务器路径或扩大工具权限。未知工具、Shell、任意 HTTP、数据库管理和正式知识写入能力 MUST 不得注册给 T6A Agent。

#### Scenario: 调用白名单内的只读工具
- **WHEN** `project_qa` 在固定项目与分支内以合法参数调用声明的知识搜索、代码搜索或代码片段读取工具
- **THEN** 系统复用对应应用服务执行查询，记录有限工具摘要，并只返回该运行范围内的有限结果

#### Scenario: 模型尝试跨范围调用
- **WHEN** 模型工具参数包含另一项目、另一分支、历史快照、非活动 commit、generation、服务器路径或超出上限的读取范围
- **THEN** 工具在访问底层检索前拒绝调用，以 `AGENT_TOOL_SCOPE_VIOLATION` 终止运行，且响应和事件不暴露越权目标是否存在

#### Scenario: 模型请求白名单外工具
- **WHEN** 模型请求未在当前 Skill 白名单中的工具或尝试执行 Shell、任意网络访问、数据库管理、知识修改或发布
- **THEN** 系统不执行该调用，以 `AGENT_TOOL_NOT_ALLOWED` 终止运行并记录工具名摘要和失败语义

#### Scenario: 不可信材料包含操作指令
- **WHEN** 知识、代码、用户问题或 Skill 示例中包含要求更改项目范围、泄露提示、调用外部网络或发布知识的指令
- **THEN** 系统只把材料作为有限证据文本处理，结构化权限与工具校验保持不变

### Requirement: 每次运行必须受到硬性资源限制
系统 SHALL 为每次运行固定最大 Agent 步骤数、最大模型调用次数、总超时、单次检索结果数、单次片段长度和总上下文长度。客户端与模型 MAY 请求更小的值但 MUST NOT 提高服务端上限；计数和截止时间 MUST 由服务端执行器计算，不得依赖模型自行遵守。达到任何上限时系统 MUST 停止后续模型和工具调用，以对应的稳定错误码安全结束，并保留截止前已完成的只读证据摘要。

#### Scenario: 在全部限制内完成
- **WHEN** 运行在步骤、模型调用、时间、检索和上下文限制内得到有效结果
- **THEN** 系统完成运行并记录实际步骤数、模型调用数、检索数量、上下文裁剪量、Token 和耗时

#### Scenario: 达到步骤或模型调用上限
- **WHEN** 模型继续请求工具或推理步骤将超过最大步骤数或模型调用次数
- **THEN** 系统不执行超限调用，以 `AGENT_STEP_LIMIT_EXCEEDED` 或 `AGENT_MODEL_CALL_LIMIT_EXCEEDED` 安全终止

#### Scenario: 达到总超时
- **WHEN** 运行到达固定截止时间且模型或工具尚未完成
- **THEN** 系统取消可取消的后续工作，以 `AGENT_RUN_TIMEOUT` 结束，并忽略截止时间后到达的模型文本或工具结果

#### Scenario: 候选或上下文超过限制
- **WHEN** 工具或模型准备阶段产生超过检索条数、片段长度或总上下文长度的内容
- **THEN** 系统按稳定规则裁剪并记录裁剪数量；若裁剪后无法保留可引用证据，则不生成无依据回答

### Requirement: 运行记录和公开事件必须可追溯且不暴露隐藏推理
系统 SHALL 持久化运行状态、固定版本、解析范围、输入来源标识、阶段、有限工具调用摘要、证据引用、模型用量、耗时、结果类型和脱敏错误。状态 MUST 只按 `ACCEPTED → RUNNING → COMPLETED|FAILED|TERMINATED` 前进，`COMPLETED` 的结果类型 MUST 明确区分 `ANSWER` 与 `REFUSAL`；终态不得回退。公开事件 SHALL 带运行 ID、单调递增序号、事件类型和服务端时间，支持调用方从已知序号读取后续事件，并至少表达运行开始、Skill 固定、模型阶段、工具开始/完成、回答文本增量、拒答、完成和失败。

系统 MUST NOT 保存或公开模型原始思维链、完整系统提示、完整用户问题、完整知识/代码正文、模型密钥、内部端点、对象键、服务器绝对路径或连接信息。工具参数和错误只保存稳定标识、长度、数量、范围及脱敏摘要；模型没有返回 Token 用量时 MUST 记录为未知，不得伪造为零。

#### Scenario: 完成带工具调用的运行
- **WHEN** Agent 调用只读工具并形成回答或拒答
- **THEN** 运行快照与按序事件能够证明固定版本、范围、实际阶段、工具名称/数量、来源标识、引用、Token 可用性、耗时和最终结果，且不包含隐藏推理或完整证据正文

#### Scenario: 从已知序号继续读取事件
- **WHEN** 下游调用方携带某运行已消费的最后事件序号重新读取
- **THEN** 系统按序返回更大的持久化公开事件，不重复更早事件，并以当前运行快照作为事实来源

#### Scenario: 运行失败后收到迟到结果
- **WHEN** 运行已经进入失败或终止状态后模型或工具仍返回迟到内容
- **THEN** 系统不得改变终态或把迟到内容作为回答发布，只记录脱敏的忽略结果摘要

#### Scenario: T6A 运行期间后端重启
- **WHEN** 后端启动时发现上次进程遗留的 `ACCEPTED` 或 `RUNNING` 单 Agent 运行
- **THEN** 系统以 `AGENT_RUN_INTERRUPTED` 将其单调终结并保留既有事件，不自动重放模型或工具调用；从检查点恢复由后续 T6B 提供

#### Scenario: 敏感内容进入运行输入或错误
- **WHEN** 输入、证据、模型响应或异常包含密钥样式、内部地址、完整正文或服务器路径
- **THEN** 持久化记录、结构化日志和公开事件只保留脱敏摘要，敏感原文不被写入

### Requirement: Agent 不得越过正式知识发布边界
T6A Agent SHALL 只执行授权的只读证据查询并产生临时回答或拒答。除运行追踪元数据外，它 MUST NOT 创建、编辑、归档、替代、索引或发布知识文档，也 MUST NOT 修改代码快照、项目、分支、账号或系统配置；后续新增写工具时也必须由独立规格和人工审核边界授权。

#### Scenario: 正常问答完成
- **WHEN** `project_qa` 生成带引用回答或拒答
- **THEN** 系统只持久化运行、事件、工具摘要和引用元数据，不改变任何正式知识、索引、代码快照或项目配置

#### Scenario: 模型输出伪造发布指令
- **WHEN** 模型在文本或工具请求中声称已批准、发布或修改正式知识
- **THEN** 系统不执行任何业务写入，且该文本不能改变正式知识状态或检索资格
