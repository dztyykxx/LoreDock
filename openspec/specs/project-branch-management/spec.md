# project-branch-management Specification

## Purpose

建立 LoreDock 后续知识、代码快照、检索与问答共同依赖的项目和分支范围主数据，并为管理员维护与普通成员选择知识空间提供一致、可追踪且不会跨越停用边界的 Web/API 行为。

## Requirements

### Requirement: 管理员可以创建带默认分支的项目
系统 SHALL 通过 `POST /api/admin/projects` 接收项目名称、项目标识、简介和主要技术栈，并在同一事务中创建状态为 `ENABLED` 的项目及唯一默认 `main` 分支。成功响应 SHALL 返回项目 UUID、全部输入字段、状态、默认分支和审计时间。该 POST 操作不承诺幂等，但项目标识全局唯一可防止重试产生重复项目。

项目名称 SHALL 为去除首尾空白后的 1～100 个字符；项目标识 SHALL 为 2～64 个小写字母、数字或单连字符组成的 kebab-case 值；简介最大 1000 个字符；主要技术栈最大 255 个字符。

#### Scenario: 创建有效项目
- **WHEN** 管理员提交合法且未使用的名称、标识、简介和主要技术栈
- **THEN** 系统返回 HTTP 201，项目状态为 `ENABLED`、默认分支为 `main`，且项目与 `main` 分支同时可查询

#### Scenario: 项目标识重复
- **WHEN** 管理员使用已存在的项目标识再次创建项目
- **THEN** 系统返回 HTTP 409 和 `PROJECT_IDENTIFIER_CONFLICT`，不新增项目或重复的 `main` 分支

#### Scenario: 项目输入无效
- **WHEN** 项目名称为空、项目标识不符合 kebab-case 或任一字段超过长度限制
- **THEN** 系统返回 HTTP 400 字段校验错误，不写入项目或分支数据

#### Scenario: 默认分支创建失败
- **WHEN** 项目记录已准备写入但默认 `main` 分支无法持久化
- **THEN** 整个创建事务回滚，普通和管理查询均看不到半成品项目

### Requirement: 普通项目查询只暴露已启用项目
系统 SHALL 允许 `ADMIN` 与 `MEMBER` 通过 `GET /api/projects` 查询已启用项目，并返回项目标识、名称、简介、主要技术栈、默认分支和真实分支数量。普通查询 MUST NOT 返回停用项目；按标识访问停用或不存在项目时均返回 HTTP 404 和 `PROJECT_NOT_FOUND`，避免通过普通入口枚举停用项目。

#### Scenario: 成员查看已启用项目
- **WHEN** 已登录成员请求普通项目列表
- **THEN** 系统按名称稳定排序返回全部已启用项目，并包含每个项目的真实分支数量和默认 `main` 分支

#### Scenario: 普通列表排除停用项目
- **WHEN** 项目已被管理员停用
- **THEN** 管理员和成员通过普通项目列表均看不到该项目

#### Scenario: 普通入口访问停用项目
- **WHEN** 已登录用户通过普通项目详情接口请求停用项目的标识
- **THEN** 系统返回 HTTP 404 和 `PROJECT_NOT_FOUND`，不返回项目元数据或分支信息

### Requirement: 管理接口可以查看全部项目状态
系统 SHALL 允许管理员通过 `/api/admin/projects` 查询已启用和已停用项目，并按 UUID 查询项目详情及分支。管理查询 SHALL 明确返回状态，不得把停用项目伪装成不存在；`MEMBER` 不得使用这些接口。

#### Scenario: 管理员查看停用项目
- **WHEN** 管理员请求包含停用项目的管理列表或该项目详情
- **THEN** 系统返回项目及其 `DISABLED` 状态、默认分支和现有分支，不修改任何数据

#### Scenario: 管理详情不存在
- **WHEN** 管理员按不存在的项目 UUID 请求详情
- **THEN** 系统返回 HTTP 404 和 `PROJECT_NOT_FOUND`

### Requirement: 管理员可以幂等启用或停用项目
系统 SHALL 通过 `PATCH /api/admin/projects/{projectId}/status` 接收目标状态 `ENABLED` 或 `DISABLED`。设置为当前状态 SHALL 成功且不产生额外业务副作用；停用 SHALL 只影响普通查询可见性，不删除项目、分支、审计信息或后续关联数据。

#### Scenario: 停用已启用项目
- **WHEN** 管理员把一个已启用项目的目标状态设置为 `DISABLED`
- **THEN** 系统更新状态和审计信息，该项目立即退出普通查询，但仍保留在管理查询中

#### Scenario: 重复停用项目
- **WHEN** 管理员再次把已经停用的项目设置为 `DISABLED`
- **THEN** 系统返回当前停用状态，不删除或重复创建任何数据

#### Scenario: 重新启用项目
- **WHEN** 管理员把停用项目设置为 `ENABLED`
- **THEN** 项目重新出现在普通项目列表，原有 UUID、标识和分支保持不变

### Requirement: 管理员可以添加项目分支
系统 SHALL 通过 `POST /api/admin/projects/{projectId}/branches` 为存在的项目添加分支。分支名 SHALL 为 1～128 个字符并接受 `main`、`feature/import-export` 等常用 Git 风格名称，同时拒绝空白、控制字符、反斜杠、连续斜杠、`..` 路径段以及首尾斜杠。分支名在同一项目内唯一，但不同项目可以使用相同分支名。

#### Scenario: 添加演示分支
- **WHEN** 管理员向网络设计工具项目添加合法且未存在的 `feature/import-export`
- **THEN** 系统返回 HTTP 201，新分支只出现在该项目的分支列表中，且默认分支仍为 `main`

#### Scenario: 同一项目分支重复
- **WHEN** 管理员向同一项目再次添加已有分支名
- **THEN** 系统返回 HTTP 409 和 `BRANCH_NAME_CONFLICT`，不创建重复分支

#### Scenario: 不同项目使用同名分支
- **WHEN** 管理员分别向两个项目添加相同的合法分支名
- **THEN** 两次创建均可成功，两个分支由各自项目范围隔离

#### Scenario: 分支名无效
- **WHEN** 管理员提交空白、包含反斜杠、连续斜杠、`..` 路径段或首尾斜杠的分支名
- **THEN** 系统返回 HTTP 400 字段校验错误，不写入分支

#### Scenario: 向不存在项目添加分支
- **WHEN** 管理员使用不存在的项目 UUID 添加分支
- **THEN** 系统返回 HTTP 404 和 `PROJECT_NOT_FOUND`

### Requirement: 项目详情明确解析当前分支
系统 SHALL 允许已登录用户通过普通项目详情接口以可选 `branch` 查询参数选择分支。省略参数时 SHALL 选择 `main`；指定存在分支时 SHALL 选择该分支；指定不存在分支时 SHALL 返回 HTTP 404 和 `BRANCH_NOT_FOUND`，MUST NOT 回退到其他分支。响应 SHALL 同时返回所选分支和全部可选分支，供后续检索入口复用。

#### Scenario: 省略分支时选择 main
- **WHEN** 用户请求已启用项目详情且没有提供 `branch`
- **THEN** 响应的所选分支为 `main`

#### Scenario: 选择存在的演示分支
- **WHEN** 用户请求项目详情并指定该项目已有的 `feature/import-export`
- **THEN** 响应的所选分支为该演示分支，且不混入其他项目的同名分支

#### Scenario: 请求不存在分支
- **WHEN** 用户为项目指定不存在的分支名
- **THEN** 系统返回 HTTP 404 和 `BRANCH_NOT_FOUND`，不静默使用 `main` 或其他分支

### Requirement: 项目与分支持久化遵守审计和完整性约束
系统 MUST 通过数据库唯一约束保护项目标识和项目内分支名，并 SHALL 记录 UTC 创建/更新时间及操作者。项目、分支和 API 模型 SHALL 保持身份与状态语义，不得因重启、并发创建或序列化方式发生变化。

#### Scenario: 并发创建相同项目标识
- **WHEN** 两个管理员请求并发创建相同项目标识
- **THEN** 至多一个请求成功，另一个返回 `PROJECT_IDENTIFIER_CONFLICT`，数据库中只有一个项目和一个默认 `main` 分支

#### Scenario: 并发添加相同分支
- **WHEN** 两个管理员请求并发向同一项目添加相同分支名
- **THEN** 至多一个请求成功，另一个返回 `BRANCH_NAME_CONFLICT`，数据库中只有一条该分支记录

#### Scenario: 服务重启后查询
- **WHEN** 服务重启后再次查询已创建的项目和分支
- **THEN** UUID、项目标识、状态、分支归属、默认分支和审计时间保持一致

### Requirement: 项目列表页面遵循设计基线并区分真实数据与样例占位
前端 SHALL 参考 Pencil `02 · 项目列表` 画布实现侧栏、顶部栏、通用业务知识入口、已启用项目区和项目卡片。当前后端接口已提供的名称、标识、简介、主要技术栈、分支数量、默认分支和项目总数 SHALL 使用真实响应或由真实响应计算，不得被静态样例覆盖。T2 尚未提供后端接口的知识数量、快照等后续能力信息 MAY 按设计稿中的样例静态填充，以保持桌面页面的既定信息层级；这些样例不得写入后端、参与权限或业务状态判断，也不得触发尚不存在的接口。管理员 SHALL 获得创建项目入口，成员不得看到该入口。

#### Scenario: 加载项目列表
- **WHEN** 已登录用户进入项目列表页
- **THEN** 页面从普通项目 API 加载已启用项目，以真实响应展示项目字段与项目数量，并可在无对应后端接口的后续能力位置展示设计稿样例

#### Scenario: 设计样例不得覆盖已有接口数据
- **WHEN** 普通项目 API 返回的项目、默认分支或分支数量与设计稿样例不同
- **THEN** 页面展示 API 返回或据其计算的真实值，仅在当前 API 未定义的字段位置保留设计稿样例

#### Scenario: 在当前列表中筛选项目
- **WHEN** 用户在设计稿的搜索字段输入项目名称或标识片段
- **THEN** 前端在已加载且有权查看的项目集合内筛选卡片，不查询或显示停用项目

#### Scenario: 空项目列表
- **WHEN** 普通项目 API 返回空列表
- **THEN** 页面显示可理解的空状态；管理员可从空状态创建项目，成员只看到联系管理员的提示

#### Scenario: 列表加载失败
- **WHEN** 普通项目 API 失败
- **THEN** 页面显示安全错误和重试入口，不保留过期项目作为成功结果，也不显示后端内部异常

### Requirement: 项目设置页面遵循设计基线并按角色降级
前端 SHALL 参考 Pencil `10 · 项目设置 / 分支管理` 画布实现项目骨架、基本信息、分支列表、项目状态和 MCP 项目标识区域。管理员可创建分支并启用或停用项目；`MEMBER` 仅可查看已启用项目及分支，所有写控件 SHALL 隐藏或禁用。项目、分支、状态和 MCP 项目标识等当前接口已提供的数据 SHALL 使用真实响应。知识、草稿、整理报告和代码快照等尚无后端接口的后续能力 MAY 保留导航结构并按设计稿展示静态样例数量、活动 commit 或状态；相关入口和操作不得发起不存在的接口请求，也不得把样例作为后端已持久化事实。

#### Scenario: 管理员查看项目设置
- **WHEN** 管理员进入项目设置页
- **THEN** 页面加载管理详情，展示真实基本信息、状态和分支，并提供创建分支与启停操作

#### Scenario: 管理员确认停用项目
- **WHEN** 管理员触发停用操作
- **THEN** 页面先明确提示该项目将退出普通查询但数据保留，确认后才调用状态接口，并以服务端结果刷新页面

#### Scenario: 成员查看项目范围
- **WHEN** 成员打开已启用项目的项目页面
- **THEN** 页面通过普通详情接口展示项目与分支，且不渲染创建分支、启停或其他管理操作

#### Scenario: 无后端接口的未来能力使用设计样例
- **WHEN** 当前版本尚未提供知识、草稿、整理报告或代码快照接口
- **THEN** 页面可以按 Pencil 设计稿展示对应样例数量、commit 和状态，但相关内容保持静态且不发起不存在的接口请求

#### Scenario: 桌面浏览器访问核心页面
- **WHEN** 用户在电脑浏览器中以 Pencil 设计稿的桌面尺寸访问登录、项目列表或项目设置页
- **THEN** 页面按照设计稿的信息层级、侧栏结构和主要交互呈现；移动端和窄屏专项布局不属于本变更的验收范围

### Requirement: 演示项目数据可以安全且可重复准备
系统 SHALL 提供显式、非生产默认且可重复执行的数据准备入口，用于创建网络设计工具项目、小型对照项目、`main` 和场景包演示分支。重复执行 SHALL 复用相同项目标识与分支，不产生重复记录；正式运行逻辑和 Flyway 迁移 MUST NOT 包含公司内部真实名称、代码、Wiki 内容或凭据。

#### Scenario: 首次准备演示项目
- **WHEN** 操作者在明确启用的演示或测试环境执行数据准备入口
- **THEN** 系统创建两个已启用项目，并为网络设计工具项目准备 `main` 和场景包演示分支

#### Scenario: 重复准备演示项目
- **WHEN** 操作者再次执行相同的数据准备入口
- **THEN** 系统报告项目和分支已存在或已复用，数据库不产生重复记录

#### Scenario: 生产环境未显式启用数据准备
- **WHEN** 生产环境正常启动且未显式启用演示数据准备
- **THEN** 系统不会自动创建演示项目、分支、账号或凭据
