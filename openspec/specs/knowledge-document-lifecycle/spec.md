# knowledge-document-lifecycle Specification

## Purpose

为人工整理、Wiki 转换和后续 Agent 草稿提供统一的知识文档事实来源，使内容、来源、适用范围、发布状态、替代关系与正式检索同步状态可被 Web、检索和 MCP 一致解释，并确保未审核或已退出生命周期的内容不会成为正式知识。

## Requirements

### Requirement: 管理员可以创建和编辑知识文档
系统 SHALL 允许管理员创建 `MARKDOWN` 或 `PLAIN_TEXT` 文档，并维护标题、正文、目录、标签、来源类型、原 Wiki URL、原文件名和人工整理说明。新建文档 MUST 处于 `DRAFT`；标题、正文、目录、标签和来源字段 MUST 接受明确的长度、数量与格式校验，失败时返回 HTTP 400 和 `INVALID_REQUEST`，且不得保存部分修改。

#### Scenario: 创建 Markdown 草稿
- **WHEN** 管理员提交合法标题、Markdown 正文、目录、标签、来源和适用范围
- **THEN** 系统返回 HTTP 201 和状态为 `DRAFT` 的完整文档视图，并记录创建时间、更新时间和操作者

#### Scenario: 创建纯文本草稿
- **WHEN** 管理员选择 `PLAIN_TEXT` 并提交合法纯文本正文
- **THEN** 系统按原文保存正文且不把它解释为 Markdown、HTML 或可执行指令

#### Scenario: 编辑文档内容与元数据
- **WHEN** 管理员修改未归档文档的标题、正文、目录、标签、来源或适用范围
- **THEN** 系统在一个事务中保存全部修改、增加文档修订号并返回更新后的视图

#### Scenario: 编辑归档文档
- **WHEN** 管理员尝试修改状态为 `ARCHIVED` 的文档
- **THEN** 系统返回 HTTP 409 和 `DOCUMENT_STATE_CONFLICT`，文档及其检索同步状态保持不变

#### Scenario: 请求包含无效字段
- **WHEN** 创建或编辑请求包含空标题、空正文、重复标签、非法目录或超过已公布限制的内容
- **THEN** 系统返回 HTTP 400 和字段级校验信息，不创建文档且不保存任何部分修改

### Requirement: 文档范围必须由项目和分支主数据约束
系统 SHALL 支持 `GLOBAL`、`PROJECT`、`BRANCH` 三种互斥知识范围。`GLOBAL` 文档 MUST NOT 关联项目或分支；`PROJECT` 文档 MUST 关联一个存在的项目且 MUST NOT 关联分支；`BRANCH` 文档 MUST 同时关联项目及该项目下存在的分支。系统 MUST 使用项目和分支的稳定标识执行范围校验与持久化，不得依赖名称拼接路径或在读取后再隐藏跨范围数据。

#### Scenario: 创建通用知识
- **WHEN** 管理员创建 `GLOBAL` 文档且未提交项目和分支
- **THEN** 系统保存通用范围，后续项目上下文可以按查询规则引用它，但全局入口不会召回任何项目或分支文档

#### Scenario: 创建项目级知识
- **WHEN** 管理员选择存在的项目并创建 `PROJECT` 文档
- **THEN** 系统将文档绑定到该项目且不绑定任何分支

#### Scenario: 创建分支级知识
- **WHEN** 管理员选择项目和该项目下存在的分支并创建 `BRANCH` 文档
- **THEN** 系统同时保存项目与分支范围，其他项目或同项目其他分支的普通浏览与正式检索均不可见该文档

#### Scenario: 分支不属于所选项目
- **WHEN** 管理员为 `BRANCH` 文档提交另一个项目的分支或未知分支
- **THEN** 系统返回 HTTP 400 和 `DOCUMENT_SCOPE_INVALID`，不得创建或修改文档

#### Scenario: 范围字段残留或缺失
- **WHEN** 请求为 `GLOBAL` 提交项目、为 `PROJECT` 提交分支，或为 `PROJECT`、`BRANCH` 缺少必要关联
- **THEN** 系统返回 HTTP 400 和 `DOCUMENT_SCOPE_INVALID`，不得静默丢弃、补全或回退范围字段

### Requirement: 普通浏览必须按入口范围和生命周期前置过滤
系统 SHALL 为已登录的管理员和普通成员提供目录浏览与文档读取。全局入口 MUST 只返回 `GLOBAL` 且 `PUBLISHED` 的文档；项目入口 MUST 返回 `GLOBAL`、当前项目的 `PROJECT` 以及当前项目当前分支的 `BRANCH` 文档，并 MUST 在查询层排除 `DRAFT`、`ARCHIVED`、其他项目、其他分支以及停用项目的项目知识。管理员管理查询 SHALL 可以按范围、目录、状态和标签查看草稿及归档文档。

#### Scenario: 普通成员浏览项目目录
- **WHEN** 普通成员选择一个已启用项目及其分支并打开某个目录
- **THEN** 系统返回允许范围内已发布文档的目录节点和稳定分页摘要，且每项包含标题、范围、标签、来源、更新时间和状态

#### Scenario: 普通成员进入通用业务知识
- **WHEN** 普通成员从通用业务知识入口浏览目录
- **THEN** 系统只返回已发布通用文档，不返回任何项目级或分支级文档

#### Scenario: 直接读取不属于当前上下文的文档
- **WHEN** 普通成员使用文档 ID 请求其他项目、其他分支、草稿或归档文档
- **THEN** 系统返回 HTTP 404 和 `DOCUMENT_NOT_FOUND`，不泄露该文档是否存在或其元数据

#### Scenario: 浏览停用项目
- **WHEN** 普通成员尝试通过普通入口浏览已停用项目的知识
- **THEN** 系统返回 HTTP 404，且不得先加载停用项目文档再在响应层隐藏

#### Scenario: 管理员筛选生命周期状态
- **WHEN** 管理员在管理视图按范围、目录和 `DRAFT`、`PUBLISHED` 或 `ARCHIVED` 状态筛选
- **THEN** 系统返回匹配文档并明确显示其状态、修订号和检索同步状态

### Requirement: 文档状态转换必须由管理员显式控制
系统 SHALL 支持 `DRAFT`、`PUBLISHED`、`ARCHIVED` 状态。创建和导入只能产生 `DRAFT`；只有管理员调用发布操作后文档才能成为 `PUBLISHED`；`DRAFT` 或 `PUBLISHED` 可以归档，`ARCHIVED` 在本变更中为终态。发布和归档 SHALL 使用事务化条件更新防止并发状态覆盖；对已处于目标状态的重复请求 SHALL 返回当前结果且不重复产生副作用。

#### Scenario: 管理员发布完整草稿
- **WHEN** 管理员确认发布一个内容、来源和范围均有效的 `DRAFT` 文档
- **THEN** 系统把状态改为 `PUBLISHED`、记录发布人与发布时间、增加修订号并把检索同步状态标记为 `PENDING`

#### Scenario: 普通成员尝试发布
- **WHEN** 普通成员绕过前端直接调用发布或归档接口
- **THEN** 系统返回 HTTP 403 和 `AUTH_FORBIDDEN`，文档、替代关系和检索状态均不改变

#### Scenario: 重复发布已发布文档
- **WHEN** 管理员再次发布没有发生其他变化的 `PUBLISHED` 文档
- **THEN** 系统返回当前文档且不改变发布时间、修订号或检索任务

#### Scenario: 归档草稿或已发布文档
- **WHEN** 管理员确认归档一个 `DRAFT` 或 `PUBLISHED` 文档
- **THEN** 系统把状态改为 `ARCHIVED`、记录归档人与归档时间，并立即使其不再满足普通浏览和正式检索资格

#### Scenario: 尝试恢复归档文档
- **WHEN** 管理员尝试编辑或发布 `ARCHIVED` 文档
- **THEN** 系统返回 HTTP 409 和 `DOCUMENT_STATE_CONFLICT`，并提示通过新建文档及替代关系完成修订

### Requirement: 替代关系必须原子归档旧文档并保持可追溯
系统 SHALL 允许一个新文档声明一个被替代的旧文档。新旧文档 MUST 不同、具有完全相同的知识范围，且旧文档在新文档发布前 MUST 为 `PUBLISHED`。发布新文档时，系统 MUST 在同一事务中将新文档置为 `PUBLISHED`、将旧文档置为 `ARCHIVED` 并保存双向可读的替代关系；任何校验或持久化失败 MUST 回滚全部变化。系统 MUST 拒绝自替代、循环替代以及一个旧文档被多个当前文档竞争替代。

#### Scenario: 发布替代文档
- **WHEN** 管理员发布一个声明替代同范围已发布旧文档的草稿
- **THEN** 新文档成为 `PUBLISHED`，旧文档在同一事务中成为 `ARCHIVED`，两者详情均可查看“替代/被替代”关系

#### Scenario: 替代不同范围的文档
- **WHEN** 新文档与旧文档的范围类型、项目或分支任一不同
- **THEN** 系统返回 HTTP 409 和 `DOCUMENT_REPLACEMENT_CONFLICT`，新旧文档状态均不改变

#### Scenario: 替代关系形成循环
- **WHEN** 新的替代声明会使替代链回到当前文档
- **THEN** 系统返回 HTTP 409 和 `DOCUMENT_REPLACEMENT_CONFLICT`，不得保存该关系

#### Scenario: 旧文档已被其他文档替代
- **WHEN** 管理员发布的文档声明替代一个已被另一当前文档替代的旧文档
- **THEN** 系统返回 HTTP 409 和 `DOCUMENT_REPLACEMENT_CONFLICT`，不得覆盖已有追溯关系

#### Scenario: 归档旧文档失败
- **WHEN** 发布新文档过程中旧文档状态被并发修改或数据库写入失败
- **THEN** 整个发布操作失败并回滚，新文档仍为草稿且不存在半完成的替代关系

### Requirement: 正式检索数据集只接收已发布且仍有资格的文档
系统 SHALL 维护一个可供后续 T5 检索能力读取的活动知识索引数据集。文档创建、编辑、发布或范围变化后 SHALL 显示 `PENDING` 或 `STALE` 同步状态；管理员 SHALL 可以提交一次全量知识重新索引并获得持久化后台任务 ID。任务 MUST 仅快照当时有效的 `PUBLISHED` 文档，在完整构建与校验成功后原子切换活动数据集；失败或进程中断 MUST 保留上一个成功数据集及明确失败信息。正式检索消费者 MUST 在查询层再次校验文档实时状态、项目、分支和知识范围，确保已归档或已越界文档即使仍存在于旧数据集中也不可返回。

#### Scenario: 提交重新索引
- **WHEN** 管理员请求重新索引且当前没有待执行或运行中的知识重建任务
- **THEN** 系统返回 HTTP 202、任务 ID 和 `PENDING` 状态，并在受控后台执行器中开始构建新数据集

#### Scenario: 重复提交正在进行的重新索引
- **WHEN** 管理员在已有 `PENDING` 或 `RUNNING` 知识重建任务时再次请求重新索引
- **THEN** 系统返回现有任务 ID 和当前状态，不创建并行全量重建任务

#### Scenario: 重新索引成功
- **WHEN** 后台任务完整读取并验证所有当时有效的已发布文档
- **THEN** 系统原子切换到新活动数据集、把任务标记为 `SUCCEEDED`，并让快照修订一致的文档显示 `SYNCED`

#### Scenario: 重新索引失败
- **WHEN** 构建、校验或活动切换任一步失败
- **THEN** 系统把任务标记为 `FAILED` 并保存脱敏错误摘要，上一个成功活动数据集继续可用，未完成数据不得成为活动数据集

#### Scenario: 归档尚未重新索引的文档
- **WHEN** 一个仍存在于旧活动数据集的文档被归档
- **THEN** 普通浏览和任何正式检索入口立即排除该文档，不等待下一次重新索引

#### Scenario: 草稿从未进入数据集
- **WHEN** 管理员创建、导入或编辑一个仍为 `DRAFT` 的文档并执行重新索引
- **THEN** 新活动数据集不包含该草稿的标题、正文、标签或来源内容

### Requirement: 知识管理页面必须呈现真实生命周期和操作反馈
前端 SHALL 参考 Pencil `03 · 项目详情 / 知识管理` 与 `05 · 新建 / 编辑知识`，在桌面浏览器提供通用或项目知识目录、文档查看、新建/编辑、发布、归档、替代选择和重新索引入口。页面 MUST 使用真实 API 数据表达加载、空、失败、保存成功、权限受限、未同步、任务执行中与任务失败状态；前端隐藏写控件不得替代服务端授权。

#### Scenario: 管理员维护项目知识
- **WHEN** 管理员进入已启用项目的知识页并选择分支
- **THEN** 页面加载真实目录和文档状态，允许新建、编辑、导入、发布、归档、选择同范围替代文档及提交重新索引

#### Scenario: 普通成员浏览知识
- **WHEN** 普通成员进入通用或项目知识页
- **THEN** 页面只展示其当前范围内已发布文档，且不渲染新建、编辑、导入、发布、归档或重新索引操作

#### Scenario: 页面请求失败
- **WHEN** 目录、详情、保存或生命周期 API 失败
- **THEN** 页面保留当前上下文，显示不泄露内部异常的错误与重试入口，不把失败操作显示为成功

#### Scenario: 破坏性操作确认
- **WHEN** 管理员选择归档文档或发布会归档旧文档的替代文档
- **THEN** 页面在提交前明确展示受影响文档和后果，提交期间防止重复操作并在完成后刷新真实服务端状态

### Requirement: 知识任务必须按完整审核集合原子发布多文档
管理员 SHALL 只能发布仍为 `PROCESSING` 的知识任务，并 SHALL 提交任务当前全部有效工作文档的 `draft_id/reviewed_revision` 完整集合与任务级幂等键。服务端 MUST 在一个事务中验证集合、当前工作修订和固定正式基线，执行全部 ADD/MODIFY，更新草稿、任务与候选输入状态，记录发布事实并创建一个持久化索引任务。任一校验或写入失败 MUST 回滚整个集合，MUST NOT 留下部分正式发布。

#### Scenario: 同时发布新增与修改
- **WHEN** 审核集合包含一份 ADD 和一份 MODIFY，所有当前修订、目录标题和正式基线都有效
- **THEN** 系统在同一事务创建新正式文档、更新既有正式文档、把任务设为 PUBLISHED、把候选输入设为 CURATED，并只创建一个索引任务

#### Scenario: 审核集合不完整
- **WHEN** 请求遗漏当前有效工作文档、包含额外草稿、重复草稿或包含空 v0 草稿
- **THEN** 系统拒绝整个请求且不发布任何文档

#### Scenario: 任一正式基线变化
- **WHEN** 任一 MODIFY 工作文档固定的 baseline_revision 已不再是正式文档当前修订
- **THEN** 系统报告冲突并回滚全部 ADD/MODIFY，其他无冲突文档也不发布

#### Scenario: 发布幂等重试
- **WHEN** 管理员以相同幂等键和相同审核集合重试已成功请求
- **THEN** 系统返回原发布结果，不生成重复正式文档、正式修订或索引任务

#### Scenario: 发布幂等键异参
- **WHEN** 同一任务使用已存在幂等键提交不同审核集合
- **THEN** 系统拒绝为发布幂等冲突，原发布事实保持不变

### Requirement: 知识任务 MODIFY 必须保持正式文档稳定身份
知识任务的 MODIFY 发布 SHALL 更新固定 `baseline_document_id` 对应的同一正式文档，只修改 Markdown 正文并增加正式修订号；标题、目录、标签和 document_id SHALL 保持不变。普通 MODIFY MUST NOT 创建替代文档或归档基线。ADD SHALL 创建新正式文档 ID，并在发布时验证目录格式合法和项目内标题无冲突；ADD 允许发布到尚无已发布文档的全新逻辑目录，目录浏览树按已发布文档自然生长。

#### Scenario: 发布正文修改
- **WHEN** MODIFY 的审核正文有效且正式修订等于固定基线
- **THEN** 原 document_id 的正文和正式修订被更新，原标题、目录、标签与引用身份不变

#### Scenario: 新增文档标题冲突
- **WHEN** ADD 的最终目录与标题在项目正式知识中已经存在
- **THEN** 整个任务发布失败且不创建新文档

#### Scenario: ADD 发布到全新目录
- **WHEN** ADD 的目录格式合法但该目录下尚无任何已发布文档
- **THEN** 系统创建新正式文档并发布，目录树随后显示该新目录

#### Scenario: Agent 尝试修改元数据
- **WHEN** MODIFY 工作草稿请求改变标题、目录或标签
- **THEN** 工作区 Tool 在正式发布前拒绝该变更，既有元数据保持不变

### Requirement: 发布后的索引更新必须与业务事务可靠衔接
知识任务发布事务 SHALL 只创建一个持久化知识索引任务，并 SHALL 在业务事务提交后异步执行。索引任务失败 MUST NOT 回滚已提交的正式文档或任务状态；系统 SHALL 暴露索引中、成功或失败状态并允许现有后台任务机制重试。

#### Scenario: 发布提交后索引成功
- **WHEN** 多文档发布事务提交且索引任务正常完成
- **THEN** 所有新正式修订进入同一个新的活动索引数据集，页面显示索引已更新

#### Scenario: 发布提交后索引失败
- **WHEN** 正式发布已经提交但异步索引任务失败
- **THEN** 正式文档与任务保持 PUBLISHED，页面显示索引更新失败，上一活动索引继续可用且后台可以重试

### Requirement: MCP 工具的项目范围可由部署配置锁定
MCP 服务 SHALL 接受可选请求头 `X-LoreDock-Project` 声明部署锁定的项目标识。配置后，该 MCP server 的所有知识工具 MUST 只检索该项目的已发布知识与草稿池；工具未传 `project` 参数时 SHALL 使用锁定项目，显式传入其他项目 MUST 被拒绝且不返回任何数据。未配置时，工具的项目参数 MUST 保持必填。

#### Scenario: 配置项目锁后省略项目参数
- **WHEN** 请求头配置项目锁且工具调用未传 `project` 参数
- **THEN** 工具使用锁定项目执行检索并返回结果

#### Scenario: 配置项目锁后传入其他项目
- **WHEN** 请求头配置项目锁且工具调用显式传入其他项目标识
- **THEN** 工具调用返回错误且不返回任何项目数据

#### Scenario: 未配置项目锁且省略项目参数
- **WHEN** 未配置项目锁且工具调用未传 `project` 参数
- **THEN** 工具调用返回错误提示项目参数必填
