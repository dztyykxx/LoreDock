# project-qa-agent Specification

## Purpose

定义 `project_qa` 单 Agent 如何在已授权项目与分支中受控检索人工知识和活动代码快照、生成可校验引用，并在缺少证据、范围不符或版本冲突时给出可信拒答。

## Requirements

### Requirement: 项目问答运行必须绑定已启用项目和确定分支
系统 SHALL 接受已认证 `ADMIN` 或 `MEMBER` 发起的 `project_qa` 应用请求，请求 MUST 包含去除首尾空白后 1～2000 个 Unicode 字符的问题、项目标识和启动幂等键，分支 MAY 省略并由服务端解析为项目 `main`。系统 MUST 在调用模型前确认项目已启用、分支存在，并把解析后的项目、分支和当时的活动代码快照元数据固定到运行；调用方与模型不得指定服务器索引位置、历史 generation 或使用其他分支 commit。

#### Scenario: 在指定项目分支启动问答
- **WHEN** 已登录用户为已启用项目和存在分支提交合法问题
- **THEN** 系统创建只绑定该项目、分支及其活动快照元数据的 `project_qa` 运行

#### Scenario: 省略分支
- **WHEN** 已登录用户为已启用项目提交问题但省略分支
- **THEN** 系统使用该项目 `main` 分支完成整次运行，并在运行快照、来源和结果中明确实际分支

#### Scenario: 输入或范围无效
- **WHEN** 问题为空或超过上限、项目不存在或停用、或指定分支不存在
- **THEN** 系统分别返回 `INVALID_REQUEST`、`PROJECT_NOT_FOUND` 或 `BRANCH_NOT_FOUND`，不创建会调用模型的运行且不回退到其他范围

#### Scenario: 匿名调用项目问答
- **WHEN** 未认证调用方尝试启动或读取项目问答运行
- **THEN** 系统拒绝访问且不暴露项目、分支、Skill、模型、commit 或来源是否存在

### Requirement: project_qa 必须只使用受控证据工具回答项目事实
`project_qa` SHALL 只能通过知识混合搜索、代码搜索和代码片段读取工具获取项目事实，并 SHALL 复用这些能力既有的发布状态、通用/项目/分支知识范围、活动快照、有限返回和错误契约。系统 SHALL 为每条工具结果分配仅在当前运行有效的稳定证据 ID，并保留知识文档 ID 或代码快照/路径/commit 等来源元数据；工具正文 MUST 在进入模型上下文前受长度和总量限制。

回答当前快照实现时，Agent SHALL 以当前分支活动代码证据为实现事实；回答业务原因、设计规则或历史约束时，Agent SHALL 以当前允许范围内的已发布人工知识为依据。模型常识、其他对话、其他运行和未通过工具取得的内容 MUST NOT 作为 LoreDock 项目事实证据。

#### Scenario: 基于人工知识回答业务原因
- **WHEN** 问题询问业务规则或设计原因，且允许范围内的已发布知识达到证据阈值
- **THEN** Agent 使用对应知识证据形成结果，并保留文档 ID、范围、标题、公开来源和更新时间

#### Scenario: 基于活动快照回答当前实现
- **WHEN** 问题询问当前分支如何实现，且该分支有活动代码快照和相关代码证据
- **THEN** Agent 只使用该活动快照的搜索和有限片段，结果保留项目、分支、commit、索引时间和仓库相对路径

#### Scenario: 其他分支存在更相关内容
- **WHEN** 同项目其他分支或其他项目存在更高相关的知识或代码
- **THEN** 候选生成、补充读取、证据台账和最终结果均不包含越界来源

#### Scenario: 工具没有命中
- **WHEN** 当前允许范围内的知识与活动代码工具都没有返回达到阈值的证据
- **THEN** Agent 不扩大到其他范围、不使用模型常识补写项目事实，并进入拒答结果

### Requirement: 回答必须携带可由服务端校验的引用
`project_qa` 的结构化结果 SHALL 包含结果类型、回答正文或拒答说明、引用的当前运行证据 ID 和使用的来源摘要。`ANSWER` MUST 至少引用一个由本次运行工具实际返回且仍属于固定范围的证据；每个引用 MUST 能解析为知识文档来源或代码来源。服务端 MUST 在完成运行前验证引用存在、来源类型与元数据完整、未被模型篡改且未跨范围；验证失败时不得发布回答文本。

#### Scenario: 生成知识引用回答
- **WHEN** 模型输出引用本次运行返回的有效知识证据 ID
- **THEN** 系统完成 `ANSWER`，引用可解析到文档 ID、范围、标题、公开来源和更新时间

#### Scenario: 生成代码引用回答
- **WHEN** 模型输出引用本次运行返回的有效代码证据 ID
- **THEN** 系统完成 `ANSWER`，引用可解析到项目、分支、活动 commit、索引时间和仓库相对路径，且不包含服务器路径

#### Scenario: 模型伪造或遗漏引用
- **WHEN** 模型给出项目事实回答但没有引用，或引用了工具未返回、已裁剪移除、另一运行或另一范围的证据 ID
- **THEN** 服务端拒绝该回答并转换为 `REFUSAL`，记录 `AGENT_CITATION_INVALID` 摘要而不暴露越权来源

### Requirement: 证据不足、无快照和无法解释的冲突必须拒答
系统 SHALL 使用服务端版本化的最低证据阈值和可信回答规则验证 `project_qa` 结果。没有相关证据、只有低相关证据、问题超出当前项目与通用知识范围、要求确认实现但当前分支没有活动代码快照、或人工知识与活动代码存在无法解释的冲突时，结果 MUST 为 `REFUSAL`。拒答 SHALL 明确说明“当前知识库没有足够依据”，包含稳定原因码、少量仍在当前范围内的可能相关来源，并在涉及实现时提供当前分支和可用的快照状态；不得用通用模型知识补齐结论。

当当前问题所需的允许证据类别已经完成必要检索，且没有达到阈值的证据或没有可查询的活动代码快照时，系统 MUST 在运行资源上限内确定性完成 `REFUSAL`，不得继续执行等价或不能产生新证据的检索并最终以步骤上限、模型调用上限或超时替代拒答。该规则不得把模型连接失败、工具故障、权限变化、版本变化或真实资源耗尽转换为证据不足；这些运行故障仍 SHALL 保留对应失败或终止事实。

#### Scenario: 当前分支没有快照但询问具体实现
- **WHEN** 用户要求确认当前实现，而目标分支没有活动代码快照
- **THEN** Agent 在不调用不可用代码工具的情况下完成 `REFUSAL`，返回 `CODE_SNAPSHOT_NOT_INDEXED` 原因并明确实际分支，可附带相关人工知识但不得把它冒充当前代码事实

#### Scenario: 只有低相关来源
- **WHEN** 工具只返回低于固定证据阈值的候选，且当前问题所需的允许证据类别已完成必要检索
- **THEN** Agent 返回 `REFUSAL` 与 `INSUFFICIENT_EVIDENCE`，最多展示配置上限内的当前范围候选，不生成项目事实结论

#### Scenario: 必要检索没有命中
- **WHEN** 当前允许范围内的必要知识检索没有返回合格证据，且当前问题不存在可产生新证据的其他允许来源
- **THEN** Agent 完成 `REFUSAL` 与 `INSUFFICIENT_EVIDENCE`，公开拒答正文和终态事件，不因重复等价检索进入 `AGENT_STEP_LIMIT_EXCEEDED`

#### Scenario: 问题超出项目范围
- **WHEN** 用户询问当前项目和通用业务知识以外的事实
- **THEN** Agent 返回 `REFUSAL` 与 `OUT_OF_SCOPE`，不访问其他项目或外部网络

#### Scenario: 人工知识与代码证据冲突
- **WHEN** 当前允许范围的人工知识与活动代码证据对同一事实给出无法同时成立的结论
- **THEN** Agent 返回带 `SOURCE_CONFLICT` 原因的 `REFUSAL`，必须同时引用两类来源并标明分支、commit 与更新时间，不静默选择其中一方

#### Scenario: 检索基础设施发生故障
- **WHEN** 必要工具因权限变化、证据版本变化或检索基础设施异常而未能完成
- **THEN** 系统保留对应失败或终止错误，不把“检索失败”错误宣称为“当前范围没有证据”

### Requirement: 问答输出必须可供后续 Web 流式接入
`project_qa` SHALL 通过统一运行事件输出检索阶段、有限工具摘要、来源发现、回答文本增量、拒答和终态。文本增量 MUST 按事件序号拼接为最终回答或拒答正文；运行终态中的结果、引用和原因码 MUST 与持久化运行快照一致。T6A 不要求提供浏览器 SSE、对话历史或页面接口，但后续入口不得通过重新执行模型来恢复已产生的事件。

#### Scenario: 流式形成回答
- **WHEN** 模型在限制内分段产生一个带有效引用的回答
- **THEN** 调用方可按事件序号观察阶段和文本增量，拼接正文与最终运行快照中的 `ANSWER` 一致

#### Scenario: 流式过程中安全终止
- **WHEN** 运行在输出部分文本后发生超时、越权工具调用、模型失败或引用校验失败
- **THEN** 后续事件明确终止原因，部分文本不得被标记为已完成可信回答，最终快照为 `FAILED`、`TERMINATED` 或带原因的 `REFUSAL`

#### Scenario: 下游重新连接读取运行
- **WHEN** 后续 Web 入口在连接中断后读取运行快照和未消费事件
- **THEN** 它能从持久化状态继续展示，不需要重放用户请求、重新执行工具或再次调用模型
