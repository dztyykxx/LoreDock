# LoreDock 部署指南（单机云服务器 + Docker Compose）

把本机运行的前后端 Docker 化，连同本地数据库数据、对象存储与 embedding 模型迁移到一台云服务器。

> **已按你的服务器做过巡检（49.233.186.235，Ubuntu 24.04，Docker 29.4.2）：**
> 80/443 已被 **1Panel openresty**（host 网络）占用（托管 halo 博客 + parcel-station），8081 也被 parcel 前端占用，
> 内存仅 3.6G（空闲约 1.2G），服务器无 registry 登录。因此本部署采用：
> **LOREDOCK_TLS_MODE=external（本 nginx 走独立高位端口 8082，TLS/域名/证书交给 1Panel 反代，不动任何现有服务）**，
> JVM 限堆 -Xmx768m，镜像用 docker save/load 传输（服务器无需登录任何仓库）。

## 0. 前置条件

- 一台可 ssh 的云服务器（Linux，装了 Docker + Compose v2），建议 2C4G 以上（embedding 模型冷初始化约需 512MiB+）。
- 一个已备案域名，DNS A 记录指向服务器公网 IP（HTTPS/cookie 必需）。
- 服务器安全组/防火墙只开放所需端口（80/443 已被博客占用时，放行新高位端口；SSH 保持最小来源范围）。
- 本机 Docker Desktop 可构建（`docker buildx` v0.35+ 已确认可用）。

## 0.5 两种 TLS 模式

| 模式 | 适用 | 说明 |
| --- | --- | --- |
| `internal`（默认） | 80/443 空闲的服务器 | 本 nginx 终结 TLS + certbot 签发/续期 Let's Encrypt |
| `external` | 80/443 被宿主机/面板反代占用（如 1Panel） | 本 nginx 只开一个高位 HTTP 端口，域名/HTTPS/证书由上游反代终结 |

在 `.env.production` 设置 `LOREDOCK_TLS_MODE`。external 模式下：
- `LOREDOCK_WEB_HTTP_PORT=8082`（任意空闲高位）；
- 在 1Panel 里新增「网站 → 反向代理」：域名填 `loredock.dztyykxx.cn` 这类子域名、转发目标 `http://127.0.0.1:8082`，证书（HTTPS）由 1Panel 自动签发；域名 DNS 增加对应 A 记录。**完全不影响现有站点。**

## 1. 本机：准备生产配置

```bash
cd LoreDock
cp deploy/.env.production.example deploy/.env.production
chmod 600 deploy/.env.production
# 编辑 .env.production，至少改这些：
#   SSL_DOMAIN=你的域名          ACME_EMAIL=你的邮箱
#   POSTGRES_PASSWORD / LOREDOCK_DB_PASSWORD 换成强密码
#   LOREDOCK_ADMIN_PASSWORD_HASH  可从本地 .env 复制，或 htpasswd -bnBC 12 "" '新密码' | tr -d ':\n'
#   LOREDOCK_MCP_READ_TOKEN / WRITE_TOKEN  可从本地 .env 复制，或 openssl rand -hex 32
#   LOREDOCK_KNOWLEDGE_EMBEDDING_MODEL_SHA256  从本地 .env 原样复制
```

> `.env.production` 不入 git（已在 .gitignore）。不要在日志/文档里泄露其中任何值。
> agent 默认关闭；启用前先注入 `LOREDOCK_AGENT_MODEL_API_KEY`。

## 2. 本机：导出数据 + 构建镜像

```bash
# a) 导出本地数据（PG dump + objects + 模型目录 + SHA 校验）
bash deploy/base/backup-data.sh

# b) 构建 amd64 镜像（开发机是 arm64，必须交叉构建；服务器可直接跑）
bash deploy/base/build-and-push.sh
#    默认 docker save 到 deploy/base/images/loredock-images.tar；
#    若 .env.production 里把镜像标签设为 registry 地址，设 LOREDOCK_PUSH=1 改为 docker push。
```

## 3. 上传并部署

```bash
# 一次性上传全部（部署件 + 备份 + 镜像）并在服务器上执行 deploy.sh
bash deploy/base/upload.sh user@服务器IP
# 非 22 端口：RSH="ssh -p 端口" bash deploy/base/upload.sh user@IP
```

`deploy/on-server/deploy.sh` 会自动完成：
加载/拉取镜像 → 起 database → 等 healthy → `pg_restore --clean --if-exists` 恢复 dump
→ 同步对象存储与模型 → 全量 up（internal 模式含 certbot 首次签发）→ 冒烟检查。
external 模式下 deploy.sh 自动跳过 certbot、并直接验证宿主高位端口链路。

## 4. 证书（仅 internal 模式需要）

`deploy.sh` 在 internal 模式已顺带启用 certbot profile。若想先验证（推荐，避免触发正式限流）：

```bash
ssh user@IP "cd ~/loredock-deploy && \
  docker compose --env-file .env.production -f compose.yaml run --rm certbot \
  certbot certonly --webroot -w /var/www/certbot --staging \
  --email 你的邮箱 -d 你的域名"
# staging 通过后再让正式签发生效：
ssh user@IP "cd ~/loredock-deploy && docker compose --env-file .env.production --profile certbot -f compose.yaml restart certbot"
```

证书会落在 named volume `loredock-prod_certbot-etc`；nginx 入口每 6 小时 reload 一次轮换新证书。
**external 模式不需要 certbot**：域名/HTTPS/证书由 1Panel 反代站点签发管理。

## 5. 冒烟验证

```bash
# —— external 模式（本机已配 LOREDOCK_WEB_HTTP_PORT=8082）：先在服务器上直连验证链路 ——
ssh user@IP "curl -sS http://127.0.0.1:8082/api/v1/system/status"
# 在 1Panel 反代站点配置好子域名后（或 internal 模式），用域名验证：
DOMAIN=你的域名或子域名
# 系统状态（可公开）
curl https://$DOMAIN/api/v1/system/status
# 登录拿 cookie（用你配置的管理员账号明文密码）
curl -c /tmp/ld.jar -X POST https://$DOMAIN/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"管理员用户名","password":"明文密码"}'
# 已登录查询项目
curl -b /tmp/ld.jar https://$DOMAIN/api/projects
# MCP Streamable 握手（read token 与 .env.production 一致）
curl https://$DOMAIN/mcp -H "Authorization: Bearer $LOREDOCK_MCP_READ_TOKEN" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'
```

接口按文档 `/api/v1/system/status` 等核对实际字段；SSE 问答另在 Web 页面验证。

## 6. 回滚与日常维护

- 回滚到旧镜像：改 `.env.production` 镜像标签 → 重新执行第 3 步。
- 备份（服务器）：`docker compose --env-file .env.production -f compose.yaml exec -T database sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > loredock.dump`；
  data/objects 与 models 目录同步备份（同一静默写入窗口）。
- 日志：`docker compose --env-file .env.production -f compose.yaml logs -f backend`。
- 升级：本机重新 `backup-data.sh`（可选）→ `build-and-push.sh` → `upload.sh`。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 上传 >1MB 报 413 | nginx `client_max_body_size` 已放开为 110m；检查是否走到了非 /api 路径 |
| SSE 问答卡住/断流 | 确认 nginx `/api/` 与 `/mcp` location 的 `proxy_buffering off` 未被改为默认 |
| 登录后 cookie 不生效 | 必须走 HTTPS 同源；`application-prod.yml` 强制 cookie secure=true |
| backend readiness FAIL | 先看 `logs backend`：Flyway 校验失败多因 dump 与代码版本不一致，或模型 SHA 不符 |
| 证书一直走到占位自签 | 检查 80 端口未被占用（nginx 容错已保证 80 在听）、ACME challenge 目录、邮箱可收件 |
| 想本地先演练 | 按「第 8 节」做一键 repo 内演练 |
