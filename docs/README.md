# LoreDock 文档目录

## 当前产品文档

`product/` 保存当前有效的产品背景、范围和需求基线：

- `项目业务上下文知识库_MVP需求文档_v1.0.md`：当前 MVP 需求基线；
- `LoreDock_MVP功能开发计划.md`：完整 MVP 的功能任务、依赖顺序、状态和逐任务完成门禁；
- `项目业务上下文知识库_MVP_选题说明.md`：选题背景和演示闭环说明。

## 调研资料

`research/` 保存技术选型和开源项目调研。这些文档用于辅助决策，不自动成为实现要求：

- `Java技术栈调研与MVP落地建议.md`；
- `开源代码知识库项目调研_v0.1.md`。

## 架构与运维

`architecture/` 保存已实现基础能力的结构、数据模型与运行约定：

- `LoreDock核心业务链路与模块边界.md`：核心业务闭环、模块职责、模块接口和开发优先级；
- `后端第一阶段收口与模块化重构任务.md`：从权威文档、模块契约、OpenSpec、测试到渐进重构的总任务顺序与完成门禁；
- `当前行为基线与测试记录.md`：必须保留的 HTTP 契约、前端依赖、可重复测试基线和待修正集成测试清单；
- `T1工程与基础设施.md`：本地拓扑、模块内 MVC 结构、数据库、对象存储、后台任务、错误/时间/审计和备份限制；
- `T2认证与项目分支管理.md`：认证会话边界与项目分支契约（第 1 节依赖冻结为历史记录）；
- `后端精简重构基线与处置清单.md`：`simplify-backend-mvc-runtime` 的接口与表处置历史记录；
- `项目问答全链路排查指南.md`：Web 项目问答从提交到展示的真实链路与排查方法；
- `MCP配置与使用说明.md`：MCP 端点、读写 Token 与 Claude Code 接入配置。

已归档到 `archive/architecture/` 的 T4（代码快照与 Lucene）、T5（知识混合检索）、T6A（单 Agent 兼容性）等文档仍描述重构前的 DDD 分层、V4/V5 迁移、UUID 标识和已删除类，仅用于追溯，不作为当前实现依据。

`quality/` 保存可重复执行的质量门禁报告；T5 检索报告由公开模拟 fixture、真实 PostgreSQL、真实离线模型和生产应用端口生成。

## UI 设计稿

`UI/` 保存 LoreDock MVP 的 Pencil 设计源稿、设计说明和总览预览：

- `UI/README.md`：画布范围、视觉规范和实现约束；
- `UI/LoreDock-MVP-UI.pen`：Pencil 可编辑源稿，只能通过 Pencil 或 Pencil MCP 工具访问；
- `UI/LoreDock-design-overview.png`：核心页面总览预览。

## 历史归档

`archive/` 保存已被新版本替代的历史文档，仅用于追溯。除非当前 OpenSpec 明确引用，否则不得把归档内容作为当前实现依据。

## 规格与变更

正式、可验收的功能规格和变更工件保存在仓库根目录的 `openspec/` 中。开发过程遵循 `AGENTS.md` 规定的 SDD + TDD 工作流。
