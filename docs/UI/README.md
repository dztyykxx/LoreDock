# LoreDock MVP UI 设计稿

> 当前实现范围（2026-08-01）：分支新增、选择、分支级知识维护和代码快照上传页面均不对前端开放；项目知识、问答等 Web 流程不携带分支参数，由后端使用默认 `main`。下文及 `.pen` 中仍出现的分支/代码快照画面仅作为历史设计参考，不是当前 MVP 实现依据。

本目录保存 LoreDock MVP 的 UI 设计基线。设计稿使用 Pencil 创建，视觉方向参考 ChatGPT 的克制布局、对话优先与低干扰界面，同时以 LoreDock 的“可引用、可信、范围隔离”建立独立产品识别。

## 文件说明

- `LoreDock-MVP-UI.pen`：Pencil 可编辑源稿。`.pen` 为 Pencil 加密格式，只能通过 Pencil 或 Pencil MCP 工具访问，不得使用普通文本读取、搜索或改写工具处理。
- `LoreDock-design-overview.png`：全部核心画布的总览预览，用于快速评审与定位页面。
- `clipboard`：Pencil 在将源稿放入仓库时生成的伴随文件，应与源稿一并保留，不作为产品需求或实现事实来源。

## 画布范围

1. `00 · LoreDock UI Kit`：颜色、字体、基础控件和可信回答状态。
2. `00A · LoreDock 可复用组件库`：按钮、字段、徽标、提示、卡片、页面标题和项目页面骨架；用于约束 Vue 组件边界。
3. `01 · 登录`：管理员与组内只读账号的统一登录入口。
4. `02 · 项目列表`：项目选择与通用业务知识入口。
5. `03 · 项目详情 / 知识管理`：当前项目页签收敛为知识文档、项目问答、草稿和项目设置；草稿统一承接材料上传、待处理输入、AI 合并整理与人工审核入口。
6. `04 · 项目问答 / 引用展开`：项目锁定、多轮会话、可折叠处理过程、冲突提示、引用面板和知识缺口反馈。
7. `05 · 新建 / 编辑知识`：Markdown 编辑、适用范围、来源和标签配置，以及 Agent 生成内容的审核提示。
8. `06 · 代码快照 / 上传与索引`：历史设计参考；当前 MVP 不开放该页面。
9. `07 · 变更知识 / 材料导入`：历史设计参考；其材料上传能力已合并到统一草稿流程，不再作为独立页面。
10. `07A · 知识任务会话`：系统/人工触发消息、真实 Agent/Tool 过程、安全暂停与恢复、受控草稿、修订列表和服务端 Markdown Diff。
11. `08 · 草稿审核 / 发布`：历史设计参考；当前由统一草稿入口启动任务，并在知识任务会话内审核修订和发布。
12. `09 · 知识体检 / 整理报告`：历史设计参考；重复、冲突、过期和缺口作为知识任务中的结构化发现项展示，不再作为独立页面。
13. `10 · 项目设置 / 分支管理`：历史分支管理设计参考；当前 MVP 的项目设置不开放分支维护。

## 已确认的问答增量设计范围

`04 · 项目问答` 的 T7A 增量已于 2026-08-01 同步到 Pencil 源稿：主区保持回答优先，右侧活动层级在页内收敛为默认折叠的纵向“处理过程”时间线。该增量不改变现有问答的项目锁定、引用和拒答规则，下列结构、状态和脱敏规则同时约束 `.pen` 与 Vue 实现。

1. 对话按会话组织：左侧展示最近会话，主区域连续展示同一会话的问题和最终回答；每轮仍是独立运行，不把生成中的半成品带入下一轮。
2. 回答区增加默认折叠的“处理过程”，运行中实时追加 Agent、模型、Tool、检索、证据/引用校验和最终结果事件。
3. RAG 结果显示命中文档标题、数量、范围、更新时间和引用关系；标题过长时单行截断，悬停可查看完整名称。
4. Tool 卡片显示名称、用途、脱敏参数摘要、结果摘要、耗时和状态；不显示完整系统提示词、隐藏消息、全量证据正文和模型原始思维链。
5. 模型面向用户生成的“继续检索原因”“拒答原因”等内容必须标注为公开决策摘要，不能冒充或复现内部思维链。
6. 页面首次通过 REST 获取会话和运行快照，再通过 SSE 增量更新；刷新或断线后重新获取快照。当前不提供生成中断续跑、详细过程恢复或长期记忆。

## 已确认的多 Agent 增量设计范围

多 Agent 文档整理已经确认为 LoreDock 核心能力。以下增量页面和状态已于 2026-08-01 同步到 Pencil 源稿、项目页签和 `LoreDock-design-overview.png`；现有画布中仍属于当前 MVP 的知识、问答、草稿审核和治理能力不得因新增 Agent 页面被删除或裁剪，分支与代码快照仍按本文件顶部说明仅作历史参考。

1. `07A · 知识任务会话`：采用以对话为主、产物为辅的双栏布局。左侧连续展示系统触发、用户指导、协调 Agent、实际调用的子 Agent、Tool 和公开决策摘要；右侧展示当前草稿、修订列表、来源和服务端 Markdown Diff。
2. 项目详情中的“知识任务”入口：按项目展示手动/定时触发的会话及其活动运行、请求暂停、等待人工、可恢复、恢复中、失败、取消和完成状态；“可恢复/恢复中”只用于配置持久化 Checkpoint 的知识长任务。
3. 动态子 Agent 卡片：仅为本次实际调用的预定义子 Agent 创建卡片，展示任务、状态、产物摘要、来源、错误和待核实项，不预设固定并行角色或不可靠的精确百分比。
4. Tool 与产物时间线：按真实调用顺序展示检索、读取、证据核验、冲突整理、`draft_read`、`draft_update` 和修订生成；每次草稿更新链接到对应 Diff，不在 UI 中伪造固定阶段或把 Agent 最终全文当成已保存草稿。
5. 暂停与人工处理：运行中提供“请求暂停”，点击后显示“将在当前步骤完成后暂停”；进入等待后才能提交指导并恢复。在证据不足或审查阻断时提供允许保留待核实项、要求重写、恢复、重试和取消。恢复入口显示最近 Checkpoint 时间和下一节点，不承诺恢复模型流或 Tool 内部进度。
6. 定义信息只读摘要：展示运行加载的 Skill、Agent Spec、模型和工具集合摘要。本地文件由部署或运维编辑，新运行重新加载；当前不建设 Web Skill 编辑、发布、版本市场或可视化 Graph 编排器。
7. 完成后继续对话：一次 Agent run 完成不关闭任务会话；输入框继续可用，管理员追加修改意见后创建新运行，并在当前草稿修订上产生后续 Diff。
8. Diff 审批：默认比较正式文档/空基线与当前草稿修订，也可切换任意两个修订；MVP 以整份当前修订为审核发布单位，不建设逐 hunk 合并器。需要局部修改时通过继续对话或人工编辑形成新修订。

多 Agent 前端采用对话形式但不设计多个拟人机器人群聊；每条消息明确标识系统触发、用户、协调 Agent、子 Agent 或 Tool。默认只展示阶段、工具与来源摘要、结构化结论、草稿变更、审查问题、Token、耗时和错误，禁止展示模型原始思维链。对话正文不是草稿事实来源，右侧受版本控制的草稿修订与 Diff 才是待审核产物。页面首次通过 REST 获取服务端会话、运行和草稿快照，再使用 SSE 增量更新；浏览器刷新或连接中断后重新获取快照，不把前端内存作为任务事实来源。

## 视觉规范摘要

- 字体：Geist；代码路径、分支和 commit 信息使用 Geist Mono。
- 主色：`#15836D`；主文本：`#202123`；画布：`#F7F7F8`。
- 组件以细边框、低阴影和中等圆角为主，不使用装饰性渐变。
- 可信回答状态分为“有可靠依据”“来源存在冲突”“当前知识库没有足够依据”。
- Agent 运行状态至少区分“排队中”“运行中”“请求暂停”“等待人工”“可恢复”“恢复中”“部分失败”“失败”“已取消”和“已完成”；短时 QA 在后端重启后明确失败并允许新运行重试，只有持久化 Checkpoint 的知识长任务可以暂停或恢复。
- 页面结构、导航、按钮、表单、状态和提示优先使用 Pencil 可复用组件；图片只用于真实图像内容和评审预览。
- `05`～`10` 画布已经使用组件实例搭建，页面专属业务区域保留为语义明确的组合层，便于对应 Vue 页面组件。

## 实现约束

- UI 设计稿用于确定页面结构、信息层级、状态表达和视觉规范，不替代需求基线或有效 OpenSpec 中的业务行为与接口契约。
- 实现页面前应同时核对 `docs/product/项目业务上下文知识库_MVP需求文档_v1.0.md`、`docs/product/LoreDock_MVP功能开发计划.md` 和当前有效 OpenSpec。
- 如果设计稿与更高优先级规格冲突，应先按 `AGENTS.md` 的事实优先级处理并同步修订设计说明，不得仅按静态画面推断业务规则。
