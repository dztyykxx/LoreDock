# LoreDock MVP UI 设计稿

本目录保存 LoreDock MVP 的 UI 设计基线。设计稿使用 Pencil 创建，视觉方向参考 ChatGPT 的克制布局、对话优先与低干扰界面，同时以 LoreDock 的“可引用、可信、范围隔离”建立独立产品识别。

## 文件说明

- `LoreDock-MVP-UI.pen`：Pencil 可编辑源稿。`.pen` 为 Pencil 加密格式，只能通过 Pencil 或 Pencil MCP 工具访问，不得使用普通文本读取、搜索或改写工具处理。
- `LoreDock-design-overview.png`：全部核心画布的总览预览，用于快速评审与定位页面。
- `clipboard`：Pencil 在将源稿放入仓库时生成的伴随文件，应与源稿一并保留，不作为产品需求或实现事实来源。

## 画布范围

1. `00 · LoreDock UI Kit`：颜色、字体、基础控件和可信回答状态。
2. `00A · LoreDock 可复用组件库`：按钮、字段、徽标、提示、卡片、页面标题和项目页面骨架；用于约束 Vue 组件边界。
3. `01 · 登录`：管理员与组内只读账号的统一登录入口。
4. `02 · 项目列表`：项目选择与通用业务知识入口。
5. `03 · 项目详情 / 知识管理`：文档目录、活动代码快照、待审核草稿和知识体检状态。
6. `04 · 项目问答 / 引用展开`：项目与分支锁定、业务知识与代码事实分层、冲突提示、引用面板和知识缺口反馈。
7. `05 · 新建 / 编辑知识`：Markdown 编辑、适用范围、分支、来源和标签配置，以及 Agent 生成内容的审核提示。
8. `06 · 代码快照 / 上传与索引`：快照 ZIP 上传、项目/分支/commit 绑定、活动快照状态、失败隔离和重新索引。
9. `07 · 变更知识 / 材料导入`：变更知识单元创建、需求与 PR 材料、diff、测试证据和生成草稿流程。
10. `08 · 草稿审核 / 发布`：审核队列、需求到实现映射、待核实项、发布检查和发布锁定状态。
11. `09 · 知识体检 / 整理报告`：过期、重复、冲突和知识缺口四类问题，以及转为待审核修订草稿的入口。
12. `10 · 项目设置 / 分支管理`：项目基本信息、启停状态、分支与活动快照提示、管理员和只读用户权限边界。

## 视觉规范摘要

- 字体：Geist；代码路径、分支和 commit 信息使用 Geist Mono。
- 主色：`#15836D`；主文本：`#202123`；画布：`#F7F7F8`。
- 组件以细边框、低阴影和中等圆角为主，不使用装饰性渐变。
- 可信回答状态分为“有可靠依据”“来源存在冲突”“当前知识库没有足够依据”。
- 页面结构、导航、按钮、表单、状态和提示优先使用 Pencil 可复用组件；图片只用于真实图像内容和评审预览。
- `05`～`10` 画布已经使用组件实例搭建，页面专属业务区域保留为语义明确的组合层，便于对应 Vue 页面组件。

## 实现约束

- UI 设计稿用于确定页面结构、信息层级、状态表达和视觉规范，不替代需求基线或有效 OpenSpec 中的业务行为与接口契约。
- 实现页面前应同时核对 `docs/product/项目业务上下文知识库_MVP需求文档_v1.0.md`、`docs/product/LoreDock_MVP功能开发计划.md` 和当前有效 OpenSpec。
- 如果设计稿与更高优先级规格冲突，应先按 `AGENTS.md` 的事实优先级处理并同步修订设计说明，不得仅按静态画面推断业务规则。
