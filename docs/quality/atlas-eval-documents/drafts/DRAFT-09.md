# 审核拒绝后的修订流程

补充审核拒绝后重新提交的操作流程。

批次被审核拒绝后，上传者会在状态里看到拒绝原因。修订按以下步骤进行：

1. 查看拒绝原因，定位正文中的问题；
2. 在本地修改场景包正文，必要时补充来源信息；
3. 使用新的幂等键重新上传，生成新的导入批次；
4. 新批次重新走校验和审核，通过后正式发布。

原拒绝批次保留在历史记录中，不删除，方便追溯修改过程。修订后的内容与历史版本的关系可以通过来源信息和审计记录对应起来。

为什么用新的幂等键：相同项目和幂等键的重复提交会返回原批次，无法重新进入审核，所以要换新键发起新批次。这条和重复提交处理规则一致。
