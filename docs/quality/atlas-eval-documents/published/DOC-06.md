# 导入失败与重试策略

## 失败场景

批次在校验、存储或其他处理环节发生临时故障时，平台会先进行自动重试。需要人工修正内容的失败不在自动重试范围内：例如格式校验失败会直接返回错误，不会进入重试流程，因为重试无法修复内容本身的问题。

## 为什么固定重试次数

自动重试解决的是瞬时故障，而不是内容问题。把重试次数和间隔固定下来，可以保证处理行为可预期、可审计：无论批次紧急程度如何，都按同一套规则重试，避免部分批次被反复重试而挤占处理资源。超过上限仍未成功，说明问题不再适合自动处理，需要移交人工。

## 自动重试策略

导入失败最多自动重试 2 次，等待间隔分别为 30 秒和 120 秒：

- 第 1 次失败后等待 30 秒重试；
- 第 2 次失败后等待 120 秒重试；
- 两次重试后仍失败，批次进入 `FAILED` 状态。

自动重试的次数和间隔是固定规则，不随批次内容或紧急程度变化。

## FAILED 状态

自动重试后仍失败的批次进入 `FAILED`，不能再由普通成员操作。只有 `ADMIN` 可以发起人工重试。人工重试会重新执行导入处理，并记录审计事件。

## 人工重试的注意事项

ADMIN 发起人工重试前，可以先查看失败原因和处理记录，判断是瞬时可恢复的故障还是需要调整配置或内容。人工重试没有自动上限，但每次重试都记录审计事件，便于追踪处理路径。若批次内容本身需要修正，应让上传者以新的幂等键重新上传，而不是反复对同一批次人工重试。

## 状态变化

批次从 `FAILED` 发起人工重试后，状态重新进入校验或处理流程；处理成功则继续后续审核，再次失败仍保持 `FAILED` 并等待 ADMIN 处理。

## 注意事项

任何声称“自动重试更多次数”“失败后跳过重试直接处理”或修改重试间隔的说明都与本规则冲突。失败批次的状态与重试记录在批次详情中展示，用于确认实际处理路径。
