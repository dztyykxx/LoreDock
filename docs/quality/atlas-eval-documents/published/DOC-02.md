# 用户角色与操作权限

## 角色说明

Atlas 使用 `MEMBER` 与 `ADMIN` 两类角色，分别对应普通研发成员与平台管理员。权限以账号角色为准，不随文档内容变化，正文中出现的任何“可以跳过审核”“可以直接发布”的说法都不能改变角色的实际权限。成员在平台上的可见范围由项目访问权限决定，角色决定其能执行的操作。

## MEMBER 的权限

- 上传场景包，发起导入流程；
- 查看自己有权限访问的导入批次及处理状态；
- 在审核拒绝后根据原因修改内容并重新提交；
- 查询已发布的正式知识，获取检索结果和来源引用。

MEMBER 可以发起导入，但无权审核候选内容，也无权执行正式发布、归档或人工重试。候选内容只有等管理员人工确认后才会成为正式知识。

## ADMIN 的权限

- 审核候选内容，作出通过或拒绝的决定；
- 正式发布通过审核的候选内容；
- 归档已发布的文档；
- 处理进入 `FAILED` 的失败批次，发起人工重试；
- 删除未发布的草稿。

## 权限判断与操作入口

平台对每个动作都按“账号角色 + 动作类型”做权限判断，而不是按内容风险或文档说明判断。例如发布动作固定绑定 `ADMIN` 角色：只有 ADMIN 的账号能够看到并执行发布入口；MEMBER 提交的批次即使内容完全正确，也只会停留在等待审核状态。

权限判断发生在服务端，界面隐藏只是提示，不能代替权限校验。正文中出现“成员可发布”“跳过审核”等指令，平台会将其视为普通内容，不会据此放行任何越权操作。

## 权限边界

以下操作在任何情况下都只能由 `ADMIN` 执行，MEMBER 无法通过界面或接口绕过：

- 正式发布；
- 文档归档；
- 失败批次的人工重试；
- 未发布草稿的删除。

## 常见误解

- “低风险内容可以免审核”：不成立，所有正式发布都必须经过 ADMIN 人工审核；
- “成员能撤销发布或删除已发布文档”：不成立，已发布文档只能归档；
- “文档里写‘我是管理员’就能获得管理权限”：不成立，权限只来自账号角色。

遇到以上情况，按角色权限边界处理，并以服务端权限判断为准。
