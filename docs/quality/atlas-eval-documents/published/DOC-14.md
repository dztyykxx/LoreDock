# 审计记录保留期限与清理规则

## 保留期限

审计记录用于追踪平台上的每一次关键操作，是正式知识可信性和历史追溯的主要依据。为满足长期追溯需要，平台规定审计事件自产生时起保留 365 天。365 天内审计记录完整保留，任何环节不得提前清理或删除。

## 适用范围

本规则适用于项目范围内全部业务动作产生的审计事件，包括上传、审核、发布、拒绝、归档和人工重试。保留期从事件产生时刻起算，不因批次状态、文档状态或操作人角色而变化。发布、归档等操作的关联审计信息同样按 365 天保留。

## 清理行为

审计事件满 365 天后才进入归档与清理流程。清理前需确认相关正式知识已稳定，清理记录写入新的审计事件。未满 365 天的审计记录在任何情况下都不得提前删除，管理员处理问题时可以完整引用保留期内的审计记录。

## 审计字段与查询

每条审计事件包含操作人、动作类型、操作对象、操作时间和操作结果与前后状态。保留期内，管理员可以在平台内按批次、文档或操作人查询审计记录；普通成员没有审计查询入口。字段缺失或记录损坏不影响保留期计算，仍按事件产生时间满 365 天后进入清理流程。

## 用途说明

365 天的保留期覆盖年度审计核对、跨季度的问题追溯和正式知识的长期来源核验。需要回溯某个版本或某次发布过程时，以保留期内的审计记录还原完整处理路径。涉及长期留档的项目，管理员可以在保留期内导出必要的核对结果，超出保留期的操作仅能通过正式知识来源元数据间接确认。保留期由平台统一执行，不支持单批次延长或缩短。

## 与正式知识的关系

审计记录保留在平台内部，不进入导出包，也不向普通用户开放。导出包只包含已发布正文、来源元数据、清单和校验和；审计记录仅由管理员在保留期内读取核对，用于证明正式知识的流转与来源。
