# 场景包上传与导入流程

## 上传入口

研发人员通过 Atlas 的上传入口提交场景包。上传入口只接收 ZIP 格式的压缩包，包内业务正文支持 Markdown 和 UTF-8 纯文本。单个上传包的大小上限为 50 MB，超过限制的包会直接上传失败，不会进入后续校验。

## 上传前检查清单

上传前建议按以下要点检查，减少校验失败和反复上传：

- 包内已包含清单文件和至少一份业务正文；
- 正文使用 Markdown 或 UTF-8 纯文本，编码正确；
- 清单声明的文件都真实存在于包内，路径一致；
- 包体积不超过 50 MB；
- 正文未包含密码、令牌、私钥、内部地址或连接串等敏感内容；
- 清单中的幂等键稳定可复用，能代表本次业务内容。

## 导入步骤

1. 整理内容：把产品配置说明、业务规则、交付说明和必要的来源信息整理为 Markdown 或纯文本正文。
2. 编写清单文件：在包内放置清单文件，声明正文文件、来源信息和幂等键等必要字段。
3. 打包上传：把清单文件和正文一起打成 ZIP 包，通过上传入口提交。
4. 等待校验与审核：平台先做格式校验和内容校验，校验通过后批次进入等待人工审核状态。
5. 审核通过后发布为正式知识，可以参与检索与导出。

## 导入时序

上传完成后，平台依次执行格式校验、内容校验，再进入待审核。校验是自动执行的，过程对上传者透明，批次状态依次为 `UPLOADED`、`VALIDATING`，校验通过后为 `PENDING_REVIEW`。校验阶段的临时故障由平台按重试策略自动重试，不需要上传者干预。

## 成功结果

导入成功意味着批次完成格式与内容校验并进入待审核状态，等待 ADMIN 处理。正式发布之后，正文才会进入普通用户检索范围。发布前，即使是校验通过的正文也仍然处于候选状态，不会出现在检索结果中。

## 失败入口

格式校验或内容校验失败时，上传入口会返回错误类型和可读的失败原因。上传者根据提示修改场景包后可以重新提交；同一业务内容重复上传会被幂等处理，返回原批次而不是创建新批次。

校验和处理阶段的临时失败会由平台按重试策略自动重试；自动重试后仍失败则进入 `FAILED` 状态，等待 ADMIN 人工处理。失败原因与重试状态都会在批次详情中展示，供上传者和管理员确认。
