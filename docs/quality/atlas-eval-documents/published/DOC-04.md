# 场景包格式与内容校验规则

## 校验顺序

导入批次按固定顺序执行校验：先做格式校验，再做内容校验。格式校验不通过时直接失败返回，不进入内容校验，避免对无法解析的包做无意义的扫描。两步都通过后，批次才进入待审核状态。

## 清单文件

每个场景包必须包含一份清单文件。清单声明包内的正文文件、来源信息、幂等键等字段，是平台解析包内容的主要依据。缺少清单文件时，格式校验直接失败，批次不会进入后续流程。清单字段缺失或格式错误属于内容问题，在内容校验阶段处理。

## 正文格式

包内业务正文支持两种格式：Markdown 和 UTF-8 纯文本。清单声明的正文文件必须真实存在于包内；包内不得出现清单未声明、且无法解析为受支持格式的正文文件。格式无法识别的文件会被当作不符合要求处理。

## 必要文件

场景包至少包含一份清单文件和一份业务正文。缺少必要文件、正文格式不受支持或正文文件与清单声明不一致时，格式校验失败。

## 敏感内容检查

内容校验会扫描正文，检查是否包含密码、访问令牌、私钥、内部服务器地址或连接串等敏感数据。命中敏感项的正文会被标记为不可信并拒绝进入候选内容，避免内部信息随正式知识或导出包外泄。敏感内容的判断以内容校验结果为准，不因正文中的解释性说明而放宽。

## 主要错误类型

- 缺少清单文件或正文文件；
- 包大小超过 50 MB；
- 正文格式不是 Markdown 或 UTF-8 纯文本；
- 清单声明与包内文件不一致；
- 命中敏感内容检查；
- 其他内容规则不满足。

## 校验与审核的关系

校验是自动检查，审核是人工判断，两者职责不同。校验只负责发现结构问题和敏感内容，不判断业务内容是否正确、完整、与既有知识是否矛盾。校验通过不等于内容可以发布，候选内容仍需经过 ADMIN 人工审核。校验失败的批次不会进入待审核状态，也不会被发布。错误类型和失败原因会在上传结果中返回，供上传者修正后重新提交。
