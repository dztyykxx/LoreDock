# Atlas 产品概览与核心术语

## 产品定位

Atlas 是研发团队内部使用的场景包交付平台。研发人员把产品配置、业务规则、交付说明和必要的来源信息整理为场景包并上传到平台。平台负责格式校验、内容校验、重复提交控制、人工审核、正式发布、导出交付和失败恢复，保证进入正式知识库的内容真实、完整、可追溯。开发人员通过 LoreDock 查询 Atlas 的业务规则、操作方法和设计原因。

## 核心术语

- 场景包：一次交付的最小单元，使用 ZIP 格式打包。一个场景包至少包含一份清单文件和一份业务正文，正文支持 Markdown 和 UTF-8 纯文本，整个包的大小上限为 50 MB。
- 导入批次：一次上传及其后续校验、审核、发布处理流程的载体。每次上传形成一个批次，批次有明确的状态，状态之间的转换由平台流程驱动。
- 候选内容：完成校验、等待人工审核的正文。候选内容在正式发布前不会进入普通用户检索，也不会进入正式导出包。
- 正式知识：已经由管理员确认并正式发布的正文，普通用户可以通过 LoreDock 检索和引用。
- 发布：把候选内容确认为正式知识的行为。发布必须由管理员人工确认，成员不能直接发布。
- 归档：已发布文档不能再物理删除，只能归档以退出普通检索，同时保留历史记录用于追溯。

## 术语关系

研发人员先制作场景包并上传，平台生成导入批次，批次经过格式与内容校验后成为候选内容，等待管理员审核。审核通过后发布为正式知识，供检索与导出；审核拒绝或处理失败的批次不会产生正式知识。已发布的文档需要下线或调整时走归档流程，而不是删除。整个链路中，上传、审核、发布、拒绝、归档和人工重试都会被记录为审计事件，保证每一条正式知识都能追溯到来源和操作人。

## 平台边界

Atlas 只负责场景包的流转与正式知识的管理。它不替代本地的代码阅读，也不接收真实代码正文；本地 Agent 以用户工作区中的最新代码为实现事实。平台内容遵循数据安全边界，不保存密码、访问令牌、私钥、内部服务器地址或连接串等敏感数据。
