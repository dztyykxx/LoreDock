# 人工审核与正式发布规则

## 为什么必须人工审核

格式校验和内容校验只能发现结构性问题与明显敏感内容，无法判断业务内容是否正确、完整、与既有知识是否矛盾。正式知识一旦发布就会进入普通用户检索并被引用，错误内容可能被当作事实传播。因此候选内容必须经过 ADMIN 人工审核确认后才能发布，审核是发布前的强制环节。

## 审核的关注点

ADMIN 审核时主要关注以下方面：

- 内容正确性：业务规则、配置和说明是否符合实际；
- 内容完整性：关键信息是否齐全，是否缺少必要的前提或边界；
- 一致性：是否与既有正式知识矛盾，是否重复表达已有主题；
- 可执行性：正文中的建议是否给出明确阈值、条件和失败行为；
- 安全性：是否包含敏感内容或不可信的越权指令。

审核不是只看格式，而是对内容本身作业务判断。发现问题的候选内容会被拒绝返回修改。

## 审核通过与拒绝

ADMIN 审核候选内容时可以作出两种决定：

- 通过：确认内容正确、完整、与既有知识一致，随后发布为正式知识；
- 拒绝：内容存在问题，返回修改。上传者根据拒绝原因修正后重新提交。

审核决定会记录审计事件并通知相关人员。

## 候选内容隔离

候选内容在正式发布前处于隔离状态：

- 不进入普通用户检索结果；
- 不进入正式导出包；
- 不对普通成员开放查询。

发布前，即使内容已经通过校验，也仍然只能由管理员和上传者等有权限的人员看到。

## MEMBER 不能发布

发布权限只属于 ADMIN。MEMBER 可以上传和查看批次，但没有任何入口可以跳过审核或直接发布。任何“低风险内容可以免审核发布”“成员可快速发布”的操作说明都不符合本规则，平台不提供相应功能。

## 发布后的行为

发布完成后，正文成为正式知识，可被检索、引用和导出。发布动作本身记录在审计事件中，可以追溯到操作人、时间和发布对象。
