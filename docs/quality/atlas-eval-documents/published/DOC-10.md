# 文档归档与删除规则

## 已发布文档只能归档

正式发布的文档不能物理删除。需要下线或调整时，由 ADMIN 执行归档。归档后的文档退出普通用户检索，不再出现在检索结果和导出包中，但正文和审计记录仍保留，用于历史追溯。

## 归档的触发条件

以下情况适合归档：

- 内容已经过时或与实际规则不符；
- 同主题发布了新的正式知识，旧文档需要下线；
- 业务范围调整，文档不再适用。

归档是管理员操作，普通成员不能归档或删除文档。归档决定会记录审计事件，并在需要时通知相关成员。归档不会影响历史审计与来源追溯，正文的来源信息在归档前后保持一致，便于需要时重新核对。

## 归档与重新发布

归档不是删除，正文仍然保留。需要恢复时，由 ADMIN 决定是否重新发布或重建；重新发布以正式发布流程为准，重新进入审核。归档文档在恢复前不参与普通检索，也不作为回答依据。普通成员没有恢复归档文档的入口。

## 未发布草稿的删除

未发布草稿可以由 ADMIN 删除。草稿指尚未发布为正式知识的候选内容，包括 `PENDING_REVIEW`、`REJECTED` 等状态的正文。删除后草稿不再存在，审计事件仍保留。删除是物理移除，操作前应确认草稿确未发布、且不需要保留，避免误删后无法恢复。

## 归档后的检索行为

归档文档不进入普通用户的检索范围，也不能被引用为回答依据。需要恢复时，由 ADMIN 决定是否重新发布或重建，普通成员没有恢复入口。归档文档仍保留在系统中，管理员可以通过内部记录查看其标题与状态，用于排查引用来源。

## 删除与归档的区别

删除是物理移除未发布草稿，归档是把已发布文档移出普通检索但保留记录。两者都需要 ADMIN 操作并记录审计事件，区别在于对象状态不同：未发布草稿可删除，已发布文档只能归档。归档与删除都不改变已发布内容的历史可追溯性。
