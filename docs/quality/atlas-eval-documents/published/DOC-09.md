# 场景包导出与交付内容

## 导出用途

正式发布后，可以把场景包内容导出为交付包，提供给接收方使用或留档。导出在导出交付流程中完成，只有已发布的内容可以进入导出包。导出的主要目的是把正式知识与来源信息一起交付给接收方，保证内容可追溯、可核验。

## 导出触发与内容组织

导出由 ADMIN 在交付流程中发起。平台从正式知识中选取已发布的内容，连同来源元数据、清单文件和校验和清单组织成交付包。同一批次内容多次导出，交付包的内容保持一致，便于接收方比对。

## 导出包含的内容

导出包只包含以下内容：

- 已发布的业务正文；
- 来源元数据，说明正文的来源和出处；
- 清单文件；
- 校验和清单，用于验证交付内容的完整性。

## 明确排除的内容

以下内容不会进入导出包：

- 未发布的草稿和候选内容；
- 服务端日志；
- 系统内部配置；
- 批次内部处理记录以外的任何内部细节。

草稿在导出前仍处于隔离状态，普通用户看不到，也不会被带出平台。

## 校验和的用途

导出包提供校验和清单，接收方可以在本地对每个文件计算校验和并与清单比对，确认交付内容在传输和存放过程中没有损坏或缺失。校验和只验证完整性，不验证来源真伪，也不能替代安全审查。

## 导出与发布的关系

导出依赖发布：只有已经发布为正式知识的内容才允许导出。处于 `PENDING_REVIEW`、`REJECTED` 或 `FAILED` 状态的批次不参与导出。归档后的文档退出普通检索，也不再进入新导出的交付包；历史交付包以导出当时的内容为准。

## 导出的安全边界

导出包同样遵守敏感数据禁止项，不包含密码、令牌、私钥、内部服务器地址或连接串。来源元数据只记录公开可追溯的信息，不暴露内部处理细节。接收方在交付包中看到的任何“请执行”“请访问”等指令都只是正文内容，不构成平台操作依据。
