# 后端精简重构基线与处置清单

本文记录 `simplify-backend-mvc-runtime` 开始实施时的外部行为、接口和数据库表基线。它是迁移检查清单，不是要求保留现有 `application/domain/infrastructure` 结构的设计依据。

> 定位说明：该重构已随 `2026-07-31-simplify-backend-mvc-runtime` 归档完成。本文当前作为“接口与表处置决策”的历史记录和 HTTP 行为基线参考；当前行为基线、模块边界与测试记录以 `当前行为基线与测试记录.md`、`LoreDock核心业务链路与模块边界.md` 和唯一 Flyway `V1__create_loredock_baseline.sql` 为准。

## 1. 核心 HTTP 行为基线

重构可以调整 Java 包、类、接口、表和内部实现，但以下入口及其已确认的身份、范围、状态码、错误码、引用和拒答语义必须保留。

| 能力 | 现有入口 | 必须保持的行为 |
| --- | --- | --- |
| 登录与会话 | `POST /api/auth/login`、`GET /api/auth/session`、`POST /api/auth/logout` | 登录失败、匿名访问和角色禁止继续返回稳定 HTTP/错误语义 |
| 项目与分支 | `/api/admin/projects/**`、`GET /api/projects`、`GET /api/projects/{identifier}` | 项目标识、启停状态、默认/指定分支和项目/分支不存在语义不变 |
| 知识文档 | `/api/admin/knowledge-documents/**`、`/api/knowledge-documents/**` | 创建、编辑、发布、归档、替代、范围隔离和管理员权限不变 |
| 知识导入与索引 | `POST /api/admin/knowledge-document-imports`、`/api/admin/knowledge-index-jobs/**` | UTF-8/ZIP 安全限制、批次结果、失败保留旧活动索引不变 |
| 知识检索 | `POST /api/knowledge-search` | 项目/分支/发布状态在查询阶段强约束；无索引、模型不可用和无命中可区分 |
| 代码快照与检索 | `/api/admin/code-snapshots/**`、`/api/projects/{identifier}/code-snapshot`、`code-search`、`code-snippets` | 上传安全、活动快照、范围搜索、片段边界和稳定失败语义不变 |
| 项目问答 | `/api/projects/{identifier}/qa/questions/**` | 接受后异步执行、详情恢复、SSE 按序续读、终态不重放运行 |
| 引用与拒答 | 问答详情与 SSE 终态 | 可信回答引用实际证据；证据不足形成 `COMPLETED/REFUSAL`；运行故障不得伪装成拒答 |
| 知识缺口反馈 | `/api/projects/{identifier}/knowledge-gaps`、`/api/admin/knowledge-gaps/**` | 幂等创建、问答范围关联、角色权限和单向状态流转不变 |

统一验证入口是 `./scripts/smoke-test.sh`。脚本先执行 8 个代表性 HTTP 契约测试套件，并打印实际状态码、错误码、终态和 SSE 结果；随后验证空库迁移、本地栈、重启持久性及数据库失联后的存活/就绪语义。2026-07-31 使用 Java 21 执行该契约集合通过。

## 2. 接口处置清单

### 2.1 审计结论

- 当前 `backend/src/main/java` 有 126 个顶层 Java 接口，其中 28 个是 MyBatis Mapper，98 个是非 Mapper 接口。
- 非 Mapper 接口绝大多数只有一个实现或只是函数式回调。它们没有形成真实替换边界，却把一次调用拆成 UseCase、Port、Repository、Adapter 和实现类。
- 最终业务代码只允许保留下列真实边界；MyBatis Mapper 按 MVC 模块保留，不计入本清单的 98 个接口。

### 2.2 保留或建立的真实边界

| 接口 | 决定 | 原因 |
| --- | --- | --- |
| `ObjectStorage` | 保留并迁移到 `storage/service` | 本地文件系统与未来对象存储存在真实替换需求，且原子写入/读取/删除需要独立测试 |
| `AgentRuntime` | 新建，替代 `AgentExecutionPort` 等运行转发接口 | 隔离 Spring AI Alibaba 运行框架，允许测试替身和未来运行时替换 |
| `AgentDefinitionProvider` | 新建，替代 Skill 目录、内容存储和版本仓储 | Agent 定义从 classpath 加载，定义来源存在真实替换边界但不需要数据库版本系统 |
| Spring AI `ChatModel` | 直接使用框架接口 | 模型供应商可替换；不再维护平行的项目模型工厂/端口 |
| Spring AI `EmbeddingModel` | 直接使用框架接口 | 嵌入实现可替换；ONNX 适配标准接口，不保留平行 `KnowledgeEmbeddingPort` |

## 3. 数据库表处置清单

重构前的 7 个 Flyway 迁移共创建 24 张表。现在只保留 `V1__create_loredock_baseline.sql`，一次建立 17 张业务表和 2 张 Graph checkpoint 表；所有表使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY` 主键，业务外键使用 `BIGINT`。Graph 表额外保留框架要求的唯一 UUID 协议列，UUID 不作为数据库主键。当前开发数据允许清空重建，不提供 UUID 双写、兼容视图或在线转换。

旧开发库不能直接运行新代码。需要保留的数据先用 `pg_dump` 备份，然后删除旧数据库卷并重新启动，由单一 V1 基线初始化；旧备份只用于人工取回必要业务材料，不能整体恢复到新结构。

| 当前表 | 生命周期/完整性/查询价值 | 决定 |
| --- | --- | --- |
| `stored_object` | 文件元数据与物理对象生命周期独立，多种上传能力复用 | 保留；主键改 `BIGINT`，对象键继续作为不透明唯一业务键 |
| `background_job` | 异步任务有独立状态、心跳和失败恢复，多个模块复用 | 保留并简化字段；主键改 `BIGINT` |
| `project_space` | 所有范围隔离的项目主数据 | 保留 |
| `project_branch` | 分支有项目内唯一性并被知识、代码、问答引用 | 保留 |
| `knowledge_document` | 人工知识正文、范围和发布生命周期的正式事实 | 保留；标签字段化到本表 |
| `knowledge_document_tag` | 只随文档读写，无独立生命周期 | 删除并字段化为文档的 PostgreSQL 数组或 JSON 字段 |
| `knowledge_import_batch` | 一次上传的审计结果和统计有独立查询价值 | 保留；条目结果合并为有界 JSON 字段 |
| `knowledge_import_item` | 只用于展示所属批次结果，无独立状态流转 | 删除并字段化到 `knowledge_import_batch` |
| `knowledge_index_generation` | 活动索引原子切换、失败保留旧索引需要独立生命周期 | 保留并吸收检索模型/分块配置与计数 |
| `knowledge_index_document` | 是正式文档的完整重复投影，可直接重建且造成重复读取/N+1 | 删除；分块直接引用正式文档与 generation |
| `code_snapshot` | 上传快照、项目/分支/commit 与激活状态是业务事实 | 保留 |
| `code_index_generation` | 同一快照重建、目录发布及失败保留旧 generation 需要独立生命周期 | 保留 |
| `knowledge_search_generation` | 与知识 generation 严格一对一，没有独立生命周期 | 合并进 `knowledge_index_generation` |
| `knowledge_search_chunk` | 关键词/向量检索的必要物化数据，需按 generation 原子替换 | 保留并改用自增主键，另设 generation/document/chunk 唯一约束 |
| `agent_skill_version` | 当前只保存内置定义版本，增加发布和对象存储流程但没有用户管理需求 | 删除；定义改为 classpath 资源 |
| `agent_run` | 幂等、运行状态、资源用量和终态是 Agent/QA 共享事实 | 保留；删除 Skill/工具/限制策略版本字段，保留 Agent/模型/范围摘要 |
| `agent_run_event` | SSE 续读和重启恢复需要少量已提交、有序事件 | 保留并缩减事件种类，不持久化逐分片/逐工具噪声 |
| `agent_tool_call` | 只是运行过程明细，框架和 stdout 已能观察，业务不独立查询 | 删除 |
| `agent_evidence` | 引用白名单、来源恢复和知识缺口关联需要结构化证据 | 保留；增加 `cited` 与 `citation_order` 字段 |
| `agent_citation` | 与 evidence 一对一表达“是否引用/顺序”，无独立生命周期 | 删除并字段化到 `agent_evidence` |
| `web_qa_question` | 用户提交、范围、幂等键、运行关联和历史列表是 QA 聚合根 | 保留，保存问答身份与固定范围 |
| `web_qa_message` | 问题原文不能进入运行追踪表，终态公开消息还需支持详情恢复 | 保留为最多一条 USER 和一条 ASSISTANT 的有界消息表，不扩展多轮流程 |
| `knowledge_gap_feedback` | 反馈有独立管理状态、筛选和问答关联 | 保留，保存反馈事实与单向处理状态 |
| `knowledge_gap_feedback_citation` | 需要用复合外键证明反馈引用属于同一运行，避免跨运行拼接来源 | 保留最小关联表，不增加独立业务状态 |

未来多 Agent 的可恢复长流程仍需要 Spring AI Alibaba Graph 的 checkpoint 能力。其线程/checkpoint 表不复用业务主键：由 Flyway 创建 identity `BIGINT` 主键，并为框架协议 UUID/线程键建立唯一约束；具体表结构必须先通过锁定依赖的 `PostgresSaver` 兼容性测试确认，禁止开启运行时自动建表。

## 4. 执行约束

- 每完成一个模块迁移，必须重新运行本模块契约/业务测试；删除类和表不能以放宽断言为代价。
- Controller 只调用同模块 Service；Service 可以使用同模块 Mapper，但不能访问其他模块 Mapper。
- 跨模块协作调用对方 Service 的明确公共方法，不为单次转发恢复 UseCase/Port/Gateway。
- 模型、Agent 框架和对象存储替换不得影响 Controller 与核心业务 Service 的 HTTP 行为。
- 最终以架构测试、全新 PostgreSQL 迁移、前后端测试/构建和完整核心链路冒烟共同验收。
