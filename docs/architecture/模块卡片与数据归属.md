# 模块卡片与数据归属

本文是 `后端第一阶段收口与模块化重构任务` 阶段三的确认产物：固定每个业务模块的职责、非职责、数据归属、对外能力、依赖方向、处置决定和是否需要 `api` 契约包。所有卡片基于 2026-08-01 实际代码与唯一 Flyway `V1__create_loredock_baseline.sql` 核对。

## 0. 总体规则

- 模块内部使用 `Controller → Service → Mapper → PostgreSQL` 简单 MVC，禁止 `domain/application/infrastructure` 分层与 Repository/Port/Adapter 结构；
- 只有被其他模块调用的模块才创建 `<module>.api` 契约包；`api` 只保存 Service 接口、最小不可变契约类型和少量稳定枚举；
- 跨模块只引用对方 `api`，禁止引用对方 `service`、`mapper`、`model/entity`、内部 DTO 与过程模型；
- 一份核心业务事实只有一个模块拥有；其他模块通过拥有者 `api` 获取，不得直接改表；
- 依赖图必须单向无环。

## 1. project

- 一句话职责：管理项目与后端默认分支主数据，为知识和问答解析稳定启用范围。
- 非职责：不拥有知识正文、代码快照、问答记录或运行事实。
- 拥有的数据：`project_space`（项目主数据）、`project_branch`（现有后端分支数据）。
- 对外能力：后端继续保留创建/启停项目、新增分支、查询详情和范围解析；当前前端不暴露新增或选择分支，Web 请求统一省略分支并解析为默认 `main`。
- 依赖：无业务模块依赖；被 `knowledge`、`code`、`agent`、`qa`、`feedback` 调用。
- 处置：保留现有后端能力和 `ProjectService` 契约，本轮只收口前端；是否物理删除分支表留待核心流程验证后另行决定。
- 是否需要 api：是（`project.api.ProjectService`）。

## 2. knowledge

- 一句话职责：管理知识文档全生命周期（导入、编辑、发布、归档）与索引、混合检索，只返回指定范围内的已发布知识及来源。
- 非职责：不解析问答、不持有代码快照、不决定拒答结论。
- 拥有的数据：`knowledge_document`、`knowledge_import_batch`、`knowledge_index_generation`、`knowledge_search_chunk`。
- 对外能力：文档浏览/管理/发布/归档、批量导入、索引任务、范围强约束混合检索（关键词+向量+RRF，发布状态过滤）。
- 依赖：`project.api`（范围解析）、`job.api`（索引后台任务）、`storage.api`（导入对象）。
- 处置：保留；隐藏 generation、Mapper 与索引内部数据服务，需要 `api` 契约包 `KnowledgeSearchService`（向 Agent/QA 提供有范围检索）。
- 是否需要 api：是（`knowledge.api.KnowledgeSearchService`）。

## 3. code

- 一句话职责：管理代码快照（上传、过滤、索引）并统一提供活动快照、范围代码搜索与片段读取。
- 非职责：不存储仓库历史版本，不做代码语义理解。
- 拥有的数据：`code_snapshot`、`code_index_generation`。
- 对外能力：快照上传/查询/重建、活动快照解析、路径/内容搜索、片段读取（路径与行范围校验）。
- 依赖：`project.api`（范围解析）、`job.api`（构建任务）、`storage.api`（ZIP 对象）。
- 处置：保留；收口活动快照、搜索和片段读取为 `api` 契约包 `CodeQueryService`，停止 Agent 同时依赖多个代码内部 Service（`ActiveCodeSnapshotQueryService`、`CodeSearchService`、`CodeSnippetService`）。
- 是否需要 api：是（`code.api.CodeQueryService`）。

## 4. agent

- 一句话职责：运行 Spring AI Alibaba `ReactAgent`，向 QA 提供运行启动、终态和公开事件，内部继续使用 `AgentRuntime` 隔离框架。
- 非职责：不拥有问答页面契约，不做多 Agent 编排，不做 Skill 版本管理。
- 拥有的数据：`agent_run`（运行快照）、`agent_run_event`（已提交有序事件）、`agent_evidence`（引用证据）；`graphthread`/`graphcheckpoint` 为框架 checkpoint 协议表，由锁定版本 `PostgresSaver` 兼容性测试约束。
- 对外能力：启动一次项目问答运行、查询运行快照与事件、返回可区分的回答/拒答/运行失败。
- 依赖：`project.api`、`knowledge.api`（只通过契约取得已发布文档证据）。
- 处置：保留 `AgentRuntime`（真实替换边界）；删除多余调度、定义、快照和过程模型；需要 `api` 契约包 `AgentService`。
- 是否需要 api：是（`agent.api.AgentService`）。

## 5. qa

- 一句话职责：编排一次 Web 项目问答（创建、历史、详情、SSE 续读、终态），保持已成型 HTTP 契约。
- 非职责：不决定检索算法，不直接运行模型，不拥有知识/代码事实。
- 拥有的数据：`web_qa_question`（问答记录）、`web_qa_message`（最多一条 USER 与一条 ASSISTANT 的有界消息）。
- 对外能力：`POST/GET .../qa/questions`、详情、SSE 事件流、终态 `failureMessage` 与引用。
- 依赖：`agent.api`（运行启动与终态）、`project.api`（范围校验）、`auth.api`（当前操作者）。
- 处置：保留 HTTP 契约；使用 `AgentService` 收口问答创建、历史、详情和 SSE；需要 `api` 契约包 `QaService`（供 Feedback 关联问答）。
- 是否需要 api：是（`qa.api.QaService`）。

## 6. job

- 一句话职责：提供通用后台任务的提交、查询、取消与启动恢复（不自动重放）。
- 非职责：不承载具体业务任务逻辑，不做分布式调度。
- 拥有的数据：`background_job`。
- 对外能力：提交（含 single-flight）、查询、取消、心跳与进度、启动时恢复陈旧 `RUNNING` 为失败。
- 依赖：无业务模块依赖；被 `knowledge`、`code` 调用。
- 处置：保留；合并为 `api` 契约包 `JobService`（提交/查询/取消），`JobHandler`/`JobExecutionContext` 收敛为模块内部类型或随具体任务注册。
- 是否需要 api：是（`job.api.JobService`，仅在 knowledge/code 仍需要通用后台任务时）。

## 7. feedback

- 一句话职责：记录和处理知识缺口反馈（幂等创建、问答关联、单向状态流转）。
- 非职责：不生成知识、不决定拒答。
- 拥有的数据：`knowledge_gap_feedback`、`knowledge_gap_feedback_citation`（证明引用属于同一运行）。
- 对外能力：创建反馈（幂等）、管理员分页/详情/状态流转。
- 依赖：`qa.api`（问答关联）、`project.api`（范围）、`auth.api`（操作者）。
- 处置：保留；暂不需要独立 `api` 契约包（当前无其他业务模块调用 feedback）。
- 是否需要 api：否。

## 8. auth

- 一句话职责：提供固定账户认证、会话与当前操作者身份（Sa-Token + BCrypt），不实现注册与细粒度权限。
- 非职责：不拥有业务事实表（无数据表，账户来自配置）。
- 拥有的数据：无业务表；固定 ADMIN/MEMBER 账户配置。
- 对外能力：登录/登出/会话查询、解析当前操作者。
- 依赖：无业务模块依赖；被 `qa`、`feedback` 调用。
- 处置：保留；虽然“暂无其他业务模块调用时不建空 api”，但 `qa`/`feedback` 已调用其会话能力，需要最小 `api` 契约 `SessionService`/`AuthenticatedActorService` 收口身份解析。
- 是否需要 api：是（`auth.api`，仅身份/会话能力）。

## 9. storage

- 一句话职责：本地对象存储（原子写入、读取、删除），保留未来对象存储的真实替换边界。
- 非职责：不保存业务元数据语义，不做对象生命周期治理。
- 拥有的数据：`stored_object`（对象元数据），物理文件在受控根目录。
- 对外能力：保存/读取/删除对象（UUID 对象键、SHA-256、原子移动、路径穿越防护）。
- 依赖：无业务模块依赖；被 `knowledge`、`code` 调用。
- 处置：保留 `ObjectStorage` 接口（真实替换边界），迁移到 `storage.api` 或保持 `storage.service` 包名下的稳定接口。
- 是否需要 api：是（`ObjectStorage` 已是真实边界接口，纳入 `storage.api`）。

## 10. 依赖图与环检查

当前实际依赖（按模块顶层包 import 统计，2026-08-01）：

```text
project →（无）
storage →（无）
job →（无）
auth →（无）
knowledge → project / job / storage
code → project / job / storage
agent → project / knowledge
qa → project / auth / agent
feedback → project / auth / agent / qa
```

结论：依赖图单向且无环。代码模块已从知识检索和问答主链路断开；无任何模块循环依赖。

## 12. 完成门禁自查

- 每个模块一句话职责与明确非职责：已固定；
- 每张业务表都有唯一拥有模块：已固定；
- 开发者可从 Web 问答入口沿模块依赖读完核心链路：`qa → agent → {knowledge, code} → {project, job, storage}`，无环；
- 跨模块协作只通过 `api`：目标契约已列出，存量直接调用对方 Service 的迁移顺序见阶段六。
