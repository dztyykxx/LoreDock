## 1. 任务定位

本文档是 LoreDock 后端进入新一轮 OpenSpec 和代码重构前的总任务基线。它先固定执行顺序、阶段产物和完成门禁，不直接规定具体 Java 实现。

当前仍处于第一阶段：**先保证用户可以基于指定项目和分支获得带引用的回答，证据不足时明确拒答**。所有文档、规格、测试和重构必须服务这条核心链路。

## 2. 总体约束

- 在模块责任和契约确认前，不开始批量移动类、改表或补单元测试；
- 已成型且不阻碍开发的 HTTP 接口、前端契约和核心能力优先保留；
- 先保护外部可观察行为，不为旧的内部小类和过程模型补测试；
- 模块内部使用 `Controller → Service → Mapper → PostgreSQL` MVC 结构；
- 只有被其他模块调用的模块才创建 `api` 契约包，跨模块代码只能引用对方 `api`；
- `api` 不是 HTTP 层或新业务层，只保存 Service 接口和最小稳定数据契约；
- 不为当前没有入口的版本、历史、发布、恢复、多 Agent 和生产治理能力保留额外类或表；
- 当前使用单 Maven 工程的包级隔离，不拆分 `xxx-api` / `xxx-impl` Maven 子模块；
- 每完成一个模块必须恢复到可编译、代表性测试通过和核心链路可运行状态，不做长时间大爆炸式改造。

## 5. 阶段三：定义模块、数据归属和契约

### 5.1 模块卡片

为 `project`、`knowledge`、`code`、`agent`、`qa`、`job`、`feedback`、`auth`、`storage` 逐一确认：

- [ ] 一句话职责和明确非职责；
- [ ] 拥有的业务事实、Entity 和数据库表；
- [ ] 对外能力、输入、输出和失败语义；
- [ ] 依赖的其他模块及依赖方向；
- [ ] 需要保留、合并、删除和延后的能力；
- [ ] 是否需要 `api` 契约包。

### 5.2 初始候选契约

以下只是待逐项确认的最小候选，不直接作为实现清单：

| 拥有模块 | 候选公开契约 | 当前价值 |
| --- | --- | --- |
| `project` | `ProjectService` | 统一解析启用项目、分支和稳定项目范围 |
| `knowledge` | `KnowledgeSearchService` | 对 Agent/MCP 提供有范围的知识检索，隐藏索引内部实现 |
| `code` | `CodeQueryService` | 统一活动快照、代码搜索和片段读取 |
| `agent` | `AgentService` | 向 QA 提供运行启动、终态和公开事件；内部继续使用 `AgentRuntime` |
| `qa` | `QaService` | 向 Web 和 Feedback 提供问答创建、历史、详情和必要关联事实 |
| `job` | `JobService` | 只在仍保留通用后台任务时提供提交、查询和取消 |
| `storage` | `ObjectStorage` | 保留本地文件与未来对象存储的真实替换边界 |

`feedback`、`auth` 等暂无其他业务模块调用的模块不机械创建空 `api`。

### 5.3 目标依赖方向

```text
QaService → AgentService
AgentService → ProjectService / KnowledgeSearchService / CodeQueryService
KnowledgeSearchService → ProjectService
CodeQueryService → ProjectService
Feedback Service → QaService / ProjectService
Knowledge / Code → JobService / ObjectStorage
```

- [ ] 确认依赖图单向无环；
- [ ] 禁止跨模块引用 Service 实现、Mapper、Entity、内部 DTO、Snapshot、Command 或 Result；
- [ ] 每个 `api` 类型都能说明稳定性价值，删除仅为一次转换创建的契约类；
- [ ] 列出表的保留、合并、删除和延后清单，保证一份核心事实只有一个模块拥有者。

### 5.4 完成门禁

- 每个模块都有经人工确认的模块卡片；
- 开发者可以从 Web 问答入口沿模块依赖读完整条核心链路；
- 表归属、模块契约和依赖图确认前，不进入详细 OpenSpec 和实现。

## 7. 阶段五：先制定测试门禁

### 7.1 外部行为与核心验收

- [ ] 为必须保留的 HTTP 行为建立最小特征测试，防止内部重构改变已成型契约。
- [ ] 建立确定性核心 E2E：真实 PostgreSQL + 可控 Fake `ChatModel`，走通项目、知识、索引、问答、引用和拒答。
- [ ] 建立一条可手工触发的真实模型 Smoke，验证模型、ToolCallback、检索结果和页面终态，不将付费模型纳入每次 CI。
- [ ] 修正或删除仍依赖旧表的 PostgreSQL 集成测试，保证测试与唯一 Flyway 基线一致。

### 7.2 模块契约测试

- [ ] `ProjectService` 能解析有效项目/分支范围并返回最小契约数据。
- [ ] `KnowledgeSearchService` 只返回指定范围内的已发布知识及来源。
- [ ] `CodeQueryService` 只读取指定范围的活动快照、搜索结果和片段。
- [ ] `AgentService` 只通过已确认的模块 `api` 取得证据，并返回可区分的回答、拒答和运行失败。
- [ ] `QaService` 保持问答创建、历史、详情和终态的对外行为。

### 7.3 架构测试

- [ ] 允许模块内 `Controller → Service → Mapper`；
- [ ] 跨模块只允许引用对方 `api`；
- [ ] 禁止跨模块引用对方 `service`、`mapper`、`model/entity`、内部 DTO 和过程模型；
- [ ] 禁止模块循环依赖；
- [ ] 禁止新增 DDD、Repository、Port、Adapter、Facade、Coordinator 等未批准结构；
- [ ] 对发现的存量违规给出明确迁移顺序，不通过扩大白名单让旧架构继续合法化。

### 7.4 完成门禁

- 特征测试只保护确认要保留的行为；
- 新契约和架构测试的初始失败都能对应已知存量问题；
- 没有为了测试旧小类而固化将被删除的实现结构。

## 8. 阶段六：按模块渐进重构

### 8.1 建议顺序

1. `project`：建立范围契约，先停止其他模块依赖项目内部 View/Result。
2. `knowledge`：建立检索契约，隐藏 generation、Mapper 和检索内部数据服务。
3. `code`：收口活动快照、搜索和片段读取，停止 Agent 同时依赖多个代码内部 Service。
4. `agent`：建立面向 QA 的 `AgentService`，保留 `AgentRuntime`，删除多余调度、定义、快照和过程模型。
5. `qa`：使用 `AgentService` 收口问答创建、历史、详情和 SSE，保持已成型 HTTP 契约。
6. `feedback`、`job`、`storage`、`auth`：只处理仍然阻碍核心链路或违反已确认模块边界的部分。
7. 数据库精简：在拥有模块和业务事实确认后，再删除 Graph checkpoint、版本替代链等当前无入口表与字段。

### 8.2 每个模块的固定循环

- [ ] 确认本模块任务的保留行为和非目标；
- [ ] 先定义或确认最小 `api` 契约；
- [ ] 为契约和必须保留行为编写失败测试；
- [ ] 使现有 Service 实现契约，迁移所有跨模块调用方；
- [ ] 合并内部 Command/Result/Snapshot/Converter 和只做单次转发的小类；
- [ ] 删除旧公共入口、白名单和不再有调用方的代码；
- [ ] 运行模块契约、受影响 HTTP、PostgreSQL 和架构测试；
- [ ] 人工审查 diff，确认没有借重构增加新功能或未来扩展点；
- [ ] 使核心代码恢复到可编译和可运行状态后再进入下一模块。

## 9. 阶段七：核心链路验收与归档

### 9.1 必须验收的真实链路

```text
创建项目与分支
→ 导入并发布知识
→ 建立知识索引
→ 可选上传并索引代码快照
→ 提交项目问题
→ Agent 通过模块 api 调用知识/代码检索
→ 返回带来源的回答或明确拒答
→ 问答历史、详情和前端展示一致
```

### 9.2 最终检查

- [ ] 新建数据库可以通过唯一 Flyway 基线启动；
- [ ] 确定性核心 E2E 通过；
- [ ] 真实模型 Smoke 已记录实际问题、工具结果数量、回答/拒答和引用；
- [ ] 问答、检索和范围隔离的代表性 PostgreSQL 集成测试通过；
- [ ] 架构测试证明跨模块依赖只指向对方 `api` 且依赖图无环；
- [ ] 对外 HTTP 和前端契约保持兼容；
- [ ] 已删除半成品、死代码、无入口配置、过期测试和作废文档；
- [ ] OpenSpec 主规格、Change、任务状态和最终实现一致；
- [ ] 同步主规格并归档已完成 Change。

## 10. 明确非目标

本轮任务不包含：

- 多 Agent 知识挖掘流程和动态编排平台；
- MCP 扩展、身份校验和模型摘要；
- 知识、代码或 Agent 定义的历史版本系统；
- 生产级审计、多级恢复、完整可观测平台和穷举容错；
- 新的 HTTP 功能、前端页面或已成型 JSON 字段风格迁移；
- 按微服务、DDD、六边形或多 Maven 子模块重建项目；
- 为了覆盖率或测试数量给无业务逻辑小类补测试。

## 11. 任务完成标志

只有同时满足以下条件，才能宣布“第一阶段收口与后端模块化重构”完成：

1. 用户可以从真实入口完成一次带范围、带引用的项目问答，或获得明确拒答；
2. 项目权威文档、OpenSpec、测试和实现描述同一套当前系统；
3. 核心模块职责、数据归属、`api` 契约和单向依赖已固定；
4. 模块内部符合简单 MVC，跨模块不泄漏 Mapper、Entity、Service 实现和内部过程模型；
5. 不影响核心链路的已成型能力得到保留，半成品和会持续增加开发成本的结构已删除或延后；
6. 可重复的确定性 E2E、真实模型 Smoke、PostgreSQL 集成测试和架构测试共同证明第一阶段真实可运行。
