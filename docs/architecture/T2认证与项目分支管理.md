# T2 认证与项目分支管理

本文记录 T2 实现中的依赖冻结、身份边界、项目与分支模型及验证结果。OpenSpec change `add-auth-project-branch-management` 仍是行为与验收事实来源。

> 定位说明：本文第 1 节依赖冻结与验证结果属于 T2 阶段的历史记录（版本可能已由后续依赖管理调整）；第 2 节 HTTP 契约边界仍有效，详细路径清单见 `当前行为基线与测试记录.md`。

## 2. HTTP 契约边界

- 匿名入口仅包含 `POST /api/auth/login` 与幂等 `POST /api/auth/logout`；`GET /api/auth/session` 和普通 `/api/projects/**` 要求有效 Web 会话，`/api/admin/**` 进一步要求服务端解析的 `ADMIN` 角色。
- `POST /api/admin/projects` 非幂等，但全局唯一项目标识把重试收敛为 `PROJECT_IDENTIFIER_CONFLICT`；项目和默认 `main` 分支必须处于同一事务。
- `PATCH /api/admin/projects/{projectId}/status` 设置目标状态幂等。停用项目仍可从管理入口读取，但普通入口对停用与不存在统一返回 `PROJECT_NOT_FOUND`。
- 普通项目详情未给出 `branch` 时选择 `main`；给出未知分支时返回 `BRANCH_NOT_FOUND`，禁止回退。分支名只在项目内唯一，任何查询和冲突判断都必须携带项目标识（业务 `identifier`）与稳定 Long 主键。
- T2 响应字段不包含知识数量、快照或 commit。未来能力通过新增可选字段或独立资源演进，不改变现有字段含义。
