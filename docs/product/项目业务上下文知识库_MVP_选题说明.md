# 项目业务上下文知识库 MVP——选题说明

| 项目 | 内容 |
|---|---|
| 建设周期 | 20 天 |
| 部署环境 | 公司内网，CPU 环境 |
| 试点项目 | 网络设计工具，Java + Vue 3，约 10 万行代码，维护 5 年以上 |
| 主要使用者 | 组内开发人员、管理员、本地 Claude Code |

## 1. 选题概述

计划建设一个面向组内开发人员的“项目业务上下文知识库”。

系统集中管理项目文档、通用业务知识、公司 Wiki 内容、需求材料、PR 实现信息和轻量代码快照，通过 Web 问答和 MCP 为开发人员及本地 Agent 提供可检索、可引用的业务上下文。

系统还会把后续每次真实需求及其 PR、代码实现和测试记录整理成知识文档，使缺乏文档的存量项目随着日常开发逐步形成可维护的知识体系。

## 2. 背景与问题

组内有几十个代码仓库，每个仓库通常有 20～30 万行代码。部分项目已经维护多年，但缺少系统文档，业务规则、设计原因、兼容约束和历史问题主要依赖口头传递。

目前主要存在以下问题：

- 新成员理解项目需要频繁询问有经验的同事；
- 公司已有 Wiki 检索效果较差，已有内容也难以找到；
- 代码能说明“当前怎么实现”，但通常不能解释“为什么这样设计”；
- 需求文档、PR、测试记录和最终代码彼此割裂，需求完成后没有形成长期文档；
- 本地 Claude Code 可以阅读开发者当前代码，但缺少组内业务背景和历史上下文。

我已在网络设计工具项目中完成“场景包导入导出”需求，打通了相关代码链路并整理了文档。这份真实需求及其 PR 可以作为 MVP 的核心验证样本。

## 3. 核心目标

- 统一管理通用知识、项目知识和分支级知识；
- 改善原 Wiki 内容的搜索与问答体验；
- 提供带来源、可核实、证据不足时能够拒答的 Web 问答；
- 通过 MCP 向成员本地 Claude Code 提供业务上下文；
- 建立“需求—PR—代码实现—知识文档”的持续沉淀闭环；
- 通过真实需求逐步补齐存量项目文档，而不是一次性分析全部历史代码。

## 4. 核心功能

### 4.1 项目与知识管理

- 管理项目、分支、通用知识、项目知识和分支级知识；
- 支持 Markdown/纯文本知识的新建、导入、编辑和浏览；
- 支持草稿、已发布和已归档状态；
- 管理员审核发布后，知识才进入正式检索索引；
- 原公司 Wiki 内容先转换为 Markdown，再手动导入系统。

### 4.2 代码快照与检索

- 上传带项目、分支和 commit 信息的代码快照；
- 对指定分支进行文件路径和代码全文检索；
- Web 问答可以读取有限的相关代码片段；
- 代码不做全量向量化，也不建设完整调用图；
- 用户本地 Agent 最终以本地最新代码作为实现事实。

### 4.3 Web 问答

- 用户选择项目和分支后进行自然语言问答；
- Agent 检索业务知识和相关代码片段后生成回答；
- 回答展示文档来源、代码路径、分支、commit 和更新时间；
- 没有足够证据时明确拒答并记录知识缺口；
- 代码与人工文档冲突时，同时展示冲突和版本信息。

### 4.4 需求到实现的知识沉淀

管理员导入：

- 需求文档；
- PR 标题、编号和地址；
- base/head commit；
- diff/patch 和变更文件列表；
- 测试说明及人工补充材料。

Agent 根据上述材料和对应分支代码快照，生成一篇包含以下内容的知识草稿：

- 需求背景、目标和业务规则；
- 需求条目与代码模块、文件路径的对应关系；
- 关键调用链和数据流；
- 接口、数据结构、配置及兼容性变化；
- 测试证据、实现偏差和未确认事项；
- PR、分支、commit 和原始材料引用。

草稿必须经过管理员审核才能发布和进入检索。

### 4.5 Agent 与 Skill

系统采用统一受控 Agent Runtime。Web 项目问答使用单 Agent；文档生成和需求到实现沉淀使用固定多 Agent Graph，由需求、代码和测试证据角色并行提取依据，文档编写角色生成草稿，独立审查角色检查无引用事实、证据遗漏和版本混淆，必要时等待管理员补充方向。

| Skill | 作用 |
|---|---|
| `project_qa` | 检索项目上下文并生成带引用回答 |
| `document_writer` | 根据指定材料生成知识文档草稿 |
| `change_documenter` | 整理需求、PR、代码实现和测试证据 |

Skill 具有版本、工具白名单、执行步骤、引用要求和拒答条件。Agent 只能读取知识和代码并生成草稿，不能直接发布正式知识。

每个项目可维护版本化 `PROJECT_MEMORY.md`，记录项目术语、模块边界、历史约束和文档提取方向。运行启动后固定 Skill 和项目记忆版本；后端重启后可从 PostgreSQL 检查点手动恢复。MVP 不建设动态 Agent 创建、跨服务 Agent 或可视化工作流编排器。

### 4.6 MCP 接入

系统通过远程 Streamable HTTP 向 Claude Code 提供三个只读工具：

- `knowledge_search`：搜索业务知识；
- `document_read`：读取知识文档；
- `code_search`：搜索指定项目和分支的代码快照。

MCP 返回原始知识、代码片段和引用，由 Claude Code 结合用户本地最新代码完成分析。

## 5. 技术栈

| 层次 | 技术 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite |
| 后端 | Java + Spring Boot |
| 数据库与向量 | PostgreSQL + pgvector |
| 原始文件 | MinIO 或兼容 S3 的对象存储 |
| 代码全文检索 | Apache Lucene |
| 大模型 | DeepSeek `deepseek-v4-flash`（OpenAI 兼容接口） |
| Embedding | CPU 可运行的中文向量模型 |
| MCP | Streamable HTTP |
| 部署 | Docker Compose，公司内网单机部署 |

## 6. MVP 演示闭环

```text
导入项目知识和代码快照
→ 导入场景包需求、PR、diff 和测试材料
→ Agent 生成需求到实现的知识草稿
→ 管理员审核并发布
→ Web 能够进行带引用问答
→ Claude Code 能够通过 MCP 获取同源业务上下文
→ 对无依据问题拒答并记录知识缺口
```

## 7. 范围边界

本次 MVP 不包含：

- 自动连接公司 Wiki、Git 平台和 Welink；
- 一次性接入近百个仓库；
- 全量代码向量化、完整 AST、调用图和跨仓库分析；
- 复杂组织权限和多人审核流程；
- 动态 Agent 创建、分布式 Agent、A2A 和可视化工作流编排器；
- Agent 自动发布或修改正式知识。
