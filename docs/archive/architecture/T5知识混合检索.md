# T5 知识关键词、语义与混合检索

本文记录 MVP 开发计划 T5 已实现的知识搜索架构与运行边界。可验收行为以 OpenSpec 的 `knowledge-hybrid-search` 和 `knowledge-search-benchmark` capability 为准。

## 1. 应用边界与查询流程

`KnowledgeSearchUseCase` 是 Web、后续问答与 MCP 共用的稳定应用端口。Controller 只绑定 HTTP DTO；应用服务依次执行输入规范化、项目/分支解析、固定活动 generation、候选召回、RRF 文档折叠、事实表实时资格复核和结果映射。ONNX、pgvector、MyBatis-Plus 与 HTTP 类型都不进入应用契约。

GLOBAL 只允许通用知识。PROJECT 允许通用、同项目和同项目同分支三层知识，空分支固定为 `main`。范围、标签全包含、格式和来源在关键词与语义候选 SQL 中同时应用，不先跨范围扫描再隐藏。融合后再批量查询当前事实表，删除已归档、改范围或不再发布的文档；这层复核用于处理索引后发生的生命周期变化，不能作为候选 SQL 越界的补救。复核删除后不回填其他候选。

## 2. generation、分块与原子切换

V5 增加一对一的 `knowledge_search_generation` 和以 `(generation_id, document_id, chunk_no)` 为键的 `knowledge_search_chunk`。旧 T3 ACTIVE generation 没有搜索元数据时，知识浏览仍可用，搜索明确返回 `KNOWLEDGE_INDEX_UNAVAILABLE`，直到成功完成一次新重建。

重建分四阶段：短 `REPEATABLE READ` 事务冻结 PUBLISHED 投影；事务外按 `cjk-v1` 确定性分块、文本分析并批量计算 Embedding；短事务分批写入并验证文档数、连续分块、512 维和关键词字段；最后在短事务中退休旧 ACTIVE 并激活新 generation。任一步失败都清理 BUILDING，保留旧 ACTIVE。成功后只保留当前 ACTIVE 与上一个 RETIRED，旧数据清理失败不影响查询。

分块优先使用 Markdown 标题与段落边界，单块最多 400 Unicode code point、相邻块重叠 80 code point，并保存原文 offset。标题、标签和正文经同一个 Lucene CJK 分析器生成 A/B/C 权重 TSVector；合法短查询使用受范围限制的字面回退，不解释客户端查询语法。

## 3. 离线 Embedding

语义检索锁定 `BAAI/bge-small-zh-v1.5` revision `7999e1d3359715c523056ef9478215996d62a620`，模型 MIT License。Java 侧使用 ONNX Runtime 1.28.0（MIT）和 DJL Hugging Face Tokenizers 0.36.0（Apache-2.0），直接读取 ONNX 图的二维 `sentence_embedding`；CLS pooling 与 L2 归一化由导出图完成。适配器只验证输出名、512 维、有限值和单位范数，不自行实现 tokenizer、pooling 或归一化。

模型与 tokenizer 只接受 `file:` 或 `classpath:` URI，且模型 SHA-256 必须为部署配置锁定值。HTTP(S)、缺失资源、摘要不符、输出错误或推理失败统一产生 `KNOWLEDGE_EMBEDDING_UNAVAILABLE`，不会在线下载或静默降级。KEYWORD 不调用模型；SEMANTIC/HYBRID 还要求活动 generation 的模型 ID、摘要与维度完全匹配当前适配器。

## 4. 候选、融合与结果

关键词候选使用参数化 PostgreSQL TSVector 查询，标题/标签高于正文，稳定按原始分数、文档 ID、分块号排序。语义候选在固定 generation 和完整关系过滤后执行精确 pgvector 余弦 `<=>`；MVP 数据量基准未证明需要近似索引，因此不建立 HNSW。

HYBRID 使用版本 `rrf-v1`、固定 `k=60` 的 Reciprocal Rank Fusion。候选数量由服务端根据返回上限集中计算，客户端不能控制 generation、向量、候选上限、融合常数或权重。相同文档的多个分块折叠为一条结果，选择实际最佳证据片段，片段最多 500 Unicode code point；最终相关性规范到 0～1，并以分数、更新时间和 UUID 稳定打破并列。

## 5. 配置与首次上线

| 环境变量 | 默认值 | 约束 |
|---|---|---|
| `LOREDOCK_KNOWLEDGE_EMBEDDING_MODEL_ID` | `BAAI/bge-small-zh-v1.5` | 必须与活动 generation 一致 |
| `LOREDOCK_KNOWLEDGE_EMBEDDING_MODEL_URI` | 空 | 本地 `file:` 或 `classpath:` URI |
| `LOREDOCK_KNOWLEDGE_EMBEDDING_TOKENIZER_URI` | 空 | 本地 `tokenizer.json` URI |
| `LOREDOCK_KNOWLEDGE_EMBEDDING_MODEL_SHA256` | 空 | 64 位模型 SHA-256，禁止跳过 |
| `LOREDOCK_KNOWLEDGE_EMBEDDING_OUTPUT_NAME` | `sentence_embedding` | 锁定二维句向量输出 |
| `LOREDOCK_KNOWLEDGE_EMBEDDING_MAX_TOKENS` | `512` | tokenizer 截断上限 |

部署前在受控环境准备模型，核对许可、revision 和摘要，确保应用进程可读且模型目录不属于仓库或对象上传根。首次上线先备份数据库，再启动应用执行 Flyway V5；管理员触发知识重建，待任务成功且新搜索 generation 完整 ACTIVE 后再开放搜索。模型惰性初始化会带来冷启动开销，应在重建或就绪准备阶段预热；当前 Apple Silicon CPU 基准冷初始化约 4.44 秒，预热查询最大 16 毫秒，至少预留 512 MiB 模型与原生运行时内存余量。

## 6. 故障恢复、备份与日志

`KNOWLEDGE_INDEX_UNAVAILABLE` 表示没有同时完整的活动投影与搜索元数据，或融合版本不匹配。检查重建任务、ACTIVE/BUILDING 状态、文档/分块计数和 V5 迁移，不手工修改状态。`KNOWLEDGE_EMBEDDING_UNAVAILABLE` 表示本地资源、摘要、输出或推理失败；检查只记录模型 ID 与摘要前缀的日志，不在日志或工单中粘贴模型绝对路径。

数据库备份覆盖事实文档、generation、检索分块、关键词和向量；这些搜索表是可从 PUBLISHED 文档和锁定模型重建的派生数据。恢复后若活动 generation 完整且模型配置匹配可直接查询，否则保留事实数据并发起新重建。备份期间应停止发布与重建，避免数据库与对象证据处于不同静默窗口。

生产日志记录 traceId、上下文、稳定项目/分支 UUID、模式、查询长度/摘要、generation、两路候选数、资格排除数、返回数、耗时与错误码。不得记录原始查询、正文、向量、对象键、内部地址或模型绝对路径。

## 7. 正式基准

公开模拟 fixture 位于 `backend/src/test/resources/knowledge-search-benchmark/`。结构测试先检查 18 个问题的类型、人工标注、三种模式、范围可见性以及常见敏感模式。显式正式基准使用 Testcontainers PostgreSQL 17 + pgvector 0.8.1、真实重建器、真实离线 BGE 和生产 `KnowledgeSearchUseCase`，固定应用、fixture、generation、模型摘要、`cjk-v1` 与 `rrf-v1`。

执行器把逐题文档 UUID、排名、警告、结果数、耗时与门禁写入 `backend/target/knowledge-search-benchmark-result.json`。运行中 generation 或配置变化、任一查询异常、HYBRID Top-5 低于 80%、任何范围/生命周期泄漏或预热查询超过 3 秒都会使测试失败。2026-07-30 正式结果见 [T5 知识混合检索基准报告](../quality/T5知识混合检索基准报告.md)。
